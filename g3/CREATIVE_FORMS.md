# 第二阶段：动态排版、图片轮播、聊天对话体

本阶段在原有 AutoVideo 生成链路上新增三种受控形式。保留原有知识卡片、流程图解、信息动效、文档输入、完整材料分章、逐字讲稿、包装、配音与倍速、历史任务和修订流程。真实样片及验证见 [验收记录](acceptance/creative-forms-20261023/README.md)。

| 资源 | `video_form` | 画面与输入 |
| --- | --- | --- |
| F08 动态排版 | `kinetic_typography` | 按实际旁白短语分页，文字分组随实测配音展开；不固定三段内容。 |
| F12 图片轮播 | `image_slideshow` | 图片顺序、轻微推近、图文排版；上传 1–12 张图片，或由现有本机 Draw Things 生成三张概念插画。 |
| F16 聊天对话体 | `chat_dialogue` | 章节问题与旁白形成问答画面；显式“观众：”“讲解：”会用于说话人和问题延续，拆句保留所属角色。统一使用所选旁白声音，画面标注演绎对话。 |

三种形式支持素材自动组织及 `input_mode: narration` 定稿讲稿，也支持内容时长和原有指定时长模式。素材模式仍按事实来源约束组织讲稿；定稿模式保留原文，只做分句及画面安排。没有新增独立常驻服务。

## 配方与资源入口

资源库 F08/F12/F16 已标为可用于制作。三份配方升级为 v2：AI 快讯默认动态排版；操作教程保留流程图解默认并可组合图片轮播、对话体；原理科普保留自动选型并可组合对话体、图片轮播。资源库的“配方 + 形式”按钮保留该配方的偏好、包装及关联，创建页也可手动切换。

`auto` 仍在现有流程图解、信息动效之间判断素材关系；新增形式由配方或用户指定后自动生成。旧 v1 配方快照保持原值，重试和修订不会被新默认替换。

## 图片输入 API

1. `POST /api/creative-images`，multipart `file`，静态 PNG/JPEG/WebP；单张上限 20 MB，边长 128–8192、总像素不超过 2400 万。解码、方向规整、缩放至最长边 2560 并转成无原始元数据的 PNG。
2. 返回 `image_id`、文件名、尺寸、SHA-256、`preview_url`。`GET /api/creative-images/{image_id}` 仅提供通过完整性校验的固定本机图片，不接受任意路径。
3. `POST /api/jobs` 传 `video_form: image_slideshow` 和有序的 `slideshow_images: [image_id, ...]`。列表最多 12 个，不能重复；用于其他形式会被拒绝。保留已有字段和默认行为。

创建任务时复制图片至任务 `input/images/` 并冻结记录；G2 再校验哈希并注册为 IR 图片资产。重试使用任务副本，修订从父任务副本复制，不依赖原图片磁盘路径或全局上传记录。轮播中的每张图片都进入画面；图片少于旁白短语时会重复，图片多时在一页内继续轮播。讲稿完整依次提到“第一张、第二张……”时按对应图片切换；其他材料按提交顺序分配，不声称理解未标注图片的语义。

不上传图片时 API 检查本机 Draw Things 连接，未连接返回可操作的错误，不创建无法执行的订单；网页也显示上传或连接服务的提示。自动插画是辅助表达，不作为事实证据。当前机器未开启该 API，本轮真实成片验证使用上传图片；自动插画请求与校验有离线测试，尚无本轮真实模型出图证据。

## 安全边界与版本

`g2/creative_forms.py` 从最终讲稿构造受控分镜，使用原有真实配音短语时间线；`g1/video_ir.py` 只为明确的 presentation 打开相应已注册组件。图片必须引用注册资产且路径、SHA-256 一致。禁止远程 URL、任意组件及模型代码。冻结的 v0.2 原始 schema/registry 保持原状，新增 schema 和扩展注册表单独维护。

渲染组件为 `g1/renderer/src/CreativeForms.tsx`；由原渲染入口复制至各尝试的私有目录。打包、正文媒体 QA、整片完整解码、配音相关系数及所有旧阈值继续生效。

新形式可通过素材/讲稿修订生成新版本，也可单独修订声音与倍速，图片资产随之继承。现有两种主形式的单场景文字编辑和 AI 重排保持原功能；三种新形式的单场景自由重排未开放。音乐生成、正文配乐、多角色声音及横竖屏自由切换属于后续阶段。
