# 测试样片隔离与矩阵选题去重

2026-10-25 决策：已发布视频保持原样；归档确认重复的未发布内容，保留文稿版本、生成记录和所有媒体文件。

## 验收样片

- 验收工具必须使用 `state/validation/<批次>/isolated-state/video.db`。脚本函数被直接调用时也检查隔离，禁止写入正式库。
- 新样片带 `test_sample` 标记并默认归档；历史 `chain-validation`、`prompt-quality-validation`、`多矩阵质量验收` 来源也按样片识别。
- B 站、抖音、快手、小红书使用统一的样片/重复内容隔离规则，候选列表、直接发布预览及入队都不能绕过。
- 历史已发布样片的发布记录和状态不修改，仍计入发布历史；它们讲过的新闻也纳入去重记忆。

## 自动写稿与出片

- 保留“矩阵 → 任务 → 多套视频配置 → 报告 → 文稿 → 成片”的流程。同一报告的不同配方仍可各自生成。
- 同矩阵不同报告共享最近 30 天的实际文稿来源记忆，覆盖日报、周报和历史已发布版本。不按生成标题相等与否判断重复。
- 新闻 URL 去除追踪参数、锚点及协议差异；arXiv 的 HTML、PDF、摘要统一为同一论文；复用事件记忆的保守跨媒体标题路径匹配。
- 文档、价格页、RSS、实时榜单等通用参考页不单独作为重复新闻证据。
- 同矩阵不同报告的首稿依次生成，避免两个任务同时拿到空的去重记忆；不同矩阵继续并行。
- 写稿前剔除已经讲过的原始新闻素材块。没有可独立讲述的新条目时跳过，保存原因并结束该条目的自动重试。
- 保存文稿与自动出片前再次检查主选题：开场引用的新闻全部已覆盖时阻止重复产出。保留含新素材的综合对比，不因为其中引用了旧新闻而归档。
- 去重基于可追溯来源及保守事件指纹，不承诺识别所有跨语言、无来源或改写幅度很大的语义重复。

## 现有内容归档

`scripts/archive_video_duplicates.py --output <维护目录>` 默认只输出预览，加 `--apply` 才归档。归档前检查所有平台账号的发布与投稿回执，任何已发布、已提交或结果不确定的稿件都受到保护。

都未发布时优先保留已有成片，其次保留较早的内容。新主题含少量旧素材的对比稿不会仅因共享一条链接而被归档。正在写稿或出片的项目跳过。

归档前保存数据库副本，并核对已发布文稿、版本、成片和发布记录的整体 SHA-256。归档原因及保留稿 ID 保存在 `topic.content_archive`，从所有平台候选中排除。手动恢复时保留旧归档说明并解除这项投稿限制。
