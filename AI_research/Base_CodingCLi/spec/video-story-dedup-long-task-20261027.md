# 视频主事件去重长任务

目标：在选题、写稿阶段解决跨日再次选择旧事件，以及同日报告多套配置选中同一主事件。复用已提交的矩阵来源记忆、材料过滤和自动任务流程，保留已发布内容及待投稿回执。

## 当前基础与本轮复核

当前代码已有 30 天来源矩阵记忆、同报告材料过滤、初稿顺序协调及出片前复查。本轮继续补齐主事件识别与选题分配，不改变内容矩阵、栏目、制作配方的分层。

- [x] 使用只读连接复查 Flint 跨日与经济日报多配置案例；已有重复可被来源记忆识别。
- [x] 保存已发布及有投稿回执内容的逐行摘要，作为后续不可变验收基线；初次覆盖 90 条受保护文稿。
- [x] 复现漏点：Flint 的标题、事件摘要和两条原有证据不变，仅增加一条辅助参考，当前来源覆盖率从 2/2 变成 2/3，重复判断被绕过。

历史案例、诊断及逐行摘要仅放在忽略的本地状态目录，不写入生产文稿，不批量归档或改写历史视频。

## 执行阶段

### 1. 主事件与辅助材料分离

- [x] 明确主事件证据、背景参考、事件日期、版本及上游提供的新进展；日期编号、生成标题和制作配方不充当事件身份。
- [x] 优先使用选题的主事件/证据来源；增加背景链接不改变主事件占用，旧资料作为新问题背景时仍可复用。
- [x] 为换链接、换说法、来源缺失和同一实体的新进展补齐回放用例；确认可确定匹配与需要上游事件信息的边界。

### 2. 共享候选池与自动占用

- [x] 一份报告向多套配置提供共享候选池，先确定主事件再写稿；每条候选保留明确来源及事件信息。
- [x] 复用批次账本和跨进程锁实现占用；同事件冲突时自动选择剩余候选，数量不足时少做。
- [x] 保存候选池/占用结果并支持重启恢复；失败、取消时释放未完成占用，避免重复挑选和互相等待。

### 3. 写稿与制作链路统一

- [x] 将所选主事件及其新进展传入写稿，保存到新版本元数据；复用既有写稿/改编入口。
- [x] 保留原始材料，向后续配置提供剩余材料与已覆盖事件摘要；辅助来源不构成重复事件的新信息。
- [x] 写稿后和出片前复用同一事件判断，处理旧并发任务；对已有明确新进展的后续内容保留生产路径。

### 4. 可见的自动处理结果

- [x] 在现有批次/条目状态中展示选中、等待、改选和跳过的原因，关联已覆盖文稿与主事件。
- [x] 批次结束时说明候选数、采用数、重复跳过数及素材不足情况，避免把排重当作生产失败。
- [x] 保持自动处理，不增加逐条选题的人工确认步骤。

### 5. 验收与本机接入

- [x] Flint 换日、换标题、增加辅助链接仍跳过；原有发布/待投稿内容只作证据，不变更。
- [x] 同报告多配置选择同一主事件时只保留一次自动占用，其余配置改选或少做；不同事件可以分别产出。
- [x] 上游明确给出的新版本、新结果、新政策变化等可以形成后续内容；同实体本身不触发整类封禁。
- [x] 并发、失败、取消、重启恢复与无可用候选均有隔离回归，测试不接触真实发布账号或安装调度任务。
- [x] 历史案例只读回放、受保护行摘要比对、本机自动流程接入及验收说明完成。

## 实施边界

第一批以现有来源矩阵的 30 天记忆为基础，沿用上游讲稿、事实与结论，不额外检索或重新核算。事件识别依据上游事件信息与核心证据，兼顾重复拦截与新进展保留。个人品牌资产、原创旋律、生产数据库及成片继续保存在本地忽略目录。

## 落地位置与恢复规则

- `core/video/content_guard.py` 继续承担统一判断，优先读取明确的主事件证据；保留旧选题字段的兼容路径。
- 后续候选池/占用模块使用现有视频数据库及初始化入口，事件记忆与研究报告的来源账本区分：只有已选/已写事件才占用视频选题，不把读过的整份报告视作已讲过。
- 候选保存报告内容哈希、事件身份、核心证据及上游新进展；服务端生成事件身份，模型选择已有候选，避免用临时标题或自造编号绕过占用。
- `web/services/video_autopilot.py` 在批次推进时分配候选，结合现有跨进程锁与事务占用；未绑定文稿的中断占用可恢复，失败/取消释放未完成占用，成功写稿转为已覆盖。
- `web/services/video_workflow.py` 与现有写稿/改编流程携带同一事件信息，将选择结果保存到新版本元数据；旧文稿继续走兼容判断，受保护历史保持原样。
- 现有批次条目保留可读原因和关联文稿，结束时记录选择统计；只读回放工具输出同一事件判断与保护状态。

## 初次开发进度

主事件来源优先级已实现，新增“辅助新链接不能让旧事件变新”和“新事件可引用旧资料作背景”两个回归用例。去重与自动任务相关 78 项测试通过；后续继续推进候选池、占用恢复及写稿事件元数据。

## 主流程开发进度

已实现 `matrix-story-v3`：共享报告候选池、原子事件占用、失败/取消释放、重启恢复、自动改选、初稿保存前占用复核、写稿/改编的主事件元数据，以及批次选题记录与关联文稿链接。旧版来源判断继续兼容已有文稿；新自动任务在写稿前选择事件。

本地真实历史材料配合固定事件结果的回放：Flint 跳过；经济日报两套配置分别选择 Anthropic 招股书、ECB 企业融资调查。该回放验证分配及记忆机制，不代表实时模型的事件整理效果已经验收。90 条受保护文稿及其原有 152 个版本、147 条渲染、158 条发布记录的逐行摘要全部一致。

实时整理使用现有写稿模型 `deepseek-v4.1-flash`（`opencode.ai`）。首次因历史材料外传缺少明确授权而被自动审批拒绝；用户随后明确回复“允许实时验收并启用”。现已完成真实只读回放和本机安全重载。

独立副本全量检查通过：后端 3260 项、前端 580 项，另有预期跳过。之后补充的边界修改通过 949 项相关隔离回归；TypeScript、ESLint、配置校验、构建及 `git diff --check` 均通过。详细记录见 `spec/acceptance/video-story-dedup-20261027.md`。

后续复核修正两类事件身份边界：模型省略变化说明时，明确的新版本仍可识别；带平台前缀的下载量、点赞等热度字段不能绕过旧事件记忆。同一天同一版本的发布保持一致身份，兼容版本前缀与未知字段。307 项相关回归通过，固定事件历史回放仍为 Flint 跳过、经济日报两套配置分别分配不同事件。

## 最终验收与启用

真实模型对 Flint 识别出 6 条已有事件关联，分配时跳过。经济日报整理为 25 个候选，多篇招股书报道合并为一个主事件；两套配置共用一次整理结果，分别选中企业融资调查和供应链咽喉点，没有重复占用。回放没有生成文稿、成片或发布。

本机研究端已安全重载至新实例（PID `88005`）。健康检查正常，代码哈希与验收代码一致，前端选题记录资源已实际验证，自动流水线日志无新增错误。研究、制作、Bilibili 上传避开重载窗口，独立投稿核验继续运行；原有排队和回执未手动改写。

最终比对仍覆盖原有 90 条文稿、152 个版本、147 条渲染和 158 条发布记录，逐行摘要全部一致；已有投稿回执标识保留。个人品牌资产与原创旋律保持本地。全部阶段完成，详细证据见验收说明及本地忽略的状态目录。
