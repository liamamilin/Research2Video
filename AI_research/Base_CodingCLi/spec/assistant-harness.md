# 助手 Harness 使用与实现说明

实现与复查修复日期：2026-10-16；工作台升级：2026-10-25（见 [开发计划](assistant-workspace-plan.md)）。对应 [开发计划](assistant-harness-plan.md)、[修复计划与执行记录](assistant-harness-fix-plan.md)，验证记录见 [开发进度](assistant-harness-progress.md)。

## 使用方式

「助手」位于侧边栏主线（视频看板、文稿、助手），保留流式对话。可以连续提出多个明确动作，工具结果显示实际对象、状态和入口，不需要为每个内部步骤重复确认。

可以直接说：

- 创建一个跟踪 Agent 记忆的 Job，每周一九点运行，使用 Asia/Shanghai。
- 把这个计划改成周五，先暂停；之后恢复。
- 查看这个 Job 最近的周期运行，读取实际生成的报告。
- 比较九月和十月的报告，列出变化、冲突和仍缺的证据；只分析。
- 收藏这份报告并打上 memory 标签；根据第二个缺口创建任务并保存来源。
- 查今天轮次哪里失败，补跑未完成阶段；或重跑指定阶段及其下游。
- 将这条行动标为完成，备注「已在测试环境验证」。
- 查看当前模型和本月用量；测试候选 provider，通过后切换。
- 重建索引，查看进度；向指定渠道发测试通知。
- 创建用户、调整角色、撤销本人 Token，或在处理现有运行后重启应用。
- 看看有哪些文稿等我审；今天的快讯里哪些选题还没写；用今天快讯的 F2、F3、F4 写一期盘点（只写到草稿）。
- 对已有文稿：定稿、换风格重写、对快讯做发布前复核、开始生成成片、记录你提供的 B 站链接和日期。
- 新建矩阵，加入研究任务；矩阵设 1.25 倍速，某个任务覆盖为 1.5，之后恢复继承。
- 给研究任务关联适用的视频配方，设置自动生产数量；预览、创建或暂停周期。
- 只看某个矩阵在指定平台尚未投稿的当前定稿，准备标题、简介和来源，先不上传。
- 将明确指定的成片发布到指定平台账号；查询既有任务，诊断失败或核对投稿结果。

视频工具：`query_video` 查询流水线，`create_video` 创建文稿，`manage_video` 定稿、重写、复核或出片；用户要求完整制作视频时，`continue_video` 将已有文稿接入现有持久批次，后台继续到成片。重复衔接复用进行中的批次；只写草稿时不启动后续出片。

应用操作目录：`application_actions` 按需发现矩阵、配方/共享部件、任务视频设置、素材、正文编辑/版本、分阶段重跑和平台发布等真实 API；`read_application` 读取，`operate_application` 执行修改。它们沿用页面的鉴权、CSRF、验证、冲突检查、备份和审计。长读取返回带版本指纹的分页片段。平台公开发布需要用户指定内容和平台；账号登录、验证码和秘密输入通过原平台页面或受保护卡片完成。

各页面右下角「让助手处理」打开侧栏并保留原页，详情对象自动成为可移除的结构化上下文；完整工作台提供历史会话切换和工作区。工作区直接读取真实状态、文稿与视频版本、相关配置及影响范围；执行中的对象自动刷新，隐藏页面暂停轮询。按钮可将重跑/调整/比较请求填入输入框，不自动提交。

## 矩阵运营与发布

`query_matrices` 返回成员、周期、共用设置、任务覆盖及适用的配方；`manage_matrix` 只合并指定字段，不删除任务或清空未修改设置。`configure_production` 新增任务与配方的关联，或通过生产配置的 `config_key` 修改覆盖、恢复继承；修改带内容版本，保留原配置备份。共用设置与任务覆盖影响后续生成，已有视频保持原版本。

`query_publishing` 统一查询可用平台与当前账号、按矩阵筛选候选、准备准确成片版本的发布字段，以及读取既有投稿。默认候选是未归档的当前定稿，沿用各平台重复保护。发布准备卡保留版本、账号、简介、来源和提示，「让助手发布」只预填请求。

用户明确发送发布指令后，`manage_publishing` 核对目标账号并调用原生提交、重试、取消或核对接口。批量部分失败保留成功项；工作区按准确任务 ID 直接跟踪，提供原生队列入口。上传提交、平台审核与公开发布分别显示，模型不循环等待后台；需本人登录或验证码时转到平台页。真实平台上传仍取决于账号与平台能力，不承诺所有平台都能完全无人值守。


## 任务中心与研究跟踪

全应用范围与本轮新增入口见 [能力清单](assistant-application-coverage.md)。`configure_matrix_task` 将矩阵、共享来源、研究任务和配方连接起来，避免反复发现接口。`prepare_application_batch` 冻结完整范围，`manage_application_batch` 启动/继续/停止后续派发；任务中心显示研究到成片、周期启停、矩阵设置及批量投稿的逐项结果。「能做什么」提供全应用场景示例，只预填不发送。

顶部「任务中心」汇总当前账号跨对话的助手操作请求，支持状态筛选、搜索和载入更早记录。默认最近 20 条，可载入至 100 条；筛选计数仅针对已载入请求，更早记录通过历史对话查看。`query_assistant_tasks` 提供同一份只读投影，不调用模型推进后台工作。

研究卡记录手动/周期来源、研究任务和准确运行 ID，跟踪到报告文件或失败、中断、取消状态；提供报告、检查本次运行、取消本次研究、从报告继续制作入口。按钮只预填请求。跨对话继续会恢复原会话后预填，不自动发送。对相同研究任务，投影只读取一份日志快照；活跃执行器与运行 ID 必须匹配，旧日志不证明进程仍在。报告仍使用原生文件路径，不是不可变快照。

## 权限

| 角色 | 能力 |
| --- | --- |
| viewer | 查询 Jobs、运行资料、报告、轮次和行动；下载报告；管理本人账号允许的会话与 Token |
| editor | 上述能力，加 Jobs/模板维护、手动运行及取消、报告元数据/分享/邮件、行动更新、索引重建 |
| admin | 上述能力，加周期调度、系统配置/诊断、通知、用户管理和服务维护 |

调度的查询和修改仍均需管理员。周期运行取消也需管理员。每次工具调用重新核验当前登录身份，直接调用业务函数时仍显式检查角色；模型伪造工具名或参数不能绕过权限。

## 周期与运行的区别

周期采用现有五字段 cron，支持 IANA 时区并预览未来三次时间。当前普通托管计划沿用「同一个 Job 一个计划」规则。新计划使用 SQLite 独立调度器，既有 cron 和矩阵 LaunchAgent 保留兼容管理。

暂停计划不会取消已开始的运行。恢复托管计划只从下一个未来时点开始，不补跑暂停期间；`latest` 处理的是计划启用期间因离线错过的时点。不能用五字段 cron 无损表达的一次性、节假日或其他规则，需要说明差异。

手动运行和周期运行使用不同执行器。查询和取消必须指定运行来源与具体一次 ID。周期取消通过持久取消标记通知 worker，不让模型传 PID；worker 确认前显示「已请求取消」，主动取消不会进入失败重试，未来周期保持不变。

选择一次历史手动运行后，摘要、日志和报告引用均取该次 ID；当前正在执行的任务单独返回。计划卡片展示最近运行结果和已核验的报告入口，暂停计划的未来时间标为预览。

「停止响应」仅停止本次助手，不代表取消研究运行，也不代表暂停周期。服务维护会检查当前 Web 手动运行和轮次，按明确选择等待或取消；独立周期执行器继续运行。

## 报告与情报轮次

报告工具支持目录、日期/Job/分类/轮次/明确文件范围、全文与混合检索，以及分页读取原文。历史检索不默认局限最新轮。检索片段不代表已经穷尽全部报告，回复需要说明范围和缺失，并用报告日期与链接引用。

目录、文件和轮次范围在 SQL 查询中筛选。列表的总数及日期范围依据索引，实际返回的页内文件另行核验；失效文件会标明，不能将索引统计解释为已逐份阅读全文。限定检索在范围内取候选并过滤失效文件。

运行记录中的产物会核验文件和目录边界，转换为报告相对路径。即使索引尚未更新，也能直接打开和读取已生成报告；索引为空不能当成文件不存在。

引擎实际读写、暂存及失败恢复均使用经过校验的绝对路径，索引与展示引用单独生成；进程工作目录不同或设置 `runtime.output_root` 时保持同样语义。这不新增每次运行的不可变报告存档；同一个输出文件仍可能被后续运行替换。

收藏、标签、已读和评分只在用户要求时修改。HTML 导出提供下载链接；邮件要求明确收件地址，分享链接可以列出和撤销。将证据转成 Job 时可以保存 `source_references`，类型为 report/action/round，服务端核验来源存在。

轮次工具支持状态、阶段、质量提示、结构化产物、跨轮 diff、整轮运行、补跑、指定阶段重跑及取消。指定阶段重跑只覆盖所选阶段及依赖下游；其他必要上游尚未完成时先说明缺少项，不擅自扩大执行范围。上游重跑失败时，下游保持过期状态，不读取旧文件生成本次新结论，也不把旧行动产物重新同步为新结果。

## 配置、凭据与恢复

配置工具返回专用脱敏投影，不把原始 YAML、内联密钥或请求头原值交给模型。设置页与助手共用字段校验、文件锁和内容版本检查；错误类型、非法枚举/范围和新写入的未知字段在保存前拒绝，未修改的已有扩展字段保留。选择 provider 预设时，URL、密钥环境变量和必要请求头一起更新，清理前一 provider 的过期请求头；自定义 OpenAI 兼容地址仍可通过 patch 配置。托管计划也携带版本，旧编辑不能覆盖新编辑；既有 cron 更新在同一个锁中保留实际命令。

模型/provider 切换先验证普通调用、流式工具调用和工具结果后的流式文本。测试失败保持当前配置；只有明确要求强制保存失败候选时才覆盖。当前助手与研究任务共用 `ai` 配置，后续请求采用新配置，已开始的执行保留原配置。

密钥、私密请求头、用户密码和新 Token 使用受保护卡片。输入直接到后端，不经过模型，也不保存到普通聊天或操作回执。新 Token 仅在提交响应中向当前浏览器显示一次，隐藏或刷新后不能再次取出。本人改密、创建 Token 等沿用现有登录会话要求。

配置变更先写入私有旧值快照和恢复记录，再发布新配置；保存后的缓存/审计收尾失败会返回已保存及警告。私密请求头也在测试后保存并提供回退。配置变更返回「恢复变更前配置」按钮，设置页也能直接发现本人可用的恢复记录，聊天响应丢失时仍可使用。恢复直接调用后端，不需要 LLM 可用，不继承秘密输入的一小时有效期；依据内容版本判断是否仍适用，其他人或其他页面再次修改配置后会阻止旧回退覆盖新编辑。旧版恢复记录兼容其原有版本依据。

索引重建在后台运行，显示进度、失败项及部分完成状态。服务重启导致进程内重建中断时保留记录，不自动重放。

## 会话和操作回执

当前会话、最近对象引用和操作步骤写入当前 state 目录的 `assistant.db`，按账号隔离。当前标签页按账号保存活动会话 ID，刷新和页面切换显式恢复该段会话，其他标签页新建对话不会将它切走。重复 request ID 不重新执行。页面的「核验结果」直接重读已记录结果，不调用 LLM；断线后可先核验再决定后续动作。页面提供新对话、最近 80 个历史会话的切换、当前会话恢复与上下文移除；工作区展示最近 4 个相关对象与最近操作。

一次写操作在执行前记录标识，随后记录真实结果。中途失败时保留成功步骤。服务中断窗口中的未知结果明确标为待核验，先查询实际业务对象，不自动重放整条多步命令。这不承诺跨文件、数据库和外部进程的所有操作恰好执行一次。

受保护卡片记录执行归属；原执行进程消失时，原先的「处理中」转为「结果待核验」，页面提供直接查询业务状态的入口，不自动再次提交。Token 只核验名称、创建时间等元数据，不能重新取出原值，也不凭同名就宣称本次创建成功；可按用户选择撤销后重新创建。受保护卡片状态会带入后续上下文，使助手知道输入是否已经完成，但不带入秘密。后台操作和维护均有独立查询入口。

一次助手请求仍有 16 轮/32 次工具调用上限。达到上限时明确显示原请求未完成，记录候选报告、连续读取位置、正文版本、实际读取回执和尚未派发的工具，并提供「继续处理」。这些记录只表示读取进度，不能代替正文证据；继续分析时先从回执取回证据或按需重读，再展开后续内容。不同正文版本的片段不会合并成完整阅读；已成功的写操作不由恢复机制自动重放。

## 服务维护与升级

应用重启/关停通过受支持的 `run_web.py serve` 启动实例执行，核验当前运行进程并保存维护回执；不依赖可能陈旧的全局 PID 文件。重启由独立 helper 等待旧服务退出，再验证新实例身份和健康状态，不强制杀死无法退出的服务，也不盲目启动重复实例。

维护标记与新的手动 Job/轮次注册共用准入锁，已取消但尚未退出的 worker 仍计入活动任务。维护工具返回回执后关闭本次助手请求，避免再等一次模型响应阻塞自己的退出。网关回收自己拉起的子进程，helper 将僵尸进程识别为已退出。

主动关停后，被动 API/资源请求返回 `503 app_stopped`，不会唤醒应用，维护卡片停止这种轮询。用户重新打开应用文档页面可以主动唤醒。网关中断后的重绑定回执依据实际监听和执行者状态收尾，不盲目重放旧命令。

网关保存配置与实际监听分别展示。新版网关提供本地控制回执与心跳，重绑定失败时恢复先前监听，保存的配置仍显示待生效。网关重绑定保持应用和研究运行继续执行。

旧版常驻网关需要先重启一次以加载控制支持。运行维护不会替用户安装新的系统任务，测试也不会触碰真实 cron 或 LaunchAgent。
