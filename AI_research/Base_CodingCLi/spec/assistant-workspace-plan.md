# 助手工作台开发计划

日期：2026-10-25。目标：用户描述目标，助手定位应用对象，调用真实业务操作，跟踪结果，继续迭代。

## 实施顺序

1. **统一能力入口**：在现有领域工具之上增加按需发现的应用操作目录。矩阵、配方与共享部件、任务视频设置、正文编辑、分阶段重跑、视频与发布复用真实 API 的验证、鉴权、版本冲突和审计；凭据继续使用现有受保护入口。
2. **上下文与会话**：页面对象作为结构化引用进入助手，服务端保存会话上下文；增加按账号隔离的会话列表与切换，不自动提交预填请求。
3. **工作区与持续状态**：对话旁显示当前对象、文稿/视频版本、相关配置入口、最近执行与变更。业务状态直接读取，不调用模型。刷新或离开后可以恢复。
4. **全局入口**：各页面可以打开助手侧栏，保留原页面；完整助手页提供历史会话与工作区，窄屏折叠。
5. **验证与交付**：隔离数据库测试真实 API 调用、权限与冲突、上下文隔离、正文编辑和重跑；前端测试历史切换、恢复失败与任务状态；构建并进行浏览器验收。真实生成/发布只在用户要求时执行，不把开发测试变成生产发布。

## 验收场景

- 从文稿进入，显示当前版本和视频所用版本，并提供对应配方、矩阵、任务设置入口。
- 通过助手读取配方/公共提示词，保存修改时沿用版本冲突和备份机制。
- 读取正文并保存新版本；重跑写稿或视频沿用原 workflow。
- 新建/修改矩阵，查询任务视频继承设置，修改周期与任务归属。
- 查询发布任务、准备和提交明确指定的发布操作，展示真实结果或登录入口。
- 新对话、历史切换、刷新恢复互不串会话；后台工作状态不会被“工具调用成功”误报成完成。
- viewer 不能借通用操作接口写入；不存在的操作、路径穿越、凭据参数被拒绝。
