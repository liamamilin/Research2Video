# 视频主事件排重验收

## 已实现的行为

自动任务使用 `matrix-story-v3`，在写稿前从共享候选池选择主事件。同一报告（或快讯条目）的相同材料输入只整理一次事件池，不同制作配置共用候选；跨日历史按来源矩阵共享近 30 天记忆。旧版来源判断继续兼容历史文稿。

候选区分核心证据、辅助背景、事件日期、版本及明确的新进展。改标题、改日期编号、换配方、增加参考链接不会自行产生新事件；同一主体的明确新版本、新结果、新政策变化仍可形成后续内容。缺少事件日期/版本时保留具体证据身份，通过历史事件引用处理语义别名，不把一个主体的所有内容封禁。

候选池按报告内容哈希缓存，整理时复用现有写稿模型，仅组织已给材料，不额外检索或核算。模型只能引用材料和历史事件的已有编号；服务端生成事件键。原始材料完整保留，写稿器接收所选事件的完整核心材料及单独标出的辅助背景。

事件占用和新文稿的选题绑定在同一个 SQLite 写事务内完成。重复候选自动改选，快讯选题还有有限的备用队列；没有候选时少做一条，批次显示原因。占用随失败/取消释放，重启后恢复；取消的旧写稿线程不能在占用释放后保存初稿，也不能让后续配置一直等待。已有初稿转为已覆盖。

单次写稿和改编入口保存同一份事件元数据，写稿后与出片前复用同一判断。语义记忆保留已发布旧版本，不因当前版本改过主题而丢失。没有修改已发布内容的标题、文稿、成片、发布记录或投稿回执。

现有自动流水线卡片增加“选题记录”，显示候选数、选中事件、重复跳过原因及已覆盖文稿链接；批次汇总采用、改选、重复和素材不足的数量。

## 历史材料只读回放

使用生产账本只读连接，在临时账本内保存事件池及占用。固定事件结果来自本地已有报告，未调用实时模型，未写稿、渲染或发布。

| 案例 | 结果 |
| --- | --- |
| Flint 40B/2.5B 跨日快讯 | 旧事件跳过，未选择新的主事件 |
| 同日报告第一套配置 | 选择 Anthropic 招股书主事件 |
| 同日报告第二套配置 | 跳过已占用招股书事件，改选 ECB 企业融资调查 |

受保护基线共 90 条文稿，原有 90 条文稿行、152 个版本、147 条渲染和 158 条发布记录逐行摘要全部一致。允许后台系统新增记录，但本次不改写基线中的任何一行。原始数据与回放 JSON 保存在忽略的本地状态目录，未纳入提交文件。

可重复运行：

```sh
python scripts/replay_video_story_selection.py \
  --database state/video.db --script SCRIPT_ID \
  --events-json LOCAL_FIXED_EVENTS_JSON --output state/story-replay.json
```
