# 静态截图选取与分镜接入 · 2026-10-28

本轮复用 Playwright、本地 OCR、现有视觉模型和既有混合渲染，围绕产品功能、开源项目和文档示例制作真实样片。讲稿、数据和结论作为输入；不增加事实核验、人工确认、录屏或 AI 视频生成。

## 修复与行为

- 复现旧五条作品的记录：15 次页面尝试、0 张成片截图。7 次名称／实体匹配失败、5 次视觉结果结构校验失败，其余为页面访问与区域过长。保存在隔离目录 `baseline.json`。
- 实际重放旧截图，定位到视觉返回的 `visible_text` 超过 300 字符。现在归一化描述文字，保留段落 ID 和有效坐标校验，不因英文摘录冗长丢弃可用图片。
- 从文章和研究材料已有链接选择产品、README 与文档画面，包括没有段落引用的相关用法。参考来源存在时仍保留正文中的产品示例链接。补齐无研究报告路径的导入文章链接；不按事实置信度或推导标记筛掉上游输入。
- DOM 候选增加图片、短代码块和标题下的独立区域，优先文档锚点。按一个对象或讲解用途匹配，避免要求一张图包含整段的所有产品名。
- README 代码候选优先独立的最小调用，降低旁白未涉及的可选供应商配置权重，避免文件名中的 `example` 把额外依赖带到主画面。选择版本进入缓存键，新策略不复用旧排序下的候选。
- 图片理解选中的既有段落直接获得映射，同一素材可承接多段，减少重复采图和模型调用。页面额度按不同来源网址计数。
- 自动材料使用内容说明，并从真实 DOM／OCR 坐标取得最多三个焦点。排除无关工具栏，区域标签遵守引擎原有 32 字符合同。
- 已映射的截图不会被抽象流程图覆盖；数据图表仍承担数字解释。原分镜请求安排整体、局部与总结，无额外分镜模型调用。

```sh

../.AI_research/bin/python spec/acceptance/static-screenshots-20261028/run.py --output state/validation/static-screenshots-recheck

../.AI_research/bin/python spec/acceptance/static-screenshots-20261028/follow_next_round.py
```

`--case` 可重复指定单个类型；`--reuse-from` 只用于复用先前隔离批次的截图和账本。真实制作需要现有网页网络访问、本地视觉服务、中文配音和渲染依赖。不会创建发布任务。
