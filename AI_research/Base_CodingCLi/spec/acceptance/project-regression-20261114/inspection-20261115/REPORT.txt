确认并修复的问题（8 类）

1. AutoVideo 工作目录归档可能保留错误副本并删除正确原件。
   core/video/archive.py 的任务归档此前依赖 rsync 默认大小/mtime 比较。
   隔离用例把原文件 good 与副本 oops 设置为相同大小、相同 mtime；修复前原件被删除，副本仍是 oops。
   现在任务镜像、清理前比较和恢复都启用内容校验，与研究端成片归档保持一致。
   代价：任务归档增加读取文件内容的 I/O；生产服务本轮未加载该改动。
   证据：archive-before.log、archive-after.log、tests/test_video_archive.py。

2. 文稿草稿跨用户/文稿/版本串写。
   use-script-editor.ts 切换 key 的同一轮 effect 中，重置状态尚未生效，保存 effect 仍拿旧草稿写新 key。
   可覆盖新版本已经暂存的草稿，或把原文稿内容放进另一份文稿的恢复记录。
   新增草稿所属 key，所属范围不一致时禁止保存，等待重置完成。
   证据：editor-before.log 两项失败；editor-after.log 与 ui-final.log 通过。

3. 并发 YAML 请求共享有状态的 ruamel 解析/输出对象。
   8 个线程处理 32 份不同配置的真实 round-trip 在修复前触发解析/输出异常。
   每次操作创建独立 YAML 对象，保留原注释、缩进和多行文本设置。

4. YAML 重复键没有转成约定的校验错误。
   DuplicateKeyError 没有被原来的 ParserError/ScannerError 捕获，会绕过路由的 ValueError -> 422 处理。
   现在捕获 ruamel YAMLError 并转成 ValueError；不改变既有重复键拒绝规则。

5. YAML 备份在同一秒被覆盖。
   同名文件来自不同目录，或同一任务连续修改时，原来的 {stem}_{秒}.yaml 路径重复。
   使用独占创建的唯一文件名；三个同秒备份各自保留原内容。

6. 配置保存可能丢失并发修改。
   原来 10ms 的 mtime 容差把真实快速修改当作未变化，检查与替换也没有共同锁。
   现在精确比较客户端读到的 mtime，并对同一文件的检查、备份、替换整体加锁。
   新用例验证 0.5ms 时间差被识别，以及 4 个持有同一旧版本的保存请求只成功一个。
   3—6 的证据：yaml-before.log 四项失败、yaml-related.log、inspection-focused-final.log、tests/test_yaml_io.py。

7. 待处理批次不能正确接续已定稿文稿及其成片。
   reopen_approved 原来把任意版本的已完成/活动成片当作不恢复的理由。
   v1 已完成时，v2 定稿仍可能卡在 HELD；用户手动出片后，批次也可能一直显示待处理。
   现在恢复已定稿且未归档的文稿，由 advance_auto 按 approved_version 复用活动/完成成片，再决定是否新提交。
   用例覆盖旧版本完成后制作新版，以及同版本 RUNNING/COMPLETED 的接续；后两者均只有一个 render。

8. 恢复逻辑错误复用了展示列表的条数限制。
   自动恢复只看最近 50 条 HELD，人工批量恢复只看最近 500 条，较旧且满足恢复条件的记录可能永远排在限制之外。
   held_items 保留展示默认上限，三个恢复调用明确使用 limit=None。
   用例构造 51 条待处理记录，只有最旧一条已定稿；修复前恢复数量 0，修复后恢复数量 1。
   7—8 的证据：autopilot-before.log、autopilot-adopt-before.log、inspection-focused-final.log。

另做两处小修：补全 events.py 的 Iterator 类型导入，删除 health.py 的重复 Optional 导入。
全量回归首轮暴露 test_telemetry.py 的旧 SimpleNamespace 替身缺少新增 status 字段；已补全替身，不以放宽生产代码绕过测试。
