# 页面与视频生产性能、稳定性检查（2026-10-28）

本轮先检查正式工作台的 16 个主页面，再检查资料收集、写稿、配图、配音、分镜、渲染和回传。期间补查用户反馈的“记住我 30 天仍反复登录”。原任务、失败尝试、文稿和成片均保留。

## 已修复

- 文稿详情在两阶段之间进入 DRAFT 后仍以 30 秒低频刷新；工作中以 5 秒刷新，隐藏页面暂停，编辑时暂停，已有请求未完成时不重复发送。
- 失败文稿遗留的阶段名称不再让看板显示“制作中”，列表和详情也不再因此持续高频轮询。正式数据中的两条错误记录现已显示为失败待处理。
- 文稿和成片列表按需请求 compact 投影，完整资料和发布历史仍由详情接口提供，旧接口默认响应保持兼容。
- HTTP 200 却返回 HTML 等非 JSON 时，客户端报告可恢复的读取错误，避免错误对象进入页面数据。空错误对象也不会再触发二次异常。
- 页面整体不可用的截图失败按 URL 在同次制作中复用，失败记录持久化，可供恢复使用；段落区域不匹配仍按段落单独处理。
- 本地配音逐段原子保存回执，子进程失败或超时后保留完整章节缓存，未完成的章节重新生成。整个父进程被强制终止时，尚未发布的缓存仍可能需要重新生成。
- 语音缓存满后淘汰最久未使用的缓存副本，使新章节仍可写入。只淘汰缓存目录中的副本，任务目录里的原始 WAV 和失败记录保留。真实验收中淘汰了两个旧缓存章节后成功写入。
- 模型及依赖文件的指纹按文件身份、大小、纳秒修改/变更时间复用；文件变化后重新读取和计算。
- 设置重载时优先复用已保存的强签名密钥，并串行处理首次生成，避免环境快照缺失导致密钥重新生成、旧登录全部失效。显式配置的有效密钥继续优先。
- 初次恢复登录遇到暂时的网络或服务错误时，显示恢复入口，保留浏览器会话。被动会话失效只清理本地视图，不再自动调用退出接口；主动退出保留原行为。登录失败也不再触发已有会话的自动刷新/退出。

## 实测

同一批 115 篇文稿的完整/精简响应比较：

| 项目 | 原响应 | 新响应 | 减少 |
| --- | ---: | ---: | ---: |
| 文稿列表 | 739,665 B | 282,398 B | 61.82% |
| 成片列表 | 592,601 B | 317,716 B | 46.39% |

五次本地处理器基准中，文稿列表总中位耗时 109.7 → 96.2 ms，成片列表 105.0 → 103.2 ms；JSON 序列化分别约 30.5 → 13.2 ms、24.3 → 13.1 ms。该基准包含本地数据读取和序列化，不含浏览器、登录、网关及网络，也不是并发压力测试。详见 `handlers-final.json`、`measurements.json`。

真实音频复用：首次文件指纹计算 84.2152 秒；再次执行指纹计算 0.006 秒，含四段音频恢复的完整热缓存路径 0.0072 秒，两个完整章节命中、零新增配音进程，WAV 与原音频逐字节一致。首次配音仍然需要生成；这里没有把缓存恢复时间当作首次视频生产时间。

真实视频走隔离的普通 API 和 worker：任务 `43c7266e-2f53-4150-a757-b8ed4dac403c`，第二次尝试完成，用时约 400.5 秒，最终视频 22.1 秒、1920×1080、30 FPS、H.264/AAC。第一轮因为沙箱不提供 Metal GPU 失败，记录保留；随后在正常本机权限下重试。媒体 QA、包装 QA、完整解码通过。验收程序与实片位于 `autovideo/g3/acceptance/performance-stability-20261028/`。

首次采集、配音和复杂动画渲染仍然是主要耗时。上一条 7 分 58 秒产业视频的 48 分钟生产记录用于定位问题，本轮没有把它重新生成后再宣称整体提速。

## 页面与登录验证

`pages-before.json`、`pages-after.json` 记录 16 个主页面、矩阵工作区和详情、研究任务、报告、文稿四个工作区的正式浏览器检查。导航计时包含自动化开销，不是 LCP/FCP。初次进入的个别详情记录是加载中快照，后续完成数据加载后的记录另行保留。

用户完成登录后，工作台在队列空闲时通过现有维护锁重启；浏览器刷新保持 admin 登录，不要求再次输入密码。隔离的直连和网关实例都实际执行了重启、移除短期 access cookie、用原 refresh cookie 续期，返回 30 天会话。短暂续期失败与错误登录的前端回归均已覆盖。没有读取或保存用户浏览器的认证 Cookie、令牌或密码。

正式会话随后到达访问令牌有效期，浏览器自动调用 `/api/auth/refresh` 返回 200，页面继续保持登录；这段正式服务日志没有被动退出请求。仅保存不含令牌的路径/状态摘要于 `live-auth-recovery.json`。完成加载后的看板见 `console-after.png`、`home-after.txt`。
