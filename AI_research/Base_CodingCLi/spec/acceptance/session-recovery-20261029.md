# 30 天登录恢复与多标签页修复

用户反馈勾选“30 天内免登录”后仍反复出现登录页。历史登录审计及会话账本确认：重新登录时，多份旧 refresh 会话仍未过期、未撤销。历史访问日志只有 HTTP 状态，不能还原每一次 401 的具体原因；本轮不将某一种推断写成全部历史失败的确定原因。

## 复现与修复

- 续期重写 refresh 和 CSRF Cookie，并更换 CSRF。另一标签页较慢的续期响应可能覆盖刚完成的新登录。现在续期只写短期 access Cookie，保留原 refresh、CSRF 及其到期时间。
- 退出请求即使 CSRF 不匹配也会清除 Cookie。现在拒绝的旧退出请求既不撤销会话，也不清除 Cookie；正常主动退出仍撤销并清除。
- 旧 access 响应可能晚于账号切换到达。新 access 关联本次登录的 CSRF 摘要，旧响应不能把浏览器切回前一个账号；正常续期可恢复当前账号。旧版有效会话继续兼容，下一次续期自动使用新格式。
- 前端按登录事件区分请求，迟到的 401 不再清除新会话；恢复检查的迟到结果也不能覆盖后续登录或退出。标签页之间只共享事件标识，账号、密码和令牌不写入 localStorage。
- 其他标签页登录后自动恢复本页；回到页面时后台检查会话，暂时的网络故障不隐藏正在编辑的工作区。HTTP 局域网地址不依赖 secure-context 的 randomUUID。
- 网关返回 HTTP 200 启动 HTML 时，不再被误当作续期成功后又判定退出。
- Cookie 使用实际剩余秒数，不把剩余一分钟取整成一天。原有 30 天上限、签名检查、撤销和 CSRF 保护保持。
- 续期失败记录 `session_refresh`，区分 Cookie 缺失、过期、签名不匹配、格式错误、类型错误、撤销、用户停用和 CSRF 缺失/不匹配；附带 PID 和实例标识，不记录令牌、Cookie、密码或密钥。拒绝的退出记录 `session_logout`。
