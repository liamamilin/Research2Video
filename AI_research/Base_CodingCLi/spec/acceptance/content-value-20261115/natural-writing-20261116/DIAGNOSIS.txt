已证实的重复与路径
1. 三篇真实快讯全文：
   d74b8ce57a7d447788ddcf54e6fa9ed6：Fable 5.2 画幅 SVG 花 $1.42，这个价不能外推。
   8f9e295ec6874080bf9700dbdffdea35：Claude Code 的 Code Mode：项目里写 1 打不开，写 0 立刻关。
   2ebffe908d484210bab9f2f5a19d7828：GPT-6 Astra 补上 50 年缺口？先别急着信。
   不同材料都执行了“引子—问候—宣布一个决定—条件建议—什么会让我改主意—给观众下一步”。第三篇还直接说“拆成一个具体决定”。重复不局限于“如果你”几个字。
   三份 meta.introduction 都是 authored、requests=0，polish 都没有发现或修改，manuscript_workflow 都记录 flash-single-decision-v1 且 reader targets=[]。因此不能把这三篇的重复说成后处理机械插句；这是模型按当前指令初写出来、当前读稿标准又接受了的结果。
   快讯 draft 明确要求“开场选一个观众此刻真在犹豫的决定”“也说什么新的具体变化会让你改主意”；read/revise 继续只看决定与改选条件。这是直接对应产物的提示词诱因。
2. T05 栏目 notes 明确规定开头 15–20 秒、只比较 3 个维度、每维度先说结果、增加改选条件、结尾决策表，另列 A–G 七套结构并要求统一用对比表收尾。
   manuscript_jobs 没有启用 T05 专用 profile；因此应查当前栏目 notes，不能修改未启用的 t05-v1 后宣称生产生效。
   “相同任务或维度比较、保留使用条件”是内容要求；三维度和固定先后顺序是表达要求，两者不能一并删除。
3. 十个 illustrated 研究 job 共用的底稿结构要求“3到5步机制、一个好比喻、3到5个生活例子、2到3条误解、观众带走什么”。虽然下游再创作，原料已经按同一结构生成，可能持续诱发相似展开。当前只是提示词风险，须看真实稿件是否照搬，不能直接断言所有科普已八股化。
4. 多个日/周报在研究层、栏目层、写作层重复要求沿同一对象/任务推进、每层回到主例子、结尾回到开场。具体对象有助理解，应保留其价值；“每次必须回去”和所有背景仅能放在指定步骤，可能把论证、比较或历史叙事也压成流水线。这需要逐题对照，不能一次删除所有具体性要求。
5. 现有 polish.py 已有固定收尾/过渡的正则清理，但三篇截图稿没有命中。扩大禁词表只能捕捉新表面形式，不能解决上游要求重复。此次不扩充这套规则。

实际组装关系（已阅读源码，尚未做全部入口运行）
研究：core/engine.py 根据 job 类型分派；普通 job 再做矩阵变量替换和研究窗口追加。source_discovery/topic_discovery/topic_ideas 的 YAML prompt 多为入口说明，实际模型指令在对应 Python 模块。
写稿：web/services/video_workflow.py:_write 读取 profile_for；启用且有 draft 时，已有栏目用 draft 替换 context.notes，没有栏目则追加到 recipe.script_style。
随后 content_columns.apply_script_context 组合栏目 promise、type_definition.structure、notes、受众前提。非空 notes 会替换原 recipe 风格，因此不能把所有配置文本简单拼起来假装有效提示词。
联合规划的 direction 可再次追加；稿件主题与输入还受 audience_strategy、research_dossier、story_pool 与 question_material 影响。这几层的逐路径有效性仍待补足，不将静态快照标为“完整链路分析完成”。
manuscript_workflow.write 根据启用 profile/mode 决定是否读稿局部重写；writer.author_system_prompt 选择单条、整期、教程或专用整期模板，再追加 persona.prompt。
writer._request 在提供原始材料时另加主例子/任务推进与收尾要求。writer.write_for_column 另追加 episodes.brief。
初稿后介绍修复、整期开场另写、focused rewrite 和 polish 都可能再触发模型；失败时部分路径保留原稿。这些必须与初稿一起评估，不能只改 SYSTEM_PROMPT。

后续核对纠正与实验结果
已通读49份完整历史文稿，覆盖44个有稿job；science_weekly/culture_weekly仍作为未参与调试题保留。历史稿配置有变化，逐项观察不把当前profile倒推为旧稿成因。
13个选题入口已按当前配置追到实际分支：11个topic_discovery均mode=ideas；topic_ideas/chatgpt_acquisition为按请求出题；topic_platform/chatgpt_acquisition带platform_discovery_only，走公开平台发现。
题型outline只存在inspiration中，theme_workbench.production_input和theme_context.research_spec未把它传给作者。因此“3至6项大纲强制成稿分段”目前不成立，保留原有题型接口。真正继续传入的是catalog category.notes（同对象贯穿+四段顺序）或绑定content_columns.notes（包括T05的硬模板）。需沿这层修改，不能改错层。
来源发现实际SYSTEM明确不凑四类、不只公告；12个当前来源入口保留，不为去八股新增收集约束。素材积累走专门采集分支，无成稿模型提示。
两轮宽泛减约束路线未达到整体收益，未采用；去掉money角度强制谁换谁不换有局部效果，但不足以宣布去八股。教程宽泛draft反使重复更多。详见ROUND1-REVIEW.txt、ROUND2-REVIEW.txt。现从原控制开始试更小改动，仍未改生产。

补充诊断（第四轮后）：persona测试把“大家好，我是洛洛，今天我们聊聊”当正确提示词断言；开头检测会让缺少身份/话题的自然开头进入重写。实际flash请求还叠加配方中的开发者工作场景切入，单改persona不够。插画研究prompt末尾的“保留原有…结构”又强化了原先八段配额，作者配方仍另有4–6节等限制。修复必须沿实际覆盖/追加关系处理，不能只在总指令加一句“自然一点”。
