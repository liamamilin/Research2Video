旧规则

WorkBuddy 分享产物：没装企业微信也能打开

任务跑完，先别急着发文件
任务跑完了，最尴尬的不是结果不好，是对方公司不用企业微信，你手里这份 `2026双十一活动复盘.docx` 发不过去。大家好，我是洛洛，今天我们聊 WorkBuddy 的产物怎么生成一条分享链接，让没有客户端的人也能打开看。
我先拿一个示意任务来说：WorkBuddy 生成了一份 `2026双十一活动复盘.docx`。任务结束后，看右侧结果区——那是这次任务放结果的地方。切到“产物”，产物就是这次任务生成的文件，不是聊天回复。你会看到这份文档的卡片，点开它，进入预览。
这一步先别急着点分享。先看预览里打开的标题，确认就是 `2026双十一活动复盘.docx`。因为分享按钮分享的是当前预览中的产物，不是工作空间里那个旧文件。标题不对，就退回去重新点开正确的产物。

点右上角分享，选“发送链接”
预览打开后，右上角有分享图标。点它，会出现三个选项：发送链接、发送文件到微信、发送文件到企业微信。这里最容易手快。今天要选的是“发送链接”。选完，WorkBuddy 会生成一条分享链接。
你把这条链接复制下来，贴到邮件正文、群公告，或者任何能发文字的地方。接收方点开链接，就能查看产物内容。比如你给外部供应商写邮件，对方没装企业微信，你把链接粘在邮件里，写一句“复盘文档看这里”，他不用装任何客户端就能打开。

发送链接和发送文件，差在哪
发送文件到微信、发送文件到企业微信，是把 `2026双十一活动复盘.docx` 这个文件本身发到会话里。发送链接，是给对方一个能打开看的地址。一个给的是文件，一个给的是入口。
官方文档写了一个硬条件：发送文件到微信和企业微信，需要当前设备已经安装并登录对应的客户端。企业微信就是很多公司内部办公用的那个微信，和普通微信不是一个客户端。你电脑上没登企业微信，点“发送文件到企业微信”也走不通。这个时候别硬试，改选“发送链接”。
那什么时候该发文件？对方要拿到 docx 本身继续改、继续存档，选发送文件到微信，比如发到“市场部-小群”。如果只是让对方看内容、确认版本，链接更稳，尤其对方没装微信或企业微信，或者用的客户端跟你不一样。

分享前最后看一眼
再提醒一次最容易出错的点：点分享之前，看预览里的文件是不是你要发的那一份。产物列表里可能有旧版本，你点开的是 `2026双十一活动复盘.docx`，分享出去的才是它。别在结果区里点了一个旧卡片，然后把链接发出去。
我的建议是：内部同事都装了客户端、又要拿源文件，就走发送文件到微信或企业微信；对外、跨客户端、只想让人看内容，就走发送链接。你更常遇到对方没装客户端，还是需要拿到源文件？我是洛洛，我们下期见。

WorkBuddy 产物分享：对方没装微信也能打开

产物在哪，分享按钮在哪
任务跑完，WorkBuddy 交出来的东西叫产物——一份文档、一张表、一份报告，都算。它不在聊天记录里，在右侧结果区，顶部切到“产物”就能看到这一批文件的列表。很多人到这一步就右键另存，再想办法传出去。其实每个文件点开预览后，右上角有个分享图标。
为什么值得专门讲这个按钮：发给同事这件事，卡住的往往不是你这边，是对方那边。他电脑上没装微信、没装企业微信，或者只想在浏览器里扫一眼，你甩一个 docx 过去，他得先下载，再找能打开的软件，来回一轮就到下班了。

从产物到一条能发出去的链接
拿一份“2026双十一活动复盘.docx”举例，这是示意，你手上是什么文件就照着换。任务跑完，看右侧结果区，切到“产物”，找到这份文档。注意结果区里可能还躺着上次的旧文件，名字可能一模一样，先别急着点分享。
点开它，进入预览。预览里的内容就是等一下要分享出去的内容，所以这一眼别省：看一眼标题、日期、里面的数字，是不是这次任务跑出来的那一版。确认完，点右上角的分享图标，会列出几个选项——发送链接、发送文件到微信、发送文件到企业微信。选“发送链接”，生成一条分享链接，复制下来，贴到邮件里、贴到群公告里都行。对方点开链接就能看到产物内容，不用先收一个文件、再找软件打开。

发链接和发文件，差在哪
另外两个选项走的是另一条路：把文件本体发出去。“发送文件到微信”会在微信会话里直接出现这个 docx，比如发到“市场部-小群”，这是示意；企业微信那个选项同理，企业微信是公司内部用的那套，和日常微信是两个分开的客户端，装了微信不等于能发企业微信。这两个选项有一个前提：当前这台设备要装好并且登录对应的客户端。链接没有这个前提，能复制文字就能发。
所以选哪个，看对方接下来要干什么：只是看一眼内容、给个反馈，发链接；要拿原件去改、去归档，发文件。不确定对方装没装客户端，就从链接开始，省掉一轮“我这边打不开”。
你分享产物的时候，对方回你的第一句通常是“打开了”，还是“能不能发个原件”？评论区说说，我下次按这个来排。我是洛洛，我们下期见。

旧规则

元宝能点歌，DeepSeek 按小时卖转写：语音不是一件事

同一天两条语音消息，卖的不是同一个东西
一小时的会议录音想转成文字，DeepSeek 的语音接口一次只收两分钟，你得自己切成三十段传上去。同一天，元宝的语音通话里，你说“来首 2010 到 2020 年之间的英文民谣”，它顺着你的话往下接，还能自己判断要不要联网查天气。这两件事都被叫“语音能力”，但它们不是一回事。大家好，我是洛洛，今天聊一个具体的选择：同样是想用语音，元宝语音通话和 DeepSeek 刚开放的语音接口，你到底该用哪个，钱又该怎么算。
先把话说死：DeepSeek 这次开放的是语音识别和语音合成两个可以单独调用的工具，不是把元宝那种实时通话搬上 API。官方文档写得很清楚，识别是一次请求发送完整音频、返回完整文本，不支持流式。什么叫不支持流式？就是你得先录完，再上传，它再给你一整段文字。它不处理“你正说着、它已经在听、你改口它跟着改”这件事。
元宝这边是反过来的。Hy Realtime 接进元宝语音通话，官方说它能结合上下文，理解你口齿含糊、话说半截、中途改口。有篇体验文章写，作者试了一晚上，举的例子是“帮我设个八点提醒……算了，改成九点吧”，它能接住，不用你重说一遍。问“今天出门要不要带伞”，它自己判断去联网搜，搜完直接回答，中间不用你点一下搜索。这是实时对话那条线。

一个等你说完，一个陪你说下去
所以第一个差别，不是你问它答得好不好，是输入形态。DeepSeek 的识别接口，单次音频最长 120 秒、最大 8 MiB，双声道只识别左声道，语种由音频自动判断。你要转一小时的播客，就得自己按两分钟一段切，切三十段，还得注意别把一句话切断。这不是它做得不好，是它本来就不是为长录音连续转写设计的。
第二个差别是钱怎么算。识别按音频时长，官方价每小时 0.78 元，限时五折 0.39 元，也就是一小时三毛九，精确到秒。合成反过来，按字符算，限时价每 10,000 个计费字符 1.5 元，汉字算两个字符——一万个汉字，三块钱。而元宝那种实时语音通话，计费口径是会话或者用量，跟这两本账都不是一本。你在元宝 App 里用是免费的，但免费额度和限流规则跟 API 是两套东西。别拿 App 的免费去推算 API 的成本，也别拿 API 的报价去判断 App 值不值。

一小时三毛九，买的不是“能聊”
第三个差别是谁在用、拿来干什么。普通用户，想点歌、练口语、问天气不用手点，更新元宝，在语音通话里选“初语”音色，免费，路径最短。做内容的人，想把采访、播客、会议录音变成文字稿，DeepSeek 的识别接口够用，便宜，但你得接受分段和不流式。做产品的人，想给自己的应用加一个语音输入框、或者把回答读出来，这组工具可以单独调，合成还支持 WebSocket 分段送文字，模型一边生成它一边读。但你要想做实时语音客服、陪伴类对话，这套现在做不了，它没有打断、改口、边听边想这些事。官方说腾讯云计划近期开放 Hy Realtime 的 API，想做的可以等那个。
再说元宝那个点歌。官方说可以按歌手、专辑、曲风、语种、发行年份、热度组合着点，还能承接前文继续选。但那篇体验文章也写了，冷门歌没放出来；官方没说明歌声是实时生成、曲库匹配还是放原曲片段。所以我的判断是：把它当成一个能聊着选歌的语音搭子，可以；指望它唱出能发朋友圈的成品，再等等。官方自己说，下一步重点才是双工交互、长期记忆、前后台 Agent。翻译过来：打断抢话、记住你的口味、让它后台干活，现在还没到位。
有一个条件会改变选择：你是集中用还是零散用。如果你一天要转十段采访，分段上传这件事会很烦，你会想要一个能直接吃长音频的工具，这时候 DeepSeek 这个接口不是最优解，得配合切分脚本或者换别的。如果你只是偶尔把一段两分钟内的语音丢进去转文字，它便宜、够用、不用折腾。实时对话那边也一样：偶尔聊两句，元宝免费够；要做成产品接客服，等 API，别自己拼。

如果你是这几种情况，就这样选
所以落到选择上：想在手机上点歌、练口语、问天气，选元宝语音通话，更新后选“初语”，免费。想把播客、采访、会议录音转文字，选 DeepSeek 的识别接口，一小时三毛九，但单段最长两分钟，长录音要自己切。想给自己的应用加语音输入和朗读，选 DeepSeek 的识别加合成，合成限时价一万个汉字三块钱。想做实时语音客服或者陪伴对话，现在别拿 DeepSeek 这套凑，等腾讯云开放 Hy Realtime 的 API，或者另找实时方案。
回到开头那个问题：同样叫语音，元宝和 DeepSeek 卖的不是同一样东西。一个卖的是“你说话它接得住”，一个卖的是“你把音频给我，我给你字”。前者你现在在元宝 App 里就能免费用，后者是按小时、按字符算钱的积木。我的建议是：普通用户先别因为“DeepSeek 开放语音 API”就觉得元宝要升级了，这两件事互不影响；做产品的人，先想清楚你要的是转写还是实时对话，再决定掏哪份钱。你有没有把一段长录音丢给 AI、结果被要求切段的经历？最后是怎么处理的？评论区聊聊。我是洛洛，我们下期见。

采用方向

元宝语音能点歌，DeepSeek 的语音 API 却不会聊天

同一天两条“语音”消息，说的不是一回事
同一天，两家都发了跟语音有关的消息。腾讯混元发布实时语音模型 Hy Realtime，元宝的语音通话里能点歌、能自己判断要不要联网；DeepSeek 开放了一组应用接口，语音识别和语音合成也在里面。很多人扫一眼标题就觉得：哦，两家都在做语音。其实这是两样东西——一个是你对着手机聊天的助手，一个是你写代码时调用的零件。买错了，钱花了，事还办不成。

元宝这边：话说半截能接住，点歌能聊着选
先说元宝。把 App 更新到最新版，进语音通话，音色选“初语”，就能用上这次的模型。它要解决的是平时最烦人的几件事。官方说，人说话口齿含糊、话说半截、说一半又改口，它能结合前面的对话把意思还原出来；回答的时候一边生成文字一边合成语音，不用等你把话说完、憋半天才开口。
还有一个动作看着不起眼，其实很实用：它会自己判断这句话要不要联网。你问“今天出门要不要带伞”，它查完天气就直接回你，不用念一句“为您找到以下结果”，再让你伸手点一下搜索。这一下，搜索从你的动作变成了它自己的动作。
点歌最能看出差别。官方给的例子是“来首 2010 年到 2020 年之间的英文民谣”，它可以按歌手、专辑、曲风、语种、发行年份和热度组合着点，也能接着上一句往下选。以前点歌像喊口令，一首不行再喊一首；现在是聊着选。
但有两点得说清。第一，官方没说清歌声到底是实时生成，还是调腾讯音乐的曲库、放原曲片段，只说是跟 TME 灵音 AI 团队一起做的。第二，有第三方体验文章在最新版元宝、选“初语”的条件下试了一晚上，说连续点歌、换风格、追问版本都接得住，但想听的冷门歌没放出来——曲库有多广，还得看腾讯音乐的家底。这是那篇文章的体验，不是我的实测。

DeepSeek 这边：一次发完整音频，返回完整文本
再看 DeepSeek。11 月 13 日它开放了一组应用接口，把官方 App 和网页端在用的联网搜索、文件输入、链接阅读这些工具接到对话接口上，语音识别和语音合成也在里面，可以单独调用。但这两样是“积木”，不是元宝那样的实时通话。
语音识别这边，接口文档写得很直白：一次请求发送完整音频，返回完整文本，不支持流式识别。单次音频最长 120 秒，超过了就得你自己切段；双声道音频只认左声道；语种不用填，它根据音频自己判断。翻成大白话：它适合做“语音输入框”——你按住说一段，松手，出来文字。一两个小时的会议录音、播客素材，它不是那种边听边想、被打断还能接着聊的东西，你得先切成两分钟一段再喂进去。
语音合成正好反过来：给文字，返回音频。可以整段发，也可以走 WebSocket 把文字分段送进去，模型还在生成的时候就开始读。但文档明确写了，它不支持调节语速，也不支持中断之后续传。断在半截，你只能重新来。

两笔账不能混算
钱这块最容易混。语音识别按音频时长算，限时五折是每小时 0.39 元；语音合成按字符算，五折是 1 万个字符 1.5 元，一个汉字算两个字符。而实时语音通话是按会话或者用量计费，是完全另外一本账，跟 App 的订阅价也不是一回事。所以要比价，先得说清你买的是实时对话助手，还是录音转写、文字朗读。

你先坐哪一边
所以选哪个，先看你坐在哪一边。普通用户想找个能聊、能点歌、问天气不用自己再点一下的，直接在最新版元宝 App 里用语音通话就行，不用碰 API。开发者想给自己的应用加个语音输入框，或者把回答读出来，才去看 DeepSeek 这套接口。腾讯云那边说 Hy Realtime 近期会开放 API，跑客服、做语音助手的团队可以等到那时候再评估。
还有条边界得记住：这一轮里，DeepSeek 开放的是转写和朗读，元宝那种听懂半截话、临时改口、自己决定要不要联网的实时对话，没有出现在这套 API 里。这两件事不能拼成同一场对比，也不能拿一套转写接口的价钱去算一个实时助手的成本。
我的判断是，这次最值得带走的不是谁更强，而是先分清三层：实时语音对话、语音转写、语音合成。你日常拿着手机用的是第一层，元宝这次动的是它；你想自己做个小工具，用的是后两层，DeepSeek 这次放出来的是它们。分清了，就不会为了一个点歌功能跑去买一套 API，也不会指望一个转写接口替你搭出能陪着聊天的助手。
你自己平时用语音最多干哪件事？是聊着点歌、问天气，还是把录音转成文字？评论区说说你的用法。我是洛洛，我们下期见。

一段没词的人声，署名用了三十二年

本期导读
你先听一段没有词的女声。高音冲上去，又落下来，像有人在哭，又像有人在笑。我猜很多人第一次听，会以为这是 Pink Floyd 某个人想出来的。可录《Dark Side of the Moon》的时候，Clare Torry 进棚问乐队：你们想要什么？她得到的回答基本是“不知道”，唯一清楚的指令是：不要词。她决定“假装自己是一件乐器”，录出了这段人声。1973 年专辑发行，作曲栏署的是乐队成员；2005 年她与 Richard Wright 和解，才拿到共同创作署名。同一段声音，前后意思不一样。
大家好，我是洛洛。今天我们聊聊署名——一件作品到底是谁的，这件事是怎么被决定的。就从 Clare Torry 这段没有词的人声说起。

录音棚里那句“不要词”
Clare Torry 进录音棚的时候，二十出头。她唱过广告歌，也翻唱过别人的歌。制作人 Alan Parsons 临时把她叫来，她不是 Pink Floyd 的粉丝。她后来回忆，原话是：“如果是 The Kinks，我会高兴坏了。”
她走进棚里，问乐队：“你们想要什么？”她自己的说法是，他们根本不知道。唯一一句清楚的指令是：不要词。
她做了一个决定。她说：“我要假装自己是一件乐器。”David Gilmour 在耳机里给了她几句引导，有人递给她一罐 Heineken。她就“随便试了一下”。录出来的就是那段声音。
这里有个细节值得停一下：乐队没有先写好一条旋律让她唱。他们给的是一个空白的和声进行，和一句“不要词”。她在那个空白里，自己造了一条旋律线。这就是后来争议的核心——这条线，算谁的？

先被当成乐队的声音
1973 年专辑发行。唱片上，这首歌署的是乐队成员。Torry 的名字不在作曲栏。她拿的是一次录音的钱，行业里叫录音棚歌手。这段声音就跟着专辑、电台、现场，被当成 Pink Floyd 的一部分传出去。
Alan Parsons 1973 年做过一版单独抽出来的人声音轨。你把乐队去掉，只留钢琴、鼓、滑音吉他和她的声音，能听见她怎么在伴奏上找音、怎么往上推。那段声音不是装饰，它撑着整首歌。
但这首歌本身也一直在被重新装配。1972 年早期现场版里，还有圣经朗读和 Malcolm Muggeridge 的录音。到了最终版，这些东西被换成了乐队工作人员和朋友回答“关于死亡”的片段。同一首歌，不同的版本，装进去的东西不一样。
我的判断是：唱片工业的账本分得很清楚。谁在棚里“写”，谁在棚里“唱”，合同上不是一回事。可 Torry 这段声音恰恰卡在这条线上——她没有写词，但她唱出了一条旋律。当年的行业没有给“人声即兴”留作者的位置，所以她就“不是作者”。

三十二年后，名字回来了
2005 年，Torry 和 Pink Floyd 的键盘手 Richard Wright 达成和解。这个动作不是补录声音，是改署名：她拿到了共同创作署名。有歌曲创作专家认为这完全合理，因为她在录音棚里实际上为这首歌创造了新旋律。
从专辑发行到名字回到作曲栏，隔了 32 年。声音没有变，变的是人们怎么理解“作者”这件事。
我更看重的是这个：这不是补一个名字，是承认一种劳动。她当年拿的是一次录音的钱，2005 年拿回的是“这条旋律是我写的”的承认。差别不在声音，在谁有能力说“这是我做的”。

梵高也不是一个人成为梵高的
把镜头拉远一点。同一周，Open Culture 写了一件事：梵高能成为梵高，离不开他的弟媳 Johanna Bonger。Theo 死后，她保存梵高的作品，一家一家去谈博物馆，甚至直接捐画，换公开露出的机会。1905 年，她在阿姆斯特丹 Stedelijk 博物馆办了 484 件作品的大展，至今仍是最大的梵高展。她还把梵高的书信翻译、出版。
这周还有另一条：科学家用星位、天气模型和梵高书信，质疑《星月夜》到底是不是 1889 年 6 月画的，认为可能更接近 7 月的天空。一幅画的“事实”都还在动。
所以署名从来不是一个人的事。Torry 的名字、梵高的名声，都是后来的人一次次谈判、展览、翻译、争论出来的。

今天谁算作者
同一周，Hyperallergic 让 Claude 写一段反 AI 写作的开头。它写的是：“墙标。新闻稿。艺术家陈述。在今天快节奏的艺术世界里，书面文字站在一个关键十字路口——赌注从未如此之高。”写这篇文章的人说，一看就反感。那种“过度自信却空洞”的腔调，藏不住。他说，问题不只是方便，是“真实性”。
这也解释了为什么 AI 那段让人觉得空：它没有这样一个可辨认的人的动作。回到同一段人声，换一个展示场合看。1973 年，Alan Parsons 把 Torry 的声音单独抽成一条音轨：乐队伴奏退到后面，能听见她在和声进行上自己找音、自己推出一条旋律。这个动作让听众先辨认出——唱的人不是念台词，她在写一条线。材料里对这段录音的理解也落在这里：歌曲创作专家认为，她实际上为这首歌创造了新旋律，所以 2005 年她与 Richard Wright 和解、拿到共同创作署名是合理的。
我的判断是：AI 写作让人反感的，不只是质量差。它把艺术界不愿承认的“模板劳动”暴露了。墙标、新闻稿、艺术家陈述，本来就有大量套路。机器一写，套路就藏不住了。
这和 Torry 是一条线：谁在写，谁被看见，谁的名字留下来。区别在于，Torry 花了 32 年才拿回名字；AI 连“想拿名字”这回事都没有。

本期回顾
回到那段人声。今天再听《The Great Gig in the Sky》，你听到的不只是一段高音。你听到的是一个临时决定、一罐啤酒、一次“假装自己是乐器”，和 32 年后的一次谈判。
我的判断是：署名不是给天才发奖，是给劳动定价。Torry 当年拿的是一次录音的钱，2005 年拿回的是“她写了这条旋律”的承认。差别不在声音，在谁有能力说“这是我做的”。
你身边有没有那种“大家都以为是某个人做的，其实是另一个人”的东西？可以想一想。
我是洛洛，我们下期见。

采用方向

她被告知“不要词”，三十三年后署名加上了她

本期导读
我是洛洛。
你在流媒体上打开《The Great Gig in the Sky》。中段有一段女声，往上冲，没有一句词。你看了署名：Richard Wright和Clare Torry。
1973年这张唱片刚出来的时候，署名上只有Richard Wright。
1972年6月，伦敦Abbey Road录音室，一个叫Clare Torry的年轻录音室歌手被叫进来。她问乐队：你们想要什么。答案基本是：不知道。唯一的指令是：不要词。
她做了一个决定：我要假装自己是一件乐器。她戴上耳机，David Gilmour在她耳边说了几句话，她喝了一罐喜力，随便试了一下。录出来的，就是那段声音。
同一段声音，怎么从“乐队曲子里的一段人声”，变成了“一首她参与写的歌”？

她说，那我假装自己是一件乐器
Torry不是Pink Floyd的粉丝。她后来说，如果是The Kinks，我会高兴坏了。
她进棚之前，这首歌的早期现场版本里还有圣经朗读。到最终版，换成了乐队工作人员和朋友回答关于死亡的问题。
她听到的伴奏已经去掉了很多东西，只剩下钢琴、鼓、滑音吉他。
她没有写词，也没有唱词。她把自己当成一件乐器，用气息和音高去填那个空。录完之后，她觉得自己只是“随便试了一下”。
但那段声音有一个东西：它有自己的旋律。它不是把一段已经写好的旋律唱出来，而是在相对空白的地方绕出了一条线。后来，这条线会被摆到一次谈判的桌面上。

1973年，唱片上只写着一个名字
《The Great Gig in the Sky》收在《Dark Side of the Moon》里。1973年的唱片封底，这首歌的署名只写着Richard Wright。
Torry拿到的是录音室歌手的一次性酬劳，一张支票，没有后续版税。后来很多年，听众听到那段声音，会以为那是乐队的一部分。
署名行不只写谁唱了。它决定谁分版税，谁在版权登记里被算作作者，谁以后可以说“这是我的歌”。

2005年，她去改了署名
2005年，Torry和Richard Wright达成和解，她获得了共同创作署名。今天你在流媒体上看到的“Wright/Torry”，就是那次谈判的结果。
为什么合理？有歌曲创作专家说，因为她实际上为这首歌创造了一条新旋律。那条线不是Wright事先写好的，是她唱出来的。
Torry后来在采访里回忆，她当时只是“随便试了一下”。但“随便试了一下”的结果，被录下来，被放进专辑，被播放了五十多年。署名行改的不是她的记忆，是这条声音在法律和版权里的位置。

梵高被看见，靠的是另一个名字
不过，署名行还有另一层：它不只决定版权归谁，也影响一件作品能不能被看见。Torry改的是那段声音在法律和版税里的位置；梵高这边不是版权争议，而是传播史——让他的名字抵达后世的，是另一个人的长期行动。
梵高活着的时候，只卖出过一幅画。他去世后不到一年，弟弟Theo也走了。把梵高变成梵高的，是Theo的遗孀Johanna Bonger。她保存作品，一家一家博物馆去谈，1905年在阿姆斯特丹的Stedelijk博物馆办了484件作品的大展——到今天还是最大规模的梵高展。她还把梵高的书信翻译出版。
梵高的署名行上当然只写着Vincent van Gogh，Johanna Bonger不是《星月夜》的版权共有人。她做的是另一件事：让署名行上那个名字，被更多人看见。
回到Torry：她的情况和梵高不一样，她要争的是那段声音在版权里的位置；但两件事都提醒我们，作品背后常有一条被忽略的劳动链。她那段声音没有词，所以最容易被当成“乐队的一部分”；也正因为没有词，它最容易被漏掉，直到有人去改署名行。

本期回顾
今天再听《The Great Gig in the Sky》，那段声音还是那段声音。但你看署名，会看到两个名字。一个是写和声的，一个是唱出那条线的。
同一段声音，在两个场合里是两件东西。
你今天打开一首歌，看署名行，可以想一想：这条线上还有谁的名字没写上去？
我是洛洛，我们下期见。
