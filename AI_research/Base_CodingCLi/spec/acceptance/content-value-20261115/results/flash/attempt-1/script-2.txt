DeepSeek把语音、搜索、文件拆成API：小团队先算哪几项

DeepSeek 这波最值得小团队注意的，不是又多了一个模型，而是语音、搜索/抓取、文件解析/OCR 被拆成可以按项调用的 API。大家好，我是洛洛，今天我们聊聊：如果你在做语音助手、会议记录、文档处理或 RAG，这几项到底怎么计价，先试哪一段，哪些价格又不能当成长期价。普通用户可能只感知到功能变多，真正要算账的是接 API 的小团队和独立开发者。公开信息里有一句很关键：官方 App 的功能可以自由组合调用；但官方公告和接口文档的细节还要再确认，尤其是限时价截止时间、稳定性和并发限制。
过去小团队常见的做法是语音、OCR、搜索分别找不同供应商，或者买一个打包服务；现在至少从价格页看，ASR、TTS、Search/Fetch、文件解析/OCR 是分项列价的。原来的感觉是这些能力只能整包买，现在可以拆开买；但拆开不等于便宜，每一项都要单独算量、单独做限流和失败处理，成本不再是一口价。

语音先看两个单位：TTS 按每万字符，列表价 0.45 美元，限时五折 0.225 美元；ASR 按每小时音频，列表价 0.116 美元，限时五折 0.058 美元。这里最容易误判的是，ASR 的“每小时”是音频时长，不是你会议开了多久就花多少文本 token；TTS 的“每万字符”是你要播出来的字数，不是输入给模型的字数。做会议记录，先把这两笔分开。
搜索和抓取都是每 1000 次 0.75 美元，直接调 Search/Fetch API 算，模型通过 web tools 用也算；文件解析/OCR 是每 1000 页 0.225 美元。也就是说，RAG 里“找资料”和“读文件”是两种账：搜索按次数，文件按页数。你做文档问答，别只盯模型 token，前面 OCR 和后面抓取都可能单独冒出来。
模型侧还有一层峰谷价：Flash 和 Pro 都支持工具调用、Responses API、Anthropic API，上下文 1M；Flash 支持视觉，Pro 不支持视觉。高峰是 UTC 周一至周五 01:00–04:00、06:00–10:00，非高峰价是高峰价一半。这个结构对小团队的意义是：能挪到非高峰的批处理，和必须实时响应的语音入口，要分开算。

如果我现在带一个小团队做会议记录，我会先把链路拆成四段：录音转写走 ASR；转写文本做总结；需要播报再走 TTS；只有涉及实时信息才接搜索/抓取。第一段先试 ASR，因为它是会议记录最刚性的成本，也是最容易用量估算的一段：一小时音频的列表价 0.116 美元，限时价 0.058 美元；你先拿真实会议时长乘一下，就知道试点预算大概在哪。
总结这一段用 token 计价，Flash 和 Pro 的输入输出价不同，而且高峰和非高峰差一倍；所以会议记录不要只报“语音转写多少钱”，要把总结模型、输出长度、是否峰值调用一起算。TTS 我建议放最后，除非你的产品真的要语音播报；它按每万字符 0.45 美元列表价、限时 0.225 美元，播报稿越长越要单独控制。
搜索/抓取和 OCR 不是会议记录的默认项。会议里如果要查实时资料，才接搜索；如果有大量文档要读，才接文件解析/OCR。搜索和抓取每 1000 次 0.75 美元，OCR 每 1000 页 0.225 美元，量小的时候不吓人，量一上来就是独立成本项。

最不能直接写进长期报价的，是语音的 50% 限时价。TTS 0.225 美元、ASR 0.058 美元是限时五折，列表价是 0.45 和 0.116；现在还没看到明确的截止时间，所以做预算时我建议至少按列表价做底线，限时价只用于试点期或者促销测算。
搜索/抓取和 OCR 现在页面上没有标限时折扣，但也不等于长期合同价；模型 token 的峰谷价是结构性价格，适合做调度策略，不适合假设永远不变。还有一点，模型侧能看到并发限制：Flash 2500、Pro 500；语音和 OCR 的限流细节还没看到，这会影响你能不能扛住高峰，而不是只看单价。

所以小团队先算三项：第一，ASR 的真实音频小时数，这是会议记录和语音入口的底座；第二，总结模型的 token 量和峰值/非高峰调度；第三，OCR 的页数和搜索/抓取次数。TTS 先作为可选项，等产品确认需要播报再加。这样拆的好处是，你能只替换最贵或最不稳的那一段，而不是整包换供应商。
但我不建议现在就把“限时价”当成替换第三方服务的理由。更稳的做法是：先用 ASR 做一个小流量试点，按列表价算长期成本，按限时价算试点预算；同时确认官方接口文档、截止时间、稳定性和并发限制。等这些清楚，再决定是自建语音入口，还是继续用第三方打包服务。
