## 1. Claude Fable 5.2 降到 8/40 美元，OpenRouter Auto Code 每任务便宜 74%

v1 · `de591243` · 「Claude Code 默认模型换成了 5.2」「OpenRouter：把选模型交给路由器」「本期回顾」。

> 你升级完，看到的默认模型、计费单价、缓存价格，三样一起变了。

这比报价更新有用。观众能据此检查自己的默认模型和真实单任务账单。OpenRouter 一节也给了独立解释，换模型会重建输入缓存，所以一个好的路由器应当知道何时继续留在原模型。两者可以串成一条主线，讲谁在替团队决定每次调用，以及这个默认决定怎样改变成本。后半再接部署和安全，就需要新的组织逻辑。原结尾把默认值、开关、信任边界并列，概括了栏目覆盖面，却没选出本期最值得记住的变化。保留模型迁移、缓存取舍和具体可做的检查，压缩入口清单。74% 与五项基准一起说一次即可，观众随后能听到我们会把路由用在哪一类任务上。

## 11. ChatGPT 转圈报错：先查状态页，再做 5 步本地排查

v1 · `ea11be6a` · 「操作：按 5 步本地排查」「结果：恢复还是继续报错」「本期回顾」。

> 每做一步，回到同一份 PDF 和同一条提示词上试，别同时改好几个变量。

这一句把操作清单变成排障方法，应早一点说。读完同一 PDF 在换环境后恢复的分支，观众已经知道下一步怎么做。后半加入图片生成、重复账单、退款、功能入口和不同错误提示，一篇针对“转圈”的操作稿被扩大成故障目录。保留同一请求贯穿全篇，最后只交代换环境恢复与始终复现两条后续路。状态页会汇总不同组件、套餐和错误，真正影响操作的点是查对应组件之后还要用同一输入验证；把这一点顺着操作说出来，比正反两句提醒更短也更有用。

## 跨稿取舍

- **优先保留判断。** 混元的自主验收、Seedream 的第十轮、Fable 的任务成本、Hermes 的审查覆盖、千问的写权限，已经比原材料多给了观众一步。它们适合直接承担结尾，或提前担当标题和开场的承诺。
- **在影响选择处说条件。** 路由的成本和峰值表现、图像 API 与客户端的参数、折扣试用时机、私有仓库的代码去向，都会改变做法。原句把条件说清之后，再读一遍出处或无条件适用的声明，通常没有新信息。
- **按稿型结尾。** 快讯要让几条新闻共同推出一个新观察，比较稿要说清哪个条件会改选，教程要把成功的结果交给观众。Muse Ember 问“哪个子调用最费钱”能延续讨论，Pro 让观众提前选付费档位和 Seedream 让观众再站队会冲淡已经给出的判断。
- **区分内容方向和写稿流程。** 11 篇版本的审核元数据均为 `on_request`，没有依据把这一天观察到的套话归因于逐稿事实审核。实际稿里既有有效判断，也有用覆盖清单或互动模板消解判断的段落，改进应落在选材、篇章和收束。
