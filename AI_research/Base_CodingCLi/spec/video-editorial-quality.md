# 文稿提示词逐项打磨

> 2026-10-24：默认生成已按唯一目标重置，见 [当前流程](video-goal-first.md)。下文保留旧实现及试验历史，不作为新生成的约束。

2026-10-23。目标是写出目标观众愿意听、跟得上、听完有收获的文稿。资料与审校支撑创作，不能把口播变成研究摘要、参数清单或免责声明。

## 公共原则

先找值得讲的角度和主线，再决定材料、顺序与讲法。允许取舍、重排、个性、判断、悬念、类比和自然口语；重要的是实际效果，不是是否使用了某种技巧。完整调研不等于正文全讲，参数可留在资料或简介。

2026-10-24：作者侧只说明角色、目标和必要的数据格式，不再叠加公共来源规范、受众文案规范、统一示范稿与重复写法清单；来源核验留在独立审校环节。配方提供题材和风格，段落、结构与篇幅交给本期内容。

观众没有看过内部选题，不需要跟着创作者逐项纠错。研究结果应重新组织成面向观众的讲述。旧报告若带有模型完整的开头 `<think>` 块，只把后面的正式报告交给写稿、底稿拆分和审校；原文件不改，正文与文末来源不裁截。没有完整结束标签、或标签在正文内部时不擅自删除。

配方时长、字数、节数、段长、条目与动作数量都是参考。不为时长压缩必要解释，也不靠重复扩写；不强塞反方、教程、例子、回顾或行动。每个名词是否需要解释，取决于受众和当前语境。

底线是不要实质误导：不编造事实、数字、网址或测试经历，不把单个测试点推广成普遍规律。清楚归因的厂商自述可以使用；缺少第三方复测本身不是错误，也不要求逐句重复「未独立验证」。来源存在争议时可以准确介绍争议，不要求视频替来源解决它。

## 各环节的修改

| 环节与实现 | 本轮调整 |
|---|---|
| 公共指导 `core/video/policy.py` | 把角度、主线、听感、收获放在首位；区分来源支持与独立实验 |
| 一次写稿 `writer.py` | 从报告中创作，不照搬报告结构；交稿前处理无聊、拗口、重复与跳跃 |
| 事实底稿 `adapt/facts.py` | 事实素材保留具体内容、原始出处与实际条件；取材范围、资料缺口、后续查证与写作建议分存 research_notes，不作为作者素材。作者的素材视图也不携带审校置信度分类、推导记账等后台字段，核验仍读取完整底稿。厂商材料不因缺少复测降为无依据 |
| 讲述方案 `adapt/plan.py` | 决定角度和取舍；目标、因果链、术语表、误区与行动可以为空，不强制写成教学大纲 |
| 改编初稿与改写 `adapt/draft.py` | 方案是编辑思路，正文按叙述需要展开；保留亮点，不逐条把审稿意见填进正文 |
| 两条事实审校 `audit.py`、`adapt/review.py` | 只找实质误导，结合全文归因和前提；不要求每项结论念完全部实验参数 |
| 风格审校 `audit.py` | 从栏目合规检查改为主编评读：角度、推进、节奏、语言与收听意愿 |
| 两条观众评读 | 关注值得听与能否跟上，不追问所有生词，不要求补成百科；测验和评分只用于诊断 |
| 一次写稿后的改写 `audit.py` | 修实际问题，可删冗余、收窄或换讲法；字面参数遗漏只供复审参考，不强行退回原稿 |
| 受众文案指导 `audience_copy.py` | 制作备注留在记录；真正影响观众判断的疑点可以自然表达 |

公共提示词覆盖选材、写稿、修改、事实审校、编辑评读、观众反馈、候选比较和标题选择；研究端同步精简 agent、pipeline、fetch-only、查询规划与报告收尾提示。

两条流程都给具体的收听障碍整篇主编编辑机会：采用模型指出的主编问题 S1 或听不下去的位置 N2，意见供编辑取舍。普通疑问、评分、字数和数量偏差不会触发它，也不需要把所有编辑意见改到消失。改后复查事实，具体事实问题先尝试修复；未通过或复查失败时保留此前有依据的稿件。修改前内容和尝试记录留在元数据中。

2026-10-24：发现具体收听障碍时，两条流程优先给整篇编辑机会，将事实问题一并作为编辑资料，不再要求逐段修订全部结束后才能改善讲法。候选仍完整复审，实际事实问题仍需解决；候选失败不覆盖原稿，五步改编继续修复保留稿。普通疑问、分数和数量偏差不触发整篇重写。

编辑可删除整段或整节旁支，不再为了维持旧章节把删掉的内容自动补回来。最终文稿保持非空；结构调整后重新核对全文，五步改编会清理旧段落编号对应的审校结果。

## 自动编辑流程

v7 的手工改写不能作为自动生成的验收证据。此前的主要缺口是：模型虽然指出结构问题，执行时仍按段落补丁修改，原稿的材料选择和顺序很容易原样保留下来。

`core/video/editorial.py` 将编辑行为接入正式 workflow：

1. `single` 路径先提取并缓存事实底稿，再自动比较讲法并生成选材方案，保存在 `meta.editorial_brief`。作者只收到选定角度及入选事实，不再同时收到整篇报告、研究者的推荐讲法、未选角度和舍弃清单；完整报告仍供后续核验。`adapt` 路径沿用已有的事实底稿和讲述方案，初稿只使用方案选入的事实。
2. 事实与来源错误先修复。真正的收听障碍进入编辑：主编根据原稿和收听反馈判断需要结构重写，还是局部润色。结构重写重新选材，把新方案及入选资料交给看不到旧稿的作者；局部润色保留成立的讲法，处理具体句子、衔接与重复。方案与判断保存在 `editorial_attempt.editorial_brief`。两条路径共用这个环节，可换标题、重排、合并、删节或重新组织。
3. 新稿全文重新核对事实。`single` 路径使用原始完整报告；已有具体事实疑点、作者明确标记的疑点与新发现的问题仍需明确解决，编辑行为本身不自动给所有新段落加待核实。`adapt` 路径重新解析事实编号并核对完整事实底稿，不沿用旧编号的结论。事实不通过、存在待核实或复核失败时保留原稿。
4. 事实通过后，再比较两篇完整口播，先记录具体的收听体验，再依据角度、推进、细节和听感选择。比较只看视频标题与实际朗读的正文，不看小节标签和审校标记；没有实质改善或比较失败时保留原稿。事实通过不等于编辑通过。

整篇候选稿、原稿、标题、反馈、比较理由和采用结果保存在 `meta.editorial_attempt`。最终采用时同步更新标题、正文和长度；改编稿同步更新介绍与来源。编辑失败不覆盖此前已核对的内容。时长、章节、数字数量和固定开头结尾没有成为新的放行条件。

这些步骤由 workflow 自动调用，不需要 Codex 逐篇提供编辑方案。额外模型调用会增加生成时间；验收仍以真实自动输出为准，离线测试只验证编排与失败处理。

首次完整自动试写 v8 仍选材贪多。整篇候选稿也保留了过多功能和跑分，一段未得到充分的明确核验，因此保留原稿；不能把这个结果称为质量达标。它促成了 v2 的选材调整：比较不同切入，记录选择理由，并隔离真正交给口播作者的素材。

v9 自动去掉了发起方和项目履历，流程选择了更顺的编辑稿，但功能清单、路由约束和跑分仍沿用旧提纲，距 v7 示例的取舍还有差距。v3 据此让整篇编辑先重新策划，再交给一个看不到旧稿的作者，不把“允许重写整篇”等同于真的完成了结构编辑。

v10 从同一原报告和原选题调用 `run_rewrite` 全自动生成，没有人工角度、人工改正文或把 v7 作为生成输入。自动重新策划舍弃了跑分与硬件支持表，采用稿改为围绕过载、升级和会话路由展开；来源复核没有留下事实问题。原报告、v7 和所有历史版本保留，新稿保持 DRAFT，未定稿、未出片、未发布。

留档：`output/video/llm-d_automatic_v10_2026-10-23.md` 和同名 JSON（完整编排、方案、候选、比较、来源报告摘要值）。单独的文字对照 `llm-d_v7_vs_automatic_v10_2026-10-23.json` 未作为生成输入；模型选择自动稿，但这不是稳定质量的证明。开场仍偏履历，部分术语与转场需要打磨。不能根据单一题材和同一模型的评读宣称所有配方已稳定达标。

v3 离线验证：`python -m pytest tests/test_video_*.py tests/test_recipe_audiences.py -q`，553 项通过；`compileall` 与 `git diff --check` 通过。测试验证自动选材隔离、从新方案写稿、整篇重排及换标题、来源疑点不被空结果清除、事实复核/编辑比较失败时保留原稿等行为，不给文稿精彩程度打包票。

## 开场与转场的输入修正（主编 v4）

v10 的实际开场仍先纠正项目历史，说明仅在提示词里要求自然口语不够。重新检查输入后，处理了几处会把作者拉回研究报告的原因：

- 两条写稿路径都从对象事实选材，内部选题纠错、检索评论与推荐口播留在研究记录，不进入策划输入。原报告保存完整。
- 资料包由代码按有效事实编号构造，保留来源、归属和条件；不再信任模型自行写的长篇 `material`，避免它顺手带回已经舍弃的材料。事实按实际讲述顺序排列。
- 策划写出选中的实际开场与段落关系，交给作者。关系说明“为什么听到这里想接着听”，不把章节标签当成转场；可以按配方多线展开，不规定章节数、开场句式或结尾任务。
- 两条观众评读都只收到编号正文，小节标题不能替口播补解释。全文比较也去掉小节标签，并记录具体在哪句话感兴趣、走神或跟丢。

新增离线测试验证事实选择与来源条件、无效编号重试、叙述顺序、开场和关系传递，以及两条观众评读不借用小节标题。真实试写仍从原报告和原选题开始，示范稿只可在生成结束后作只读对照。

v11 开场从履历转向开发者的上线问题，但后续仍列功能，再跳到路由限制。自动主编尝试改为过载拒收主线，其中一句“不会让单次推理变快”扩大了结论，候选稿被整篇退回。这个结果暴露了编辑候选没有事实修复机会的问题。

v12 增加候选稿事实修复后，自动补好开场引用，再完成来源复核和全文比较，采用了过载拒收讲法；没有人工提供角度、正文或示范稿。原报告和全部历史版本摘要值不变。实稿仍有“强开场后退回官方定位”、术语代替解释、结尾重复，不认定质量已达标。

留档：`output/video/llm-d_automatic_v11_2026-10-23.*`、`llm-d_automatic_v12_2026-10-23.*`。JSON 保存自动策划、候选、事实修复、比较及生成输入的审计信息。

## 自动继续打磨（主编 v5）

开场用独立的 `opening_facts` 记录依据，素材顺序先跟随实际开场，再接后面的讲述。策划需要从开场继续推进，避免给出具体变化后又重启对象介绍、最后重复开场结论。

两条路径都允许继续处理实际收听障碍，每次从保留的稿件继续，重新选材、写稿、复核事实，再比较全文。候选没有明显改善时保留原稿，将拒绝理由供后续策划参考；事实仍不通过或调用失败时停止。最多三次编辑是调用资源上限，不是文稿配额或评分门槛；没有实际收听障碍时提前结束，一般疑问和低分本身不会触发它。

整篇候选的具体来源问题先按已有事实修复预算处理，修复后重新复核，再进入收听比较。改编路径同步更新主线与入选事实，不沿用旧稿的段落测验。全部尝试保存在 `meta.editorial_attempts`；兼容字段 `editorial_attempt` 指向最后采用的编辑稿，没有采用时优先保留完成的比较结果，否则保留失败尝试。

不加词语黑名单、固定钩子、转场句式、时长硬限或“审稿意见全部清零”的要求。质量仍由真实生成的完整文稿判断。

本轮离线回归：`python -m pytest tests/test_video_*.py tests/test_recipe_audiences.py -q`，579 项通过。新增验证覆盖开场素材顺序、两条只读正文的观众评读、编辑候选事实修复、后续编辑从采用稿继续、改差后保留上一稿及调用次数上限。`compileall` 与 `git diff --check` 通过。

v13 从同一原报告完整自动生成，用时约 11 分钟。前两轮编辑被采用：从功能与条件清单转向“只换请求分配，为什么吞吐会变化”，增加了前缀缓存的具体解释，舍弃了与该主线混杂的预测延迟路由限制。第三轮又退回发布日期开场，比较选择保留第二轮稿件。正文未经人工修改，源报告与全部旧版本保持不变，来源复核通过。

示范 v7 与自动 v13 的只读对照交换了 A/B 顺序，两次都偏好自动稿，具体理由是开场和机制解释；输入只包含两篇完整口播与受众，不含“手工/自动”标签。比较记录为 `output/video/llm-d_v7_vs_automatic_v13_2026-10-24.json`，未进入生成输入。自动稿与完整尝试记录为 `llm-d_automatic_v13_2026-10-24.*`。这是单一题材、同一模型的编辑评读，不能据此宣称所有题材已稳定达到同一质量；开场密、结尾清单感仍需处理。

## 结构重写与局部润色（主编 v6）

v13 暴露了“为改一句衔接而重启整篇”的问题。主编现在用 `edit_mode` 和 `edit_reason` 区分 `rewrite` 与 `copyedit`：主线或选材有问题时重新创作；当前讲法成立、只是开场句过密或转场生硬时，交给文字编辑保留原稿的价值再打磨。判断来自具体收听障碍，不按问题数量、文稿长度或编辑轮次机械切换。

两种模式都经过相同的来源复核、具体事实修复和全文听感比较。局部润色只接收正文、画面标签、引用与事实编号，审计标签、内部备注和核验措辞不进入作者上下文；结构重写的作者继续不收旧稿。原稿和每次尝试都保留。

## 从失败候选继续寻找讲法（主编 v7）

放宽上述停止条件：候选被拒时保留较好的原稿，在剩余编辑预算内继续寻找更合适的讲法。下一轮策划接收前面尝试的角度、编辑范围、采用结果和具体比较理由，避免重走“日期开场、泛泛判断、结尾补新术语”的失败路径；这些只是实际案例，不是词语或结构禁令。
