# 网页截图与段落配图

标准出片／自动批次 → 冻结该版讲稿及事实来源 → Playwright 定位正文并记录元素位置 →
取得截图 → 本机 OCR 检查真实像素 → 已配置的视觉模型理解图片及匹配段落 →
AutoVideo `POST /api/creative-images` 上传 PNG → 注册 UUID → 随提交快照发送 `placements` 与 `focus` →
Remotion 展示整体、放大、标记重点并显示原讲稿解释。

自动路径在既有 render 后台工作线程的第一次提交前运行，无需用户获取图片或逐张确认。
找不到匹配画面、页面需登录／验证码／被遮挡、时间或模型预算耗尽时，记录原因并保留文字画面。
第五版快速混合出片与标准出片共用自动流程，图片到达后保留快速档位。纯文字快速模式、文学类文章和人工保存的配图（包括明确取消全部配图）跳过自动获取。

文稿页的「网页截图与段落配图」可从报告来源、段落引用中选择网址，也可填写公开产品、功能、价格或公告页。
支持 1440×900 首屏、完整网页、唯一匹配的元素和首屏矩形裁切。长页超过图片合同上限时要求缩小范围，
不会把整张长图悄悄裁掉。原 PNG、SHA-256、请求网址、跳转后网址、网页标题、抓取时间、视口、
元素选择器或裁切坐标保存在 `state/video_screenshots/<UUID>/`。

截图使用独立匿名浏览器上下文，不使用发布账号或用户浏览器的登录态。只访问公开 HTTP/HTTPS，
主页面、跳转和子资源均检查目标地址；阻止本机、内网、带凭证的网址及 WebSocket。
兼容将域名解析为 198.18/15 虚拟地址的代理，但必须另经公开 DNS 核验；不直接放行此网段的字面地址。

## 配图与版本

- 自动路径只使用该段可追溯的事实／引用来源，跳过未核实、推导及冲突事实；旧稿没有事实表时沿用该段引用。
- 可人工选择每张图对应的一段或多段讲稿，填写最多 80 字说明和参考／整体／细节／对比用途，人工选择优先。
- 最多 12 张图片，选择对象展示或动态拼贴，点击「确认并保存段落配图」。
- 对应关系绑定文稿版本和完整章节／段落哈希，不继承到改稿的新版本。新版本可以复用已存截图，重新选择段落。
- AutoVideo 使用原稿分句器，把段落位置展开为实际旁白分句；只向对应场景提供该段图片。
  没有配图的段落使用可信文字组件。引擎只执行上游的明确映射；图片理解在研究侧运行，不把引擎旧有顺序分配冒充语义匹配。
- 配图仅影响下一次制作；已经创建的 render 请求及旧视频保持原快照。标准配图请求沿用标准制作；
  快速混合出片保留 `production_mode: fast` 与 `information_cards`，并将图片安排到已指定的段落，其他段落仍可使用轻量卡片。
- 带位置的 AutoVideo 任务修改讲稿前需要重新确认配图；声音／倍速／配乐修订仍可复用已冻结内容。
- 截图先保存再登记。引擎暂不可用时保留本地图片和预览，可重新登记；切换引擎后重新登记并保存选择。

页面截图记录抓取当时的页面展示，不代表来源的事实已经核验。此路线不录屏、不接收 MP4 镜头素材，
不绕过付费、登录、验证码或 Cookie 弹窗。现有内容审校和定稿闸门继续生效。

## 定位、理解与镜头

- 固定 DOM 代码提取可见候选区域和元素矩形，核对产品、版本、金额、币种、套餐、周期／单位及输入输出条件。
  功能／公告页保留滚动后的视口供镜头展示整体，价格页保留完整相关区域及计费条件。
- 截图设备缩放比固定为 1。裁切截图将视口坐标减去截图原点；矩形再按实际图片尺寸归一化到 0–1000。
  原图、滚动偏移、截图范围、DOM 文字与矩形、来源、时间及 SHA-256 全部保留。
- V3 本机 Apple Vision OCR 检查空白、遮挡、真实文字、价格及视频缩放后的可读性。OCR 无法代表完整视觉语义理解。
- 显式配置 `visual_ai` 后，Qwen3-VL 接收实际 PNG 及最多 8 个既有段落，返回图片描述、匹配段落 ID 和聚焦建议。
  校验 JSON、段落 ID 和坐标；`vision_required: true` 时，超时／模型不可用／不对应当前段落均回退文字。
  视觉建议作为审计记录，镜头优先使用准确测量的 DOM 矩形，不直接执行模型生成的代码、网址或裁切操作。
  本机使用 `yanying-vision:8b` 别名，复用 `qwen3-vl:8b-instruct-q4_K_M` 的6.2GB权重，专用上下文8K。
  构建命令：`ollama create yanying-vision:8b -f config/visual_models/Qwen3VL8B.Modelfile`。
  初测发现8B会把矛盾价格解释为“可以修正讲稿”，因此模型的接受结果仍须通过确定性金额／条件检查；模型不拥有改稿权限。
- 自动材料的 `focus:{width,height,regions:[{x1,y1,x2,y2,label,style}]}` 与图片 UUID、段落位置一起冻结。
  最多 3 个矩形，样式为 `box/circle/underline/highlight`。尺寸必须与登记后的图片一致。
- Remotion 现有运行版本为 4.0.535；本轮采用确定性的 SVG 标记及镜头变换，不新增适配包或升级依赖。
  同一张图可整体→局部放大→框选／圈选→原讲稿解释；长段落可顺序聚焦，短段落减少焦点数量以留出阅读时间。
  动态拼贴恰好两张图时等宽并列，三张图沿用已有拼贴。无 `focus` 的图片沿用原展示方式。

## 恢复与预算

原始 render `request` 保留初始意图；准备完成后单独冻结 `submission_request` 并保存哈希。
已发送或结果未知的提交只恢复跟踪，不重新采图或重复创建任务。截图先保存，再登记；重启可继续登记已有 PNG。
同一任务按图片哈希去重，不同任务复用有时效的已核对 PNG，但重新登记到当前引擎。
价格缓存最多 15 分钟；改稿重新计算段落位置，启用必需视觉检查后还要求当前段落的理解哈希一致。

页数、图片数、重试、模型调用与累计时间均有限额；单项调用受自身超时限制，进程退出后已持久化的消耗继续计入。
默认配置未开启该功能的环境保持原行为。当前机器的实际开启状态及验收见
[实施计划](auto-visual-materials-plan.md) 和 [验收记录](acceptance/automatic-visuals-20261025/README.md)。

## 安装

可移植的视觉模型与自动配图配置见 [配置示例](../config/visual_models/visual-materials.example.yaml)。
将字段合并到本机配置，保留已有设置；模型权重和本机完整配置不随代码提交。

使用研究服务自己的 Python 环境安装 `requirements.txt`。Playwright 优先使用其 Chromium，
没有安装时尝试已有 Google Chrome。需要时运行：

```sh
python -m playwright install chromium
```

实现使用 [Playwright 官方截图 API](https://playwright.dev/python/docs/screenshots)。

## 研究 API（原有登录、角色及 CSRF 规则）

| 方法与路径（前缀 `/api/video`） | 行为 |
| --- | --- |
| `GET /scripts/{id}/screenshots?version=N` | 来源候选、讲稿段落、已存截图、该版本的配图选择；viewer 可读 |
| `POST /scripts/{id}/screenshots` | `{version,url,mode,selector?,clip?}`，抓取并尝试登记；editor 可写 |
| `POST /scripts/{id}/screenshots/{asset}/register?version=N` | 从保留的 PNG 重新登记到当前引擎 |
| `GET /scripts/{id}/screenshots/{asset}/image` | 经归属和 SHA-256 校验的本地预览 |
| `PUT /scripts/{id}/image-materials` | `{version,form,materials:[{screenshot_id,caption,role,placements}]}`；仅当前已完成版本可写 |

`placements` 为 `{chapter_index,paragraph_index}` 数组，均从 0 开始。
这里的章节和段落与提交 AutoVideo 的 `chapters` 一致，空段落和空章节不会占位。
引擎仅接受已登记的图片 UUID，来源 URL 只作记录，不触发图片下载。
