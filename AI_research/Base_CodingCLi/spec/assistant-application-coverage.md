# 助手全应用能力清单

目标：用户描述业务目标，助手定位实际对象、执行应用操作、跟踪结果并处理未完成项。先保证整体业务覆盖，再优化局部创作体验。

## 能力与验证范围

| 业务 | 操作入口 | 当前验证方式 |
| --- | --- | --- |
| 全局运营总览 | 助手顶部「全局总览」、`query_operations_overview` | 跨矩阵待处理 / 进行中 / 当前账号可发布；完整统计与分页、归属与版本、部分失败及权限回归；真实数据和助手查询见 [2026-10-26 验收](acceptance/assistant-overview-20261026.md) |
| 矩阵、任务与继承 | `query_matrices`、`manage_matrix`、`configure_production` | 原生 API 回归；已有真实助手矩阵验收 |
| 现有矩阵运营概览 | `inspect_matrix_operations` | 按矩阵聚合来源、任务、周期、继承与平台候选；平台队列注明范围；软件矩阵真实验收 |
| 成套配置 | `configure_matrix_task` | 同一次操作连接矩阵、共享来源、研究任务和配方；返回准确生产配置 key；本轮真实助手复验 |
| 信息源 | `query_sources`、`manage_source`；信息源页新增/修改/删除 | 版本冲突、备份、直接/标签引用、同地址不同 ID 回归；本轮真实登记与引用 |
| 研究、报告、情报轮次与行动 | 原研究/报告/轮次/行动工具 | 沿用已有原生执行器、权限与逐次运行验收 |
| 配方、正文、版本与视频 | 配方/公共部件操作目录、视频工具 | 沿用原 workflow；已有真实报告重写、版本比较和 MP4 验收 |
| 周期批量启停、矩阵批量设置 | 应用批次 `schedules`、`matrix_render` | 隔离状态回归，验证固定范围、角色、继承和成功项保留；不修改用户真实周期用于测试 |
| 研究后自动出片 | 应用批次 `produce` | 一次研究可供多套生产配置使用；原生写稿 + 持久视频 workflow；本轮真实研究到成片验收 |
| 单条/批量投稿与恢复 | 发布工具、`manage_publishing resume`、应用批次 `publish` | 原生发布接口；候选分页、部分失败、原任务恢复与重复保护回归。小红书两条真实投稿均确认公开、回写文稿；真实助手 resume 返回已有结果，无新增上传 |
| 保存平台发布草稿 | `save_publishing_draft` | 原生保存与重新校验；保留未修改字段和正文；小红书两条现有成片真实保存，用户确认后启动固定范围发布批次 |
| 本地视频路径投稿 | `publish_local_video` | MP4/MOV/M4V 导入及已有成片复用；四个平台原生队列、重复保护与账号隔离回归；真实助手完成本地路径导入、保存小红书草稿及浏览器播放，未公开投稿，见 [2026-10-27 验收](acceptance/local-video-publishing-20261027.md) |
| 发布数据与评论 | 平台操作目录中的 analytics、sync、comments 接口 | B站现有业务接口可发现和调用；其他平台按自身能力，不宣称都有数据能力 |
| 系统配置、账号、诊断与维护 | 原管理工具、受保护卡片 | 沿用已有角色、版本冲突、回退及服务维护验收 |
| 跨对话跟进 | 工作区、任务中心、应用批次 | 进度直接读业务状态；不通过模型轮询或重放修改 |

“已有接口”“回归通过”和“真实平台验收”分别记录。能力清单在助手顶部「能做什么」提供可填入的场景示例；点击示例不会发送请求。

后续[现有矩阵运营验收](acceptance/assistant-operations-cycle-20261025.md)使用已有 software 周任务，从一次新研究自动写成 v2 并出片；另按用户明确确认，将两条已有成片的已保存草稿提交到小红书账号「安托尼啦」。该轮的平台逐项回执和实际公开状态单独记录，不扩大为全部平台真实验收。

[发布恢复追加验收](acceptance/assistant-publishing-recovery-20261025.md)补齐上述公开结果与异常恢复。请求任务卡、批次和平台页显示可操作的恢复原因；处理后继续原投稿，保留成功项、版本和发布包。后台可只读跟踪等待处理批次的已有投稿，不重新派发。

## 批次行为

- 准备时按 `scope.ids`、`scope.jobs`、`scope.matrices` 或明确的 `all=true` 冻结完整范围。`produce` 的 ids 是生产配置 key；jobs 是完整研究任务路径。未知范围报错，不扩大到全部。
- 准备不会运行研究或上传。已有明确执行指令时，助手准备后直接启动，不增加一次确认。
- 进度保存在现有 `assistant.db`。批次只衔接业务步骤，研究、写稿、视频和上传仍使用原生执行器。
- 后台调用在进程内部携带原账号 ID，每次执行检查账号及角色；不保存登录 cookie、密码或 API key。HTTP 请求不能伪造内部身份。
- 成功步骤保留；已知失败可继续，视频重试沿用原文稿及 workflow，投稿重试沿用原任务。提交后遇到断线或服务中断、结果未知时暂停核对，不盲目重投。
- 研究锁定具体运行 ID。报告页面使用 output 相对路径，视频流程使用 workspace 相对路径，显式转换；下游派发前核对本次报告指纹和配置版本。
- 停止批次只停止后续派发，已提交工作继续由原执行器管理并跟踪；取消具体运行或投稿使用原生入口。

## 尚未宣称完成的部分

平台登录、验证码及秘密录入仍需本人在原页面处理。平台公开状态依据可用回执；没有可靠回执时明确待核对。任意自然语言目标和每个平台的全部组合尚未穷尽实测，本清单不是“所有场景均无人值守”的承诺。
