# 选题池（Video topics）

状态：已实现（2026-10-20，架构第 2 期，见 `spec/video-architecture.md`）。

## 为什么

以前选题不存表，每次请求都重新解析两种报告：快讯发现、情报轮次第 07 步。来源名 `flash`、`opportunities` 写死在 6 处代码里。这带来三个问题：

- 新建的 Job 进不了选题池；
- 选题不能手动添加；
- 文稿页手填的题目不进选题池。

## 规则

1. **选题来源 = 在 YAML 里声明了 `topics:` 的 Job。** 数量不限，代码里不写任何来源名。
2. **报告按对账扫描导入 `topics` 表**（`state/video.db`）。Job 的报告无论是谁跑出来的，都会在下次读选题时导入：
   - 周期调度、命令行、情报轮次、控制台都算；
   - 大小或修改时间变了的报告重新解析；上次导入失败的报告也会重读，使解析修复可以接回原报告；
   - 第一次扫描会把已有的报告全部导入。
3. **旧报告保留原选题 id，新报告绑定独立版本。** 旧报告仍用 `<报告日期>/<编号>`，旧的 `_1.md`、`_2.md` 用 `@1`、`@2`；新完成的报告有 `.report.json` 清单，使用 `<报告日期>/<编号>@r<版本摘要>`，即使外部编辑替换同一路径也不会复用旧题。页面编号仍是 F1、F2 等。原文稿、批次和“不写”记录保留，不改写其中冻结的选题。
4. **手动添加的选题**来源为 `manual`，id 为 `manual/<n>`。文稿页手填标题建稿时，也会先存成手动选题。

## 在 Job 里声明

```yaml
output: "output/topic_discovery/{date}_{name}.md"   # 必须带 {date}；{name} 和引擎写文件时一样替换
topics:
  alias: deep_topics   # 可选：配方和批次用的短名；不写就用 Job 路径（如 monitoring/深度选题）
  format: items        # flash | opportunities | items
  prefix: D            # 选题编号 D1、D2…；1–3 个大写字母，各来源不同。items 必须写且不能是 F、C；
                       # flash、opportunities 不写就是 F、C，第二个同格式的来源要写自己的（如 MF）
  refresh: true        # 可选：允许自动流水线在当天没有报告时启动这个 Job（会花搜索额度）
```

三种 `format`：

| format | 报告长什么样 | 编号 |
|---|---|---|
| `flash` | `### 1.1 标题` 或 `### 1. 标题` 加 `- **字段**：值`，末尾有来源清单；只有标题没有条目字段的导读、来源清单不算选题 | F1、F2…（写了 prefix 就是 MF1、MF2…） |
| `opportunities` | `### C1. 标题` 加 `- **字段**：值` | C1、C2…（照报告里写的；写了 prefix 就把 C 换成它） |
| `items` | 任意 `###` 标题后面跟 `- **字段**：值`；没有字段的标题（概述、小节标题）不算选题 | prefix + 序号 |

声明有错时，这个来源照样列出来、标明原因，但不导入。常见错误：

- format 不认识；
- `items` 没写 prefix，或用了 F / C；
- prefix 不是 1–3 个大写字母；
- 两个来源重名，或编号前缀相同。选题编号是「日期/编号」，前缀相同的两个来源同一天会互相覆盖。已经导入过报告的那个照常工作，只拦新来的，错误里会让它加 prefix；两个都没导入过（或都导入过）就两个都拦；
- output 里没有 `{date}`；
- 写了不认识的字段。

同一天跑了两次时，引擎始终保留旧文件，追加 `_1`、`_2` 文件及版本清单，选题浏览列表只展示那天最新的一份，不混入前一份剩余条目。自动流程逐份扫描启用之后的全部报告，而非只看最新文件；批次以 `spec.report` 和 `report_identity` 绑定具体版本，直接按该文件读取候选及备选。指定报告没有条目时不回退其他文件；已被外部替换的版本只结束原领取回执，让新版本另行领取。已有批次的 ITEMS、文稿和渲染继续使用已保存内容。

每日推荐是独立的候选入口，在矩阵主题工作台配置 `config/theme_production/<matrix>.yaml` 后，按矩阵每日补充上限与栏目日/周配额领取当天推荐。领取写入同一自动制作批次并占位，重启不再领取同一题。快讯默认每日 1 条、教程每周 2 条，其他栏目每周 1 条；北京时间周一重置周配额。技术失败保留原任务及配额，重复跳过释放配额。报告 `auto:N` 仍按每份报告执行，两个入口共用矩阵排重与制作并发。

现在声明了来源的 Job：

- `monitoring/ai_flash_discovery`：`alias: flash`，`refresh: true`。
- `practical_ai_intelligence/07_product_content_opportunities`：`alias: opportunities`。它是情报轮次的一步，不允许自动流水线单独启动。

新模板 `jobs/_templates/_topic_discovery.yaml`（「选题发现」）建出来的 Job 默认带 `topics: {format: items, prefix: D}`，不定时，也不会被自动流水线启动。

## 配方怎么用

配方的 `topic.sources` 写来源名（alias 或 Job 路径），也可以写 `manual`。它只决定自动流水线从哪挑题，以及选题页默认显示哪个来源；手动建稿不受影响。

写了一个没有 Job 声明的名字时，配方照样能保存，但会在两处提示：

- 配方接口（列表和校验）返回 `warnings`；
- 选题页标红。

## 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/video/topics/browser` | 选题页首屏快照：配方、数量统计、来源、默认来源最新一期选题；共用一次来源扫描与配方读取 |
| GET | `/api/video/topics/sources` | 所有来源：Job、格式、最新一期、报告条数、声明错误、最新一期读不出选题的原因；外加 `manual` |
| GET | `/api/video/topics?source=&round=` | 某来源某一期的选题（默认最新一期）；`source=manual` 列出所有手动添加的选题 |
| POST | `/api/video/topics` | 手动添加：`{title, angle, audience, fields}` |
| GET/POST | `/api/video/topics/discovery?source=` | 只对 `refresh: true` 的来源：查看状态，或现在就跑它的 Job |

## 界面

选题页先选格子（配方），再在来源标签之间切换：配方声明的来源，加上「手动添加」。盘点和对比这两种格子没有「手动添加」标签。

- 「手动添加选题」：填标题、角度、受众。
- 允许刷新的来源有「生成今天的选题」按钮，确认时显示上次用了几次搜索。
- 其他来源给出它的 Job 链接。
- 首屏一次读取主数据，生成任务的状态单独刷新，不阻挡选题显示。刷新时保留上次列表；切换来源或日期会取消旧请求，返回原来源时重新读取最新选题。新报告仍在每次读取时对账导入，不用整页缓存遮住更新。

排重归档与技术失败分别展示。接口为明确带 `content_archive` 的归档记录补充 `selection_skip`（`duplicate` 或 `exhausted`、原因、关联原稿的当前进度与可用成片），兼容历史 `FAILED` 记录，不改写文稿或渲染。选题页的「已跳过」不计入「异常」或「待写」，重复项可直接查看已有文稿、播放已有成片；真正的写稿、渲染故障继续显示失败。

自动选题、备选切换及尚未开写的批次会排除已确认重复的原候选。记忆依据归档中的明确关联，匹配同矩阵的候选 ID、原始标题及内容字段（受众差异不影响）；覆盖原稿须仍有效，并遵循近 30 天记忆。模型超时等普通失败、没有关联原稿的素材不足不进入该记忆。报告内容有更新、原稿失败或未发布原稿归档、用户恢复跳过记录后，仍允许重新选择。同日新报告使用独立 ID，不被前一份报告的跳过记录覆盖。

## 没做的

- 选题不能编辑。导入的选题跟着报告走，报告重写后会整体替换；文稿里存的是建稿时的那一份。
- 早期 23 份第 07 步报告是旧格式，读不出选题（以前也读不出）。来源列表只报告最新一期的问题。
