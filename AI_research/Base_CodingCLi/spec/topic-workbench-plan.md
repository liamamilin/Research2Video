# 主题发现与主题驱动开发计划

建立日期：2026-10-27。目标：保留素材驱动，在每个矩阵增加每日主题推荐和自主命题入口，选题后复用研究、文稿与视频制作能力。

## 产品约定

- 三个入口并存：素材报告里的选题、每日平台主题推荐、自己输入主题。
- 主题归属矩阵与业务栏目；ChatGPT 使用 T01–T09，其他矩阵使用各自栏目，尚无栏目的矩阵提供领域研究入口。
- 每类每日最多推荐一条，先逐类寻找候选，再做跨类和历史去重；没有合适候选的类别允许留空。
- 推荐只说明本次实际取得的信号；可获取的播放、点赞等指标展示原值和时间，未取得时按公开内容线索展示。
- 推荐不启动视频。用户选择或输入主题后，可以研究写稿，也可以继续自动制作；不发布。
- 主题研究读取当前资料与相关历史材料，不受日常抓取的“仅新增变化”限制；原来的日常任务不变。
- 研究材料包括问题、具体场景、说明与原始材料、页面及画面建议；让同一个作者得到完整输入，减少反复摘要。
- 默认每日 09:00（Asia/Shanghai），可暂停或更改时间；使用项目 ScheduleStore 和独立调度器。

## 阶段一：主题任务基础

状态：基础功能已完成，回归与实际运行通过。

1. 新增持久主题记录：矩阵、栏目、标题、受众、角度、补充材料、发现线索、来源方式、关联文稿。
2. 推荐、手动主题共用数据结构；支持保留、忽略、编辑、研究和制作。
3. 建立可恢复状态和并发领取，避免重复点击启动两次。
4. 新增矩阵主题 API 与权限检查；保留原有 topic_store 与报告入口。

验收：两个矩阵互不串题；同一主题不会重复启动；浏览者只读，编辑者可操作。

## 阶段二：指定主题研究

状态：已完成；示例主题已生成研究报告与完整文稿。

1. 根据栏目目标、受众和补充资料形成研究任务。
2. 先明确子问题，读取栏目相关来源，再定向搜索和阅读页面；资料足够后生成研究报告。
3. 主题研究与视频表现配方分开：直接写已有报告的配方，也能接收新主题研究的结果。
4. 保存问题、场景、操作与可见结果、决策依据、原始材料和画面材料。
5. 复用现有研究日志、报告存档、文稿版本及矩阵制作设置。

验收例：《ChatGPT 免费版用了一个月，应该升级 Plus 吗？》从输入题目到研究报告、完整文稿；表达围绕用户决策，保持原有素材任务行为。

## 阶段三：分类主题发现

状态：已完成；ChatGPT 实采 72 条线索，推荐 8 个不同分类的主题。

1. 每个矩阵一份发现配置，分类从业务栏目动态读取，避免固定套用 ChatGPT 分类。
2. 逐类生成公开平台检索，收集标题、摘要、链接、时间及可取得的互动指标。
3. 将具体内容归纳为观众问题，使用实际来源线索解释推荐理由。
4. 每类最多一条；同义题、跨类重复和近期已推荐/制作的相近题去重。
5. 保存每次发现的成功、空类、来源失败和实际用量，失败时保留上次推荐。

验收：模拟候选全部集中一个分类时，结果仍不会用同类条目占满推荐；实际跑一轮 ChatGPT 分类发现。

## 阶段四：每日运行

状态：已完成；11 个内容矩阵已登记每日计划。

1. 发现任务作为普通 Job 接入现有独立调度器，执行时动态读取最新栏目。
2. 为现有活跃内容矩阵登记每日计划；新矩阵可在主题页开启。
3. 主题页显示开关、时间、下一次执行和上次结果，支持立即刷新。
4. 测试使用隔离目录并模拟调度器安装；生产注册与测试分开。

验收：同一矩阵同一天重复运行不会重复推荐；调度器离线可看到状态；暂停不会删除历史主题。

## 阶段五：矩阵主题工作台

状态：已完成；桌面和 390px 窄屏已实际操作验收，截图保存在验收目录。

1. 矩阵新增“主题推荐”工作区，原有栏目与素材来源入口保留。
2. 展示分类推荐卡：标题、目标观众、推荐理由、原始信号、来源和采集时间。
3. 支持日期/栏目筛选、自己写主题、改角度、忽略、研究写稿和研究制作。
4. 展示关联研究、文稿、成片与错误恢复入口。

验收：桌面与窄屏可操作；网络错误能重试；生成中的按钮和状态准确；不要求逐步人工确认。

## 开发与兼容策略

新主题存储、发现服务与 UI 尽量放在独立文件；对正在共同修改的研究引擎与视频工作流只增加小接口。所有来源、主题和生成尝试保留。首次版本不替换日常报告，不修改原有自动制作计划，不增加内容审核或人工确认步骤。

## 下一阶段：先验证真实指标与运行可行性

2026-10-27，根据用户对成本和正式 workflow 可行性的反馈调整。B站指标适配器、缓存与工作台排序已经开发，但不能把开发时单独读取的视频样本当作正式采集验收。新增版本尚未执行付费发现全链路验收。

检查上轮正式发现保存的 72 条线索：12 条为 B站视频链接，去重后 10 个视频，仅分布在轮换到 B站的三个分类；不少搜索结果较旧，原始计数均为空。现有发现可用作分类选题线索，不能据此声称发现了当天各分类热门主题。B站具体视频详情计数可用，原生搜索仍未打通；外部搜索索引与平台热度发现存在功能差距。

本阶段的新增代码保持原检索频次：每个分类每轮一个平台、一个关键词查询，不额外为每类同时搜索多个平台。只对实际找到的视频补充计数并排序，缓存跨矩阵复用。原有每日计划尚未根据本次讨论调整，不把“已登记调度”作为成本和推荐效果得到验证的依据。

后续候选方案按以下顺序验证，尚未视为已交付能力：

1. 复用已采集链接，补指标并记录覆盖率、发布时间和失败比例；这可以不增加搜索或模型调用。
2. 为单个 ChatGPT 矩阵建立较小的候选池，比较固定关键词、关注账号清单和用户补充链接的实际覆盖；取得足够候选再逐类推荐，缺类保留为空。
3. 将发现新作品与刷新已有计数分开：较低频发现新候选，较高频读取候选池计数；仅在材料有新增或用户需要新角度时重新调用模型。
4. 以可用推荐数、用户选用数和每次实际调用量评估试点；只有具备发布、获客及成交数据后才能判断收益是否覆盖成本。

是否改成单矩阵试点、更新候选的频率和候选来源，需要结合这轮讨论确定；当前不扩大矩阵、检索频次或付费服务依赖。

## 参考题库与题型出题

2026-10-27，根据用户提出的“先从网络梳理、分类，之后参照题型推荐；用过不删、不重推，结构继续参考”接入。

- `theme_library` 长期保留按矩阵、栏目分类的原始参考题及可复用题型。平台发现取得的全部线索入库，未入选推荐的线索也保留。
- ChatGPT 起始库整理 9 类题型并关联真实公开样本；与既有 72 条线索合并后为 80 个分类参考题。
- “帮我出一批题”读取矩阵定位、栏目目标、参考题型与例题，接受选填方向，也支持指定栏目或沿用题型。每批每类最多一条，不必填满所有类别。
- 一批一次模型生成，不额外执行搜索；每类最多取 3 个例题和 3 种题型，近期历史进入上下文，发布时仍查询完整历史作去重。
- 每条新题保留核心问题、主题标识、来源例题、题型及讲述结构。使用相同题型可以提出不同具体问题；标题、核心问题相近或主题标识相同的候选不重复入库。
- 开始研究制作时记录使用；也支持“标记已用”记录在别处制作的题目。已用记录没有时间过期，不从待选列表重复展示，使用记录可分页查看并进入原文稿与成片。
- 沿用旧手动主题时可以参考同类题型。原先已经关联文稿的主题会补齐使用时间，不删除旧数据。
- 保留平台发现和自主命题，新增出题目前按需触发，不修改已有 11 个矩阵的每日计划。

实际验收：ChatGPT 生成一批 6 个不同分类的新题；1 次模型请求、0 次搜索，输入 8075、输出 6604、合计 14679 tokens。生产界面已读取参考库与已有 Plus 主题的使用记录。详见 [参考库验收](acceptance/theme-library-20261027/README.md)。
