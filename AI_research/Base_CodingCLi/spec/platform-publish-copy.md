# 平台发布文案适配

通用发布包继续保留完整来源、章节与说明。B 站、抖音、快手、小红书和视频号的文案预览经过同一个 `core/video/platform_publish.py`；视频号保持此前暂缓状态，不重新开放入口。

## 默认适配

`core/video/publish.py` 在原有字段之外提供结构化 `content`：完整摘要或首段、作者署名、数字口径、待确定事项和章节。没有专门摘要时使用完整首段，避免截取第一句话后丢失下一句的限定。

平台适配先安排标题、话题和分隔符，计算简介剩余额度。保留完整摘要／首段、作者署名、数字口径和待确定事项；按已有引用优先顺序放入完整来源网址，再尝试放入完整章节块。部分平台略留字数余量。全文与全部出处始终在原发布包中可查看。

- 不截断句子、型号或网址，不生成短链接，不搬运到首评，不调用模型或外部服务。
- 超长标题仅在完整首分句可独立表达、没有数字结论和被省掉的条件时，建议使用该分句。无法保守处理时保留并提示编辑。
- 手动编辑的正文视为完整块，不能删除后段限定。只有能逐字匹配原发布包的纯来源尾部，才允许重新安排来源位置；尾部存在未知文字就完整保留。
- 来源全部无法放入时明确提示，不能伪称“完整来源已公开”。完整发布包与出处仅在本地可见，平台简介只显示其中实际放入的主要来源。

## 编辑、应用与版本

无已存草稿时，平台编辑器默认展示适配后的文案。有草稿时优先显示手动内容，不自动覆盖。

「一键适配」调用只读预览接口，展示修改前后文本、主要来源数量、完整出处和剩余问题。「应用」将修改前后文案在同一事务中留存后更新本平台草稿。预览之后继续手动编辑，会使应用按钮失效，必须重新预览。

「查看手动版本」按文稿版本、平台和当前账号查询最近 30 条保存记录。恢复时仍先保留当前内容；较早记录不会删除。已入投稿队列或已经发布的目标不能重新保存草稿，仍走原有状态与重复投稿保护。

草稿保存只检查类型、字段白名单和存储上限，允许超长或未填完的内容。实际投稿继续严格校验标题、简介、话题、合并文本和评论。用户点击适配、保存或恢复都不会创建投稿／评论任务。

## 计数与首评

`core/social/publish_text.py` 与前端 `lib/publish-text.ts` 按当前 uploader 的真实拼接方式计算换行、`#` 和空格。快手合计包含标题、简介和话题；抖音合计为简介和话题；B 站与小红书按已接入的独立字段规则检查。上限属于当前接入规则，不声称覆盖平台所有客户端。

首评额度独立计算，快手／小红书按原适配器的 UTF-16 上限计数。空白常用模板在新预览中默认关闭，不修改账号原设置；已有草稿的显式勾选仍保留，区域内提示填写或本次关闭。首评不承接放不下的来源链接。

## API

沿用编辑权限、身份认证和写接口 CSRF 保护。

- `POST /api/video/distributions/{platform}/adapt`：`render_id`、当前 `payload`，只返回建议与预检结果。
- `PUT /api/video/distributions/{platform}/draft`：原接口新增可选 `previous_payload`，同一事务保留原稿与新稿。
- `GET /api/video/distributions/{platform}/history/{render_id}`：当前账号与文稿版本的已保存记录。

原发布预览返回 `adaptation`，包括建议、原文、完整出处、计数及当前限制。既有发布队列、待核对任务和发布记录保持原投稿时的文案，不进行后台改写。

真实样本及验收证据见 `spec/acceptance/publish-copy-20261025/`。
