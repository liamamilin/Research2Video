# 可调整的矩阵周期生产

## 目标与边界

排期决定何时研究，研究窗口决定本期用哪些时间范围的素材，生产策略决定哪些自动入口进入出片队列。三者通过版本化的期次连接，不在代码中判断 AI、ChatGPT 或某个星期。现有受管调度存储仍是排期的唯一来源；更改 cron 后，按相邻计划槽位计算的研究窗口自动随周期改变。显式滚动时长作为可选覆盖，允许近两天、十四天等研究范围，不需要重写适配器。

生产策略采用独立、经过结构校验的 YAML：管理哪些矩阵、默认窗口计算方式、日常素材积累周期与保留范围、自动生产每日数量、主题推荐是否自动出片。现有栏目、配方、声音和视频形式继续使用。配置修订只影响未来期次；已开始的期次保留快照。

## 四个阶段

1. **策略与期次。** 以计划槽位而非实际开跑时间为截止点；排队、重试共享持久化期次快照。手动研究通过相同窗口解析器取用当前生效排期，显式指定时间范围可覆盖默认。移除十四份 Job 中固定的一天／七天业务判断，保留旧配置兼容。策略校验和变更保持可审阅。
2. **素材积累。** 日常采集只读来源和归档正文，不调用研究／写稿模型，也不创建视频任务。按来源和内容版本记录首次观察、最后观察、原始发布日期与读取结果；周更从归档和当前源合并取材。公告、变更日志和长期说明分流；失败日期可见，冷启动无法回溯的来源如实记录覆盖范围。缓存保留时间可调整。
3. **统一自动准入。** 报告自动写稿、主题自动接续、自动批次经过同一持久化准入计数。按逻辑期次防止重复占位，重试不重复计数；超出每日预算的工作等待后续机会，保留已有工作。手动指令单独标识，入口仍可用。既有历史批次迁移前已接纳的工作继续运行。
4. **迁移与验收。** AI／ChatGPT 使用当前凌晨排期，默认窗口随计划槽位变化，自动预算四期。检查改周期、排队延迟、重试跨天、并发准入、冷启动、部分来源失败和期次上下文传到写稿。通过隔离本地服务与模拟提供商验证，不为验收启动正式研究或公开发布。生产启用与代码完成分别记录。

## 数据归属

| 数据 | 唯一来源 | 冻结时间 |
|---|---|---|
| 执行规则／时区／版本／到期时刻 | 受管 schedules／schedule_runs | 入队 |
| 研究窗口、Job 及策略修订 | 期次快照 | 新执行器入队时冻结；滚动升级兼容槽位在 worker 首次执行前冻结，重试复用 |
| 素材原文及版本 | 素材归档 | 每次读取 |
| 自动生产占位 | 自动生产准入账本 | 开始生产前原子占位 |
| 本期研究底稿与原始素材 | 报告原生保存链路 | 研究完成 |
| 写稿、出片请求、发布任务 | 现有各模块 | 沿用现有冻结边界 |

## 扩展原则

窗口解析与调度表达式解耦。当前 cron 可表达的日、周、月和自定义规则走同一个槽位解析器；将来加入其他周期类型时，只扩展槽位提供者，不改采集和视频模块。时间范围不等于所有资料必须近期首次发表，当前说明和解释案例作为背景保留。素材预算与每日出片数量分开控制。

不回写旧报告或已受理出片，不暂停／清空队列来通过验收，不增加事实核查或人工确认关卡。本地数据库、执行回执和历史输出不随源码提交；可复用的策略配置与源码一起维护。

### 已实现的边界

- `production_policy` 解析可继承及按任务覆盖的窗口；`schedule_store` 持久化期次，已冻结期次在编辑计划后仍可领取和重试。明确暂停／删除继续遵守原有停止行为。Job 文件名及已有绑定不迁移；显示名称不再写死“每日／每周”。
- `material_collection` 只做公开来源读取；`material_archive` 独立维护原文版本与观察时间。正常研究的 `source_supply` 合并归档、展示读取缺口，再沿原有素材底稿进入作者。日常归档不是全网历史镜像，尚未积累的日期和上游接口条数限制仍是实际边界。
- `video.production_admission` 使用独立持久账本，并发生产共用每天额度；`video_autopilot` 在写稿前占位，`video_executor` 在自动出片入口复用，额外主题接续遵守策略开关。明确手动操作不占自动额度，既有受理任务不因升级被搁置。
- 期次通过报告元数据进入整期 `episode.issue`，排队跨日时展示期次日期。既有视频、旁白、配方、声音、速度及渲染组件未修改。
- 管理员策略 API 使用修订号防止覆盖更新，备份旧 YAML；常规排期继续使用受管调度，页面增加下期研究范围。
