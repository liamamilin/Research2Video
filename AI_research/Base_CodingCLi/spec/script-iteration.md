# 文稿详情页的迭代入口

2026-10-24。目标是缩短“发现问题 → 调整生成方式 → 重跑 → 比较结果”的循环。

## 页面与行为

- 顶部并列显示当前文稿版本、定稿情况和视频使用的文稿版本。新稿和旧视频不一致时明确提示，已有成片不因重写自动更新。
- “重新生成文稿”沿用报告，走现有写稿与审校流程并生成新版本；新稿需重新定稿后出片。
- “重新生成视频”使用定稿版本，走原出片服务；历史视图、写稿/制作进行中和未定稿时不能误提交。
- “编辑”修改单篇；“调整配方与提示词”跳到当前使用的配方。“调整生成方式与相关设置”提供受众、调研模板、共用写稿、出片、包装、矩阵视频配置和研究任务的实际入口，仅列出存在的引用。管理员可进入全局模型设置。
- 每个入口说明影响范围及改完该重跑什么。研究模板不会因为重新写稿而重新调研；共用部件会影响所有引用它的配方。
- 配置入口携带原文稿标识，配置页提供“返回文稿，继续迭代”。配方和部件切换保留上下文；有未保存修改时阻止直接跳走。
- 发布区优先展示视频与字幕，技术文件和日志折叠。旧文稿、审校、成片、发布记录均保留。

配置上下文仅在读取详情时解析，不修改稿件。受众和时长变体链接到对应基础配方，共用部件按真实类别路由，不把内部 `part` 标记当成编辑器类别。缺失配方或无效制作配置不妨碍读取已有稿件。对保存时记录的配方展开摘要与当前配置做比较，提示配置变化；这不表示模型输出质量已验收。

## 验收

- 前端完整测试 379 项通过；相关 API、配方和读取性能回归 158 项，新配置上下文回归 4 项通过。TypeScript/Vite 构建、ESLint、Python 编译及 `git diff --check` 通过。
- 使用现有登录会话浏览实际报告速览详情，核对顶部操作、版本关系和技术文件折叠；直达 `packaging/common` 并返回原文稿。
- 在编辑器仅输入未保存的测试内容，返回时正确出现保护提示，再选择放弃测试修改。没有保存配置，没有调用真实写稿或出片；重跑请求与状态限制由离线交互测试覆盖。
