`note` 记录优先级与采集范围。任务显式选择来源，ChatGPT Learn 放在教程与场景任务的前面；低优先级材料无需每个任务都读取。

## 采集行为

- `page:https://...`：读取正文，按标题拆段，保留日期和链接。每段正文最多 6,000 字符，相关链接另附。
- `catalog:https://...`：提取目录中的文章、课程、案例、视频或节目链接与公开简介。保留 YouTube 视频和播客单集的查询参数，不将不同视频去重成一条。
- `search:查询`：执行预先配置的公开内容检索。`site:` 限制会再次按返回 URL 的域名和路径过滤。计入本次报告的搜索用量。
- 现有 `rss:` 继续处理新闻和状态订阅。

网页直接读取失败时，尝试现有 Exa Contents 配置读取**同一个 URL**，请求新抓取（`maxAgeHours: 0`）。没有可用配置或仍读不到时，记录该源失败。部分来源失败时使用本次成功取得的材料，并在材料里注明缺失；全部失败时沿用现有终止行为。

新任务的 `search: false` 表示模型不自主搜索补充。声明为 `search:` 的信息源仍会在模型调用前执行其固定查询，和网页正文读取一样属于采集阶段。

## 页面历史

T09 使用 `source_history: true`，只将相对上次成功报告新增、修改的条目发送给模型。初次抓取标记为基线；没有变化时说明暂无新题材。T06、T07、T08 使用 `source_history: context`，展示变化，同时保留当前页面内容供套餐比较、常青教程和问题排查使用。

历史保存到工作区的 `state/source_history/<任务哈希>/`，包含版本文件和 `latest.json`。保存范围是本次采集限额内的条目和正文摘录。报告成功保存后才推进基线，失败或取消不会吞掉待处理变化。不同任务各自保存基线。

## 首次运行与范围

新矩阵沿用新增任务的手动运行方式，生产配置 `auto: 0`。没有创建后台周期、自动出片或发布计划。可在矩阵的「周期」页配置所需频率。

公开视频和播客目前采集目录、标题、简介及搜索索引文本，未下载视频、提取字幕或转写音频。中文平台读取公开索引内容，未采集完整评论。Reddit 不依赖 RSS，检索未命中会显示无条目。Google Trends 目前只是公开检索线索，不提供趋势时间序列或实际搜索量。

实测类材料区分来源已有测试与待实测方案，后续需要实际操作才能形成自己的实测结果。付款指导区分付款工具、服务支持地区、网页与应用内订阅，以及 ChatGPT 与 API 账单。
