链路管理接入评估｜2026-11-18

结论：可以接入，建议先开放只读链路页，再逐步开放写入和运行。不能直接覆盖隔离版的 55 文件补丁。正式产品继续由现有托管调度、研究 worker、视频后台负责执行；链路页聚合配置、提交操作、追踪同一批产物。本轮未写正式代码、数据或调度，未执行上线或回退。

证据范围
对照当前正式工作树、Git HEAD 0cc6e0cc、隔离版 implementation-manifest.json / implementation.patch，并以 SQLite mode=ro 读取项目正式 state。55 个文件中，44 个与隔离基线相同，10 个是新增，1 个已分叉（AutoVideo g2/workspace.py）；仍须在准备合入时重新核对基线和各运行进程加载的版本。隔离版两条链路、四份视频已实际完成；正式候选尚未演练。以下数量是盘点快照，不是上线时的锁定数量。

一、合入清单与必须补齐的差异

1. 首批：链路列表、向导、详情、运行详情及跨页上下文（Chains.tsx、ChainContext、use-chain-scope、App/Layout/Sidebar）；按正式 FastAPI 生命周期注册只读 /api/chains 路由。在链路服务中按既有 Job 和输出读取配置及继承值。页面和后端操作分别设开关，支持隐藏、只读和指定链路可写。关联筛选是导航范围，不能作为权限检查。
2. 写入批次：合入创建、修改、暂停、删除预览及共享引用规则；新旧入口调用同一服务。保留正式 Jobs / 矩阵 / 栏目 / 配方 / 信息源 / 产出 / 周期已有权限和错误行为。隔离版 chains.transaction() 用进程内 RLock，出错时回写全量 YAML、整库回填 schedules.db；这挡不住独立 dispatcher 和 CLI，可能撤销无关任务刚记下的执行结果。正式版采用影响对象的版本检查、跨进程协调及可恢复的变更台账；调度只按对象、计划 ID 和版本操作，失败只撤销本次变更。验证进程崩溃及外部 worker 同时推进的场景。
3. 运行批次：链路“运行”走正式研究入口和共享 Job 锁；以本次运行回执中的报告版本关联已有视频批次，或通过正式统一入口创建批次。用正式 report_identity、期次和输出去重规则做幂等交接；启动意图与下游 ID 可恢复，不能以 Job 当前的 last_output 猜本次报告。按研究任务、批次项目和渲染 ID 精确取消／重试。继续沿用冻结期次、自动额度、补跑、重试、并发限制以及正式发布策略。后台只保留一个视频推进入口：正式 video_autopilot.tick() 已遍历所有 RUNNING 批次并有跨进程锁，不能再从链路 runner 直接调 _tick_run。正式 fire_auto() 也会自动消费新报告，要与手动启动统一认领，避免一份报告生成两批。周期仍用 managed_scheduler（保留独立 dispatcher、系统计划和 gateway 唤醒）；链路运行状态通过关联现有调度回执和视频批次得到，不重定义“研究计划成功”的含义。快讯热点加跑、旧 cron、矩阵 daily/catchup、视频周计划保持原归属。
4. 独立修复：报告归属及外接盘相对路径是链路报告可见性的依赖；应从正式研究产出元数据（含独立定时 worker）写入索引，历史关联分批预演。视频 DB 的增量索引、SQLite 忙时继续跟踪同一远端渲染、发布查询缩小范围、已定稿轮询优化分别立补丁，测旧数据、历史兼容、启动锁时间与发布功能。画面 ID 反馈、字幕依赖和渲染路径是独立的 AutoVideo 修复，按正式环境复现和验收后再决定。g2/workspace.py 的正式工作树已支持 g2/runs，隔离版本删除了该兼容并增加 g3/data 根链接支持，应按实际布局合并，不能覆盖整文件。
5. 不带入：隔离启动器、替换 FastAPI lifespan、独立端口、测试账号、假调度心跳、发布拦截、盘目录映射、恢复试验脚本、样例配置及试验库。正式 lifespan 已承担报告扫描/监听、渲染恢复、视频存储、归档、热点等职责，不能替换。Flash 测试用的声音改动不覆盖正式设置。

二、线上存量怎么接入

盘点：config/production 有 72 个 YAML、涉及 62 个配置里的 Job 标识（不等于 62 条全部健康、启用的链路）。schedules.db 有 64 个未删除计划（19 开启、45 暂停）及 6,389 条历史执行。video.db 有 766 份文稿、632 个版本、660 条渲染（539 已完成）、398 个视频批次、539 条发布记录；reports.db 有 749 条索引记录。

现有链路采用原地挂接：以规范 Job ID 加输出 ID 建只读映射，保留矩阵、栏目、配方、启停和继承。现有链路的合成标识可由规范 Job ID 稳定生成；共享、移除输出或重命名需要持久化标识和历史归属，防止刷新后重复生成链路。无视频输出的共享链路仍然是有效引用；只有研究、没有链路关系的 Job 留在 Jobs；异常引用和未能唯一归属的项列出来核对，不自动补绑或启用。新增链路才为新对象分配 ID，先检查所有输出、配方、栏目、主题别名等命名空间，避免覆盖旧对象。

Flash 样本：monitoring/ai_flash_discovery，13 个显式来源，保留 ai_media 补充采集；7 个输出中 flash_each、flash_daily 开启。现有受管计划是 30 7,18 * * *，Asia/Shanghai、跳过逾期、最多重试 2 次、版本 13；研究窗口继承 previous_slot。按原输出 ID 查到 240 份历史文稿。盘点时索引有 42 份 flash/ 报告都标成目录名 flash；视频库另有 31 个已登记到该 Job 的不同报告路径。两者不能按数量硬对齐：须按规范路径和报告生产记录逐条验证，多来源冲突时不自动修。只修索引归属，可重建或按记录逆向恢复，保留收藏、标签、已读、评分和正文路径。

只新增需要的链路元数据和运行关联台账；原研究 YAML、计划 ID／版本／启停／下一次时间、已冻结期次、文稿版本、渲染 ID、远端任务 ID、发布与文件路径均沿用。老的调度记录和视频批次能关联则按原 ID 展示，无法证明属于同一完整链路时仍作为原有历史展示，不补造运行记录。research_updates 及四份验收成片留在隔离环境；正式启用同主题时先查来源库已有项，再经向导创建，以正式设置生成正式记录。已有数据无需搬库或复制 MP4。

三、其他 Tab 的影响

- 信息源：关联态显示显式来源、标签成员、补充覆盖和影响范围，退出关联恢复全部。改全局来源仍作用于所有引用方；只从本链路移除引用不等于停用源。
- Jobs、矩阵、栏目、配方、产出：沿用原数据和编辑入口。修改后新页反映同一份配置；移除输出同步栏目和单条／合集配对。删除前检查共享 Job、策略引用和外部触发，旧入口同样检查。既有生产 Job 首批只允许解绑或归档链路入口，底层删除单独开放，不能仅以新台账判断在跑与否。
- 周期调度：关联态显示现有受管计划和执行记录；全局页保留系统任务、旧 cron、其他计划和恢复入口。编辑保持时区、补跑策略、重试和已冻结期次；暂停研究与暂停出片分开。共享研究暂停对所有消费方生效。删除涉及调度的动作须明示并核对与旧入口权限等价。
- 报告、文稿、视频看板、成片与发布：关联态用真实报告 Job、批次和输出关系筛选；统计、下拉选项、批量操作都使用相同范围，详情链接保留链路上下文。已发布、草稿、账号、发布队列及原 URL 沿用；链路开关不能隐式创建、释放或重复提交发布任务。
- 平台、设置等保留全局含义。链路 scope 请求未完成或失败时显示加载/重试；已切换链路不能沿用上条链路的数据。

具体待修：隔离版 HomeBoard.tsx、VideoScripts.tsx、PublishQueue.tsx 用了类似 A && !matrix || row.matrix === matrix 的条件，选中矩阵时可绕过 A（链路范围）。应改为链路与矩阵条件同时成立，并用「同矩阵不同链路」及关联退出做回归。隔离版手工周期实测只证明试验 worker 可用；还需要在正式 worker 入口验证冻结窗口、线上队列、权限及跨进程行为。

四、分批启用与回退

预演：新鲜正式快照放独立目录，校验 config/jobs、SQLite 备份和外接盘文件映射；记录 Job→计划→输出→报告→视频 ID 映射、所有触发者、下次执行时间、开关、发布游标和在途 ID。使用正式 worker 入口验证手动与自然定时、Web 重启/退出、两种触发重合、报告写出后崩溃、渲染已收到但回执未落库、共享写入冲突和未授权访问。要求报告只由一个批次认领、无额外自动发布、无丢失历史、两次执行前后各 Tab 一致。备份恢复需先在副本演练，包含同窗口写入的新数据保留。

启用顺序：先只读核对 Flash 和一个不同结构的正式链路；再给一条新链路开放创建和手动运行，核对发布规则；然后选 Flash 小范围开写入，观察至少完整两个自然计划槽位与一次失败恢复，最后才扩大。变更期开关和异常回执要能单独核对；任何重复生产、漏跑、错误归属、越界写入或意外发布都应暂停扩展，进入回退。

回退顺序：
1. 关链路写入/提交开关和本次新增的入口触发，保留旧调度和读详情。已经由正式 worker 接管的研究、视频、上传按原 ID 排空，或逐项请求停止并确认结果；出现重复时只冻结受影响项，保留原有效任务，不全局取消。继续对未确认的远端渲染或发布按原 ID／平台回执对账，不重新提交。
2. 只读 UI 问题：隐藏 Tab／还原前端和 API 入口。执行问题：确认没有待接续的孤立意图，再使用受管维护入口切回前版；把链路台账待处理项也纳入重启门禁。数据库增量对象可以保留，不为了回代码删除它们；独立调度进程如需更新，先确认进程确已换版，网关和 AutoVideo 无本轮变更无需跟着重启。
3. 配置问题：按变更台账对受影响 YAML、计划 ID 和启停状态逐项做带版本检查的逆向改动；恢复触发前对账已完成槽位，避免补跑。保留启用后新增的报告、视频、发布和新配置，可单独暂停新链路。正式 schedules.db、video.db、发布库不得用旧快照整库覆盖作为日常回退。仅库损坏等灾备情况，在停写后做一致性恢复并补齐本次上线后的增量。
4. 现有 scripts/backup_state.sh 默认只备份部分数据库和系统配置，不覆盖本轮全量范围。上线前要补齐 SQLite 在线备份及清单：video、调度、发布/平台及相关策略账本、链路台账、报告索引和元数据；另保全受影响的 config/jobs、已有触发配置及外接盘产物清单。回退后检查下一槽位、原始产物可打开、发布回执不重复，记录处理结果。
