# 多矩阵参考库出题

分类与题型计划见 [长任务计划](theme-catalog-expansion-plan.md)，实际运行见 [验收记录](acceptance/theme-catalogs-20261028/README.md)。

## 主题分类与制作栏目

`config/theme_categories/<matrix>.yaml` 定义观众问题、讲述方向、检索关键词与可复用的生产绑定。未配置独立分类的矩阵继续从 `content_columns` 读取。已有 ChatGPT 九分类保持原配置。

主题分类不增加日报、周报或自动视频任务。选择一个主题后，研究按分类的问题与参考线索展开；文稿上下文使用所选分类的受众、承诺与讲述方向，同时继承原 production 绑定的配音、画面、倍速和包装。教育使用现有通用主题研究路径。

## 默认方式与联网补充

`theme_discovery.configuration` 缺省为 `mode: ideas`，十一份现有内容矩阵配置均设为参考库出题。已有计划 ID、时间、开关和平台选择继续保留。每日任务从持久参考库抽取分类例题与格式，一次模型请求生成一批问题，不调用搜索。

点击“联网补充参考”继续运行平台发现；在参考库出题模式下使用独立的 `topic_platform/<matrix>` Job，保存找到的线索并生成补充推荐，不更改每日推荐方式。补充检索优先使用主题分类自己的关键词。设置中仍可以主动选择每日联网发现。

每类每批最多一题，旧参考内容用于借鉴问题和讲述方式。动态类没有当前变化材料时可以留空。已推荐和已用问题继续由现有矩阵完整历史去重，反馈继续影响题型偏好。

## 旧记录兼容

API 的 `categories` 只列当前推荐分类；`legacy_categories` 提供已被独立分类替代的原栏目。旧主题、例题、题型、反馈与使用历史均保留。旧主题仍可研究制作，指定旧题型仍可出题；默认批次使用当前分类。

工作台用两套分类共同显示历史标签与筛选，参考库新增分类筛选。新建主题和默认出题选择当前分类，选中旧题型时允许沿用其原分类。清除旧题型后恢复当前分类选择。

## 模型输出与实际用量

已经有可用题型时只返回题型 ID，不重复输出题型大纲；理由和角度保持简短。模型输出上限尊重系统配置，最高 16,384 tokens，为共享输出与内部推理预算的模型保留完整返回多分类 JSON 的空间。这是请求上限，实际消耗仍按服务返回 usage 记录。

原始回答另存 `finish_reason`。返回被截断时保留失败尝试和实际用量，不加入不完整的主题，也不自动追加一次模型调用。用户重试创建新尝试，成功的每日批次则复用，记录零新增请求。
