# 信息源供给 · 逐矩阵推广长任务

开始：2026-10-30。状态：完成开发、逐矩阵真实试采、11 个受管周期登记及正式后台加载。沿用已生产启用的 AI 信息供给能力。

## 顺序与范围

1. 科技、软件：分别完成来源方向、真实试采、新来源自动接入和原始材料交付验证，验证后再进入下一组。
2. 科学 → 公司 → 财经 → 产业 → 消费 → 历史 → 地理 → 文化：逐个验证和接入，保留每个矩阵自身的问题与知识材料方向。
3. ChatGPT 专项矩阵：仅接信息供给，不修改其九个研究任务和原聊天在研内容。

AI 五栏既有能力与周期保持。教育没有现有研究 Job，助手验收矩阵不属于内容生产范围，不为它们新建生产栏目。

## 每个矩阵的工作

- 新增独立 `config/source_supply/<matrix>.yaml` 与 `jobs/source_discovery/<matrix>.yaml`；原研究 YAML、生产绑定、配方、声音、速度、自动数量和周期保持。
- 动态栏目取材偏新增，专题、教程、机制和常青知识保留当前背景，避免把历史、地理与文化都变成新闻源汇总。
- 调用现有发现器完成有限搜索、实际入口发现、试采、栏目匹配和自动来源池接入；仅有可读材料且适合对应栏目时接入，不凑新增源数量。
- 原采集器读取声明来源与自动池，保留正文与更新材料，进入原报告素材快照和联合写稿路线。验证不启动研究视频、渲染或发布，也不推进正式研究的交付基线。
- 保存失败尝试和成功回执；先诊断明确问题再进行有界恢复，不重复整轮研究。
- 以原有受管调度登记错峰的每周发现计划，不重排原研究周期，不暂停或清空任务。只有全部真实工作空闲时才通过原维护入口加载必要源码。

## 验证与完成条件

1. 科技、软件先完成真实公开读取与自动接入的先行验证，其余矩阵按上表逐个完成。
2. 所有配置对应真实矩阵与现有 Job，单个 Job 不会误入其他领域池；初始固定源不被替换。
3. 真实材料保留具体例子、过程、数据与解释；预算、失败、无新材料和未到期周计划如实记录。
4. 信息源页能区分不同矩阵共享的自动来源，不能因为链接相同而发生行标识冲突。
5. 通过相关离线回归、配置检查与逐矩阵真实试采。保存每个矩阵的启用范围、自动池、下一次周期回执；实际加载后才计入生产完成。

## 协作边界

GitHub 提交按本轮文件清单收录新的来源配置、发现任务、采集与展示改进、对应测试及实施记录。所有开始时已有及过程中其他聊天新出现的未提交文件均保留，不混入本轮提交。不新增视频引擎、Agent、内容核查或人工确认关卡。完整进度与配置基线在 `state/validation/source-supply-rollout-20261030/`。

实施及真实采集结果见 [验收记录](acceptance/source-supply-rollout-20261030.md)。唯一受管维护 `82df2788ece54a0090eb141f5a5e6b92` 已完成；研究后台新实例 PID `77729`，8766/8775 健康，正式信息源页已确认全部 19 个新来源的矩阵与栏目归属。原研究周期、制品与其他聊天改动保留。
