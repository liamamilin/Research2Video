# 数据分析看板（设计，2026-10-22，还没做）

放在侧栏「高级」里，新增一个页面（和「选题」「文稿配方」并列）。要回答的是：**一条视频从选题到成片，花了多少搜索、多少 token、多少钱、多长时间；这些钱花得值不值。** 之后接入发布平台的数据，把「花了多少」和「得到了什么」放在一起看。

动手之前先定这份设计；搜索和 LLM 都按量收费，所以第一阶段先把「花了多少」记准。

## 1. 现在已经有的数据

| 数据 | 在哪里 | 粒度 | 备注 |
|---|---|---|---|
| Job 每次运行的 LLM 请求数、prompt/completion/total tokens、模型、**搜索次数**、耗时 | `state/history/*.jsonl`，`usage` 和 `duration_seconds` | 每次运行 | 搜索次数是 `SearchClient.calls`，只统计「有结果返回」的那次，失败的请求不记 |
| 按天、Job、模型、触发者汇总 | `StateManager.get_usage_summary`、`GET /api/usage` | 汇总 | 现有「预算」页用它；token 汇总有，搜索只按触发者汇总 |
| 估算花费 | `ai.pricing`（`input_per_1m`/`output_per_1m`） | 一个单价 | 只有一个模型的单价；换模型或用免费模型时失真（见 `spec/llm-providers.md`） |
| 矩阵每月搜索额度 | `monthly_searches`，`core/matrices.month_searches` | 矩阵 | 超额阻止运行；AI 矩阵目前没设上限 |
| 视频写稿、审校的 LLM 调用 | AREC 的 `LLMClient.usage`，记在文稿的步骤日志里（`core/video/steps.py`） | 每一步 | 没有汇总到按文稿看 |
| 出片的 LLM 调用 | AutoVideo 每条成片的 `model-cost.json`：每次调用的 prompt/completion/reasoning tokens、耗时、费用上限估算 | 每次调用 | 在成片目录里，AREC 没读 |
| 出片耗时 | 出片记录 `submitted_at`、`completed_at`、`attempt_count` | 每条成片 | |
| 批次进度 | 自动出片的批次和条目（`autopilot_*`） | 每条 | 看得出哪里挂起、重试几次 |
| 发布记录 | `publications`（平台、链接、发布日期、文稿和出片记录） | 每次发布 | 只有链接，没有播放数据；目前一条都没有 |

## 2. 缺口（做看板前要先补的记录）

1. **失败的搜索没有记录。** 10-21 那轮验证里 27 次成功运行有 24 次搜索数是 0，Parallel 额度用完、DuckDuckGo 兜底也没结果，运行仍然标「成功」，没有任何地方提醒。看板必须能看到：每个服务商的请求数、失败数、失败原因，以及「成功但 0 次搜索」的运行。
2. **搜索服务商没记。** 现在只有一个总数，不知道是 Parallel、Exa 还是 DuckDuckGo 答的，也就算不出钱。
3. **价格是一个数。** 需要按「服务商 + 模型」记单价，并且每条记录当时用的单价要存下来（价格会变，历史不能跟着变）。免费模型记 0，但要记下「它本来值多少」，才看得出换付费兜底后多花了多少。
4. **兜底的轨迹没记。** 哪次请求从主模型换到了兜底（402）、哪次搜索从 Parallel 换到了 DuckDuckGo，只在日志里。
5. **按文稿/按视频汇总不存在。** 一条视频的成本散在四处：研究 Job、写稿、审校、AutoVideo 出片。需要一个共同的归属键（文稿 id，研究 Job 的运行用报告 id 连起来）。
6. **耗时只有总数。** 研究、写稿、审校、等人定稿、排队、出片各占多久没有分开；「等人」的时间不能算进产出耗时。
7. **成本里没有 AutoVideo 的 Draw Things 和本地 TTS。** 这两样是本机算力，不花钱但占时间，先只记耗时。

## 3. 看板的内容

分四块，从上往下：

**A. 总览（可选时间范围、可选矩阵）**
- 本期花费（搜索 + LLM，分开显示，合计）、搜索次数、token 数、出片数、平均每条视频的成本。
- 与上一期对比。
- 额度条：矩阵每月搜索上限、预算护栏。

**B. 成本**
- 按服务商、按模型的搜索次数和 token（堆叠柱，按天）。
- 按环节：研究、写稿、审校、出片（成本在哪个环节）。
- 按矩阵、按栏目（配方）、按 Job 的排行；每条视频的成本分布。
- 兜底带来的额外花费：主模型出问题后多花了多少。

**C. 耗时**
- 一条视频从「选题进入批次」到「成片完成」的总时长，分环节堆叠（研究、写稿、审校、排队、出片），不含等人定稿的时间（单独显示）。
- 各环节的中位数和 90 分位；最慢的十条。
- 失败和重试：出片失败率、写稿失败率、重试次数；挂起的原因分布（余额、模型 404、格式错误）。

**D. 健康（先看这一块，最能防出错）**
- 「成功但 0 次搜索」的运行；各搜索服务商的失败率；各模型的 402/404/限流次数。
- 某个服务商连续失败时，在页面顶部提示（对应之前 Parallel 额度用完没人发现的事）。

## 4. 数据层设计

不再从各处临时拼，加一张**用量事件表**（`state/usage.db`，SQLite，只追加）：

| 字段 | 说明 |
|---|---|
| `id`、`ts` | |
| `kind` | `search` / `llm` / `render`（出片整体）/ `stage`（环节耗时） |
| `provider`、`model` | 服务商和模型；搜索时是搜索服务商 |
| `requests`、`failed`、`error_code` | 请求数、失败数、失败码 |
| `prompt_tokens`、`completion_tokens`、`reasoning_tokens` | LLM 才有 |
| `unit_price_in`、`unit_price_out`、`unit_price_search` | 记录当时用的单价 |
| `cost_usd`、`cost_list_usd` | 实际花费；按标价应花多少（免费模型 `cost_usd=0`、`cost_list_usd>0`） |
| `duration_s` | 耗时 |
| `job`、`run_ts` | 研究 Job 的哪次运行 |
| `script_id`、`render_id`、`batch_id`、`item_id` | 归属到哪条视频、哪个批次 |
| `matrix`、`column_key` | 归属的矩阵和栏目 |
| `fell_back_from` | 从哪个模型/服务商兜底过来 |

- 谁来写：`LLMClient`、`SearchClient` 每次请求后写一条（失败也写）；`video_render` 在出片完成时把 `model-cost.json` 的每次调用读进来；批次引擎写环节耗时。
- 历史回填：`state/history/*.jsonl` 和各成片的 `model-cost.json` 一次性导入，已知缺的字段（搜索服务商）留空，看板上标「早期数据，没有服务商」。
- 价格表放配置里（`config/pricing.yaml`：服务商 + 模型 → 输入/输出每百万 token、搜索每千次），可以在设置页改；写入事件时把单价抄进去。
- 「预算」页现在读 `history`，等事件表稳定后改读事件表，两边对得上再切。

## 5. 接入平台（后做）

- 现在的 `publications` 只有链接。要做的是从平台拿到**播放、完播率、点赞、收藏、评论、涨粉**，按发布后第 1/3/7/30 天各取一次，存成 `platform_stats`（`publication_id`、`taken_at`、各指标）。
- 有了它就可以看：每条视频的「成本 / 播放」；哪个栏目、哪种视频形式、哪个长度、哪个标题风格的效果好；写稿用的研究深度（搜索次数）和效果有没有关系；发布时间的影响。
- **还没查清的**：B 站（目前发布包按 B 站设计）有没有官方、可用的数据接口；是只能靠创作中心导出，还是要走开放平台申请；抖音、YouTube 是否也要接。接入前先查官方文档，再定是自动拉取还是手动导入 CSV（后者最省事，可以先做）。
- 没有平台数据之前，看板第一期只看「花了多少」。

## 6. 分期

1. **记录**：事件表、价格表、`SearchClient`/`LLMClient` 写事件（含失败和兜底）、历史回填。看板先只有 D「健康」和 B 的搜索与 token，因为这是现在最缺的。
2. **按视频汇总**：归属键打通，读出片的 `model-cost.json`，做 A、C 和每条视频的成本。
3. **页面完整**：B、C 的全部图表，价格表设置页，顶部提示。
4. **平台数据**：先手动导入，再看能不能自动拉取；做「成本 / 效果」。

## 7. 要你定的

- 钱的口径：是否把免费模型按标价算一份「本来该花多少」放在旁边？（设计里默认放）
- 搜索的单价从哪里来：各家套餐不同（Parallel、Exa 按量或订阅），要你给我现在的套餐价，或者先只看次数不看钱。
- 平台先接哪一个，数据先手动导入还是等接口。
- 看板给谁看：和「高级」其它页一样所有登录用户都能看，还是只给管理员。
- 历史数据保留多久；事件表要不要定期归档。
