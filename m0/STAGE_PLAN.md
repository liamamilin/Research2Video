# M0 阶段计划：冻结 V0.1 实测基线

**状态：执行完成，M0 结果为 PASS（基线冻结）** · **授权：用户于 2026-10-13 验收 G4、明确要求进入 M0，并要求采用其已提供的评分作为基线**

## 目标与假设

把 G4 Golden-3 的真实生成结果、Video IR v0.2、测试样例、依赖锁和已知风险固定为可复核的 MVP 基线。当前数据只支持描述这三类 10–20 秒本地样片，不外推到长视频、生产可靠性或商业分发。

## 范围

- 以 `0d52757`（G4 干净安装验证）为冻结代码基线，校验 Golden-3 的 MP4、运行报告、schema、样例和依赖锁哈希。
- 从 G4 成功与失败尝试记录端到端成功率、执行耗时、DeepSeek 费用保守上界及失败分类；明确估算与未计量成本。
- 登记 G4 已知缺陷、授权/隐私风险，以及人工评分的局限。
- 输出 `M0_BASELINE.md` 与审阅表；按用户明确要求采用其已提供的非盲评分作为主观质量基线，并如实披露，不将其描述为盲评。

## 不在本阶段

不修改生成器、UI、API、Video IR 或 provider；不调用模型、不重跑生成、不新增媒介；不启动 H1–H4。M0 完成后仍需单独授权才能启动 H1。

## 验收与退出标准

M0 基线必须列明样本量、成功和失败尝试、费用/耗时口径、三例真实 artifact 路径与哈希、schema/fixture/锁文件哈希、已知问题和未测项目。主观评分数据已记录并由用户核对；用户明确要求将这组已知非盲评分用于 M0 基线，因此 M0 可按基线冻结目标判为 `PASS`，但不得称为盲评或据此宣称产品达到 V0.1 可用质量。若评分数据缺失则报告 `PARTIAL` 及精确缺口。

## 验证与恢复点

- 只读检查现有 G4 manifest 和真实 artifact，不覆盖原运行目录。
- 重跑冻结版本的相关自动化测试，并记录实际命令和结果。
- 所有新增文件限于 M0 计划、基线报告与审阅材料；提交前核对 `git diff --check` 和工作区。
- 恢复点：提交 `0d52757`；已有 G4 artifacts 保留原路径，不移动、不重生成。
