## 现有链路中的接入位置

1. 研究端继续通过 web/services/video_render.py 向 AutoVideo 提交；AutoVideo 继续使用原有 POST /api/jobs、worker 和 attempt。
2. 已启用混合分镜的任务，在原来的章节规划请求中看到 code_demo 参数目录。已有原文包含代码或命令时可自动选用；其他内容继续选择截图、图表或现有组件。
3. g2/explanation.py 编译展示数据；information_motion 把讲稿短语连接到已有字幕词级时间；shot_director 把截图区域重点写入同一时间记录。
4. CodeDemo.tsx 只渲染文本、颜色与帧驱动高亮。代码作为展示数据，不执行。run_g2 将组件复制到每个任务的可信渲染器。
5. 连续代码步骤保留前面的短命令，只为当前讲解行生成新重点；原有故事回顾可以引用这些画面。
6. 既有画面编辑可以修改代码、标题和注释；声音或倍速修订后，重点按现有词级证据重新对齐。

标准与快速混合模式使用同一组件与编译器；矩阵沿用共同入口，无需复制组件选择逻辑。真实验收覆盖快速混合 API/worker 和共用渲染器原声重放；研究端共同入口由离线回归覆盖，未对每个矩阵分别调用付费模型。

## 条件性后续工作

原先列出的 14–22 个工作日方案是完整候选路线。按用户随后强调的“视频效果优先、避免不必要复杂”，本次执行收敛为上述截图、教程、同步与连续画面交付。初始方案副本保存在本次运行数据目录，下列能力未记为完成：

- 录屏与成品动画片段：当上游已有片段且确实需要播放时，再补最小材料登记、裁剪和末帧保持，复用现有 IR、配音与混合执行。
- 新的过程或数量演示：先由实际讲稿证明现有图表、流程图无法表达，再增加具体组件。
- 库存素材：仅在具体配方有实拍需求时接入必要的供应商适配器。

这些候选工作按真实成片收益决定是否实施。当前交付不依赖它们，也不增加通用插件框架、额外内容审查或人工确认流程。

## 验收与交付规则

- 渲染改动有真实 MP4、完整解码、日志和关键帧检查，组件探针不替代正常任务。
- 改画面对比优先复用同一讲稿和音频，记录自动规划、人工改动与额外模型调用。
- 覆盖组件合同、词级同步、上下文承接、编辑与声音修订；运行相关回归和 git diff --check。
- 新任务使用当前源码生成新尝试，历史成片不被重写。没有前端代码变化，无需重建前端静态包。
