# 第五版：快速模式自动混用重点画面

快速分章讲稿通过 `visual_storytelling: true` 选择 `hybrid_cards`。同一次原有章节分镜安排轻量说明、截图聚焦、价格、数据、流程与回顾；旁白仍使用上游原稿。没有新增素材选择界面或逐镜人工操作。

## 实现

- 普通说明／承接优先用静态卡片，Pillow 排版并按已编译旁白 beat 逐项展开；旧图标关键词回退不会自动将普通卡片变成动画。
- 截图、图表、价格变化、流程、关键概念与明确图标动作沿用可信 Remotion 组件。相邻同类画面合并成片段，只渲染动画实际使用的帧区间。
- 两种画面共用底图、标题、角标、页数与进度；动态画面沿用焦点、同图延续和进入时的短过渡。轻量卡片直接切页。
- 画面片段统一轨道时间基和颜色范围后拼接，再加入一条连续配音和字幕轨道，沿用原包装与配乐阶段。
- 现有图片登记 UUID、`placements` 和 `focus` 接入快速模式；研究端自动配图与保存的配图都会保持矩阵选择的快速档位。
- `visual_storytelling: false` 或省略时继续使用纯文字 `ffmpeg_cards`，历史冻结任务沿用原执行器。声音／倍速修订保持混合执行器，重画新时间线的卡片。
- 冻结的 MVP schema、动作注册表和原 MP4 素材边界没有变化。

真实模型、Kokoro 中文配音、隔离 FastAPI 任务库；网页图片使用 Playwright 已拍摄的本地演示页面和 DOM 区域。全部通过正常图片登记接口提交，没有人工修改模型返回的分镜。

## 修复与保留记录

首轮实片发现 FFmpeg 卡片的轨道时间基为 1/15360，Remotion 为 1/90000，直接拼接导致字幕与后续画面错位。生产合成器统一为 1/90000，并增加双时间基真实 MP4 回归。随后抽帧发现编码器的 full/limited 色域范围不同，卡片切回时底色变灰；现在统一为 BT.709 limited range，动态片段也显式选择 BT.709。原始尝试、失败日志和中间片保留在本机 `g3/data/acceptance-hybrid-cards-v5/`，中间重组保留在本验收目录忽略的运行树中。
