# 镜头同步与比较连续性修复

2026-10-28。公共实现、原声重放与最终真实 workflow 验收完成。目标是让对象、比较和结论及时帮助理解。

## 实现

- `information_motion.py` 分开匹配对象首次出现、再次强调和结论的短语，再按实际讲述时间排序；同一句可同时引入对象并强调它。已有字幕逐词对齐复用于视觉 beat，不增加模型阶段。
- `ShotDirector.tsx` 提前开始镜头移动，明确的语音时间点优先于建立画面、最短停留与收尾预留。结论是时间线中的一个事件，段首或段中的结论不会锁住后续镜头。
- `ScatterChart.tsx` 共用出现与强调的时间顺序；新的讲解对象可以替换旧焦点。已由比较步骤引入的对象不会因随后补齐显示而拆散比较，背景对象不按均分时间抢占重点。双对象比较保留两者位置。
- 对比卡在场景开始时提供两侧完整背景，讲到对象时再强调；相同图表或对比卡沿用既有 `scene_flow`，保持对象、位置及焦点连续。
- 短语定位容忍空格、大小写和句末标点差异，保留小数区别，避免实际存在的结论短语退回均分时间。

复用现有对象、颜色、Beat、分镜与可信组件；没有新 Agent、冻结 schema 改动、内容限制或额外审查环节。

## 自动 workflow

`workflow.py` 沿正常 `POST /api/jobs` 与 G3 worker，用已有作者完整的一章（508 字符、三段）生成新分镜、配音、字幕、快速混合内容片与包装片；正文和时间点没有人工修改，速度沿用 1.25。使用隔离任务状态，不注册公开投稿。

首次真实分镜在段首安排结论，暴露总结状态持续覆盖后续强调的问题；后续沿公共时间线修复。另一份真实分镜的结论短语改了句末标点，暴露均分时间兜底，随后修复短语定位。最终正常 workflow 为 `de452245-2c35-43c5-83cc-79c16d25a85d`，输出目录 `g3/data/acceptance-focus-sync-20261028/workflow-release/`。

最终内容片 68.1 秒、包装片 72.6 秒，1 次真实 DeepSeek 分镜请求，4 个自动画面，使用实际快速混合执行器。9 张实际画面已审看：28.1 秒在段首结论时已看到完整比较；30.5 秒突出 high 与 max；38.2 秒切换为 medium 与 max，比较组不被后续出现动作拆散；53 秒结尾两侧完整可读。原作者文字一致，模型输出、beat 和正文均没有人工改写。

内容片、包装片及两份原声重放均通过完整解码；生成进程保存的四份渲染源码与当前实现一致，验证期间公共源文件摘要未变。结构化证据见本目录 `verification.json`。本次仍观察到 49 秒讲输出速度时沿用成本／等待比较画面，保留为分镜选型的后续打磨点，不扩展本轮镜头同步修复。

`audit.ts` 输出各讲述时间点的可见对象、当前焦点、字幕与镜头；`verify.py` 验证原作者文本、真实模型调用、渲染器源码、MP4 解码及源文件冻结摘要。运行记录和媒体放在忽略的 `g3/data/acceptance-focus-sync-20261028/`，原始输入、失败请求与中间成片均保留。
