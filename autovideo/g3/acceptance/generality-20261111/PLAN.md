# 通用性收敛（2026-11-11）

范围：1920×1080 横屏信息视频中的比较、步骤/关系、素材展示及其旁白镜头。上游内容固定。此次检验的是给定结构到可读画面的泛化；不以此宣称模型可为任何题材生成好分镜。

## 实施前固定的要求

- 讲解焦点及理解它所需的关系在对应语音锚点可见；不由节点数量代替几何判断。
- 流程焦点文字目标不低于 30px（1080p 设计基准）；总览可用于定位，但不能把小字总览计作已完成细节讲解。
- 明确存在容量边界：给定语音时间与空间不足时记录该项未满足，不以裁切、遗漏对象或静默缩字标为通过。
- 镜头从语音锚点生成；快速连续提及时不丢对象，重复短语不能抢到对象介绍之前。
- 比较主体保持在场；素材目标区域不得被相机裁掉。无区域/字号元数据的图片不声称内部文字可读。
- 同一输入、任意跳帧得到相同结果；速度变化保持语义顺序。

## 验证纪律

先运行 corpus.py 固定 development.json、holdout.json 及哈希。调试期只读取 development；冻结实现后才运行 holdout。类别事先公开，留出实例由固定随机种子生成，属于工程留出验证，并非独立外部盲测。若依据留出失败修改实现，旧组改记为回归组，使用新种子另建留出组，保留所有结果。

结构维度：链、分支、汇聚、菱形、回路；3–8 节点（2 节点由单元测试覆盖），短/长/中英混合标签；短/长比较条目；横图、竖图、极宽图及边角区域；稀疏/密集语音事件、语速变换；重复短语和跨段定位。样例不引用当前几条视频的产品、坐标或标题。

开发组与留出组均做确定性结构检查；预先选定代表样例做真实视频与抽帧。合成测试材料标明用途。真实语音的同步另做抽样，不把静音几何样片当作旁白验收。

## 初始审计

| 规则 | 判断 | 本轮处理 |
| --- | --- | --- |
| 六节点以内固定全景 | 节点数不能代表必要上下文或可读性 | 优先替换 |
| 镜头合并对象超过四个则忽略新焦点 | 静默丢失语音对象 | 收敛到完整上下文与容量描述 |
| 强调短语只找全文第一次出现 | 重复词可能落在介绍之前 | 使用介绍之后的语义位置 |
| 机制主图固定尺度和配图位置 | 有边界的版式，不是通用布局器 | 保留边界，不为更多样例继续加坐标分支 |
| 字号、边距、节奏档位 | 可以是设计参数，但不应替代实际测量 | 保留并检验输出 |

阶段：冻结样例 → 基线测量 → 共用规则收敛 → 开发组验证 → 冻结并留出检验 → 实片/回归/结论。

首次语料生成的中英混合标签超过既有 30 字符合同，尚未修改生产代码时将该草稿归档至 corpus-invalid-draft。缩短生成器词表后重新冻结；未读取留出实例或根据渲染结果调参。
第二次合同预检发现比较卡上限为四项、每项 58 字符；归档第二稿并加入生成器合同验证。以上均发生在生产实现修改前。

开发期补充验收：分支/汇聚按实际邻接关系独立检查必要上下文，不仅检查实现自己选出的焦点；短场景的全景策略单列，不误报为丢对象。素材窗口按实际单图及双图聚焦尺寸检查。比较正文下限 28px、标题下限 30px、面板高度 560px；按实际字体测量选字号与间距，完整保留原文。
