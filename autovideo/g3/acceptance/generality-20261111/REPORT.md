# 通用性收敛结果：可复用能力与仍然存在的边界

本轮已经把节点数、字符数、前几个对象和短语第一次出现等代理规则，替换为可测量的排版与定位规则。**比较文字适配、语音对象保留、重复强调定位具备进一步复用的基础；流程关系图仍不是任意结构都能自动排好的通用能力。** 新留出组 52 个样例中，45 个满足本轮检查项，7 个流程结构保留为失败，未通过降低标准、删节点或逐例改坐标处理。

## 本轮具体改变

| 原有规则 / 缺陷 | 收敛后的共同规则 | 位置 |
| --- | --- | --- |
| 六节点以内固定全景 | 根据图形范围、实际有效字号和必要关系决定全景或局部重排 | `g1/renderer/src/Framing.ts`、`ShotDirector.tsx` |
| 流程只选择一个邻居，可能漏掉其他输入或分支 | 汇聚保留已讲来源，分支保留后续分支；选中子图完整保留内部连线 | `g2/shot_director.py`、`flow_layouts.py` |
| 快速连续焦点超过四个就丢弃后续对象 | 合并连续讲述的完整对象集合，并预生成对应关系布局 | `ShotDirector.tsx`、`flow_layouts.py` |
| 长比较文本靠字符数选字号，固定面板可能溢出 | 以浏览器字体测量进行换行，联合选择两侧字号、间距和行高，保留全部文字 | `g1/renderer/src/TextFit.ts`、`Root.tsx` |
| 强调总是抢到全文第一次重复短语 | 从当前对象介绍的实际结束位置之后寻找强调；兼容空格及标点差异 | `g2/visual_language.py` |
| 混合卡片写死缩放与偏移 | 将完整内容区域适配到嵌入窗口，避免新面板底部被裁 | `Root.tsx` 的 `FastCardsVideo` |

局部布局沿用已有离线 ELK 编译器，没有为某个产品、视频 ID、标题或测试编号添加分支，也没有引入新的模型调用。运行时合同保留兼容的可选 `layout_views`，旧 IR 仍能显示；旧 IR 不会自动获得新局部布局，需重新编排才能使用它。规划端节点上限与原运行时合同统一为 8，不把“8 个节点”当作可读性保证。

`Framing.ts` 收敛的是流程图和混合卡片的视口适配；素材镜头保留原有画布内平移约束，没有为了统一文件结构而重写所有相机。

## 固定的验证要求

原生横屏画面为 1920×1080。流程讲解锚点的节点文字目标至少 30px；比较正文至少 28px、侧标题至少 30px。文字和必要对象不能被裁切或静默丢弃；图的总览用于定位，不把其中的小字算作完成细节讲解。正文上下限、面板尺寸及边距属于设计参数，仍然需要在真实画面中验证。

混合卡片还会将内容区域缩放到嵌入窗口，原生字号标准不能直接当作其屏幕有效字号。本轮为它验证了完整画面适配和不裁切，**没有宣称它也通过全部 30px / 28px 字号要求**。

## 样例和留出纪律

三批各 52 例，共 156 例：每批包括 20 个流程、8 个素材区域、8 个比较、8 个密集/稀疏镜头时序、8 个跨段重复短语。流程覆盖链、分支、汇聚、菱形、回路，3–8 个节点，长短和中英混合标签；2 节点另有单元测试。素材覆盖横图、竖图、极宽图、方图及边角区域；时序包含不同持续时间、节奏档位和速度。

- 开发组 seed `2026111101`，原始留出组 seed `2026111102`，在实施前固定并保存哈希。
- 第一次冻结后才读取原留出组。它暴露了“局部已经包含全图却仍保留重复定位图”的问题。修复共同规则后，该组明确改为回归组。
- 第二次冻结后新生成 `holdout2`，seed `2026111103`，哈希 `51875d8bb2d2dd09afde163175d44d54bd96979b324138c6df437c4ef1525291`。没有依据这批结果继续调原生排版参数。
- 最终代码审阅另修正了提示 schema 中遗漏的五节点上限，以及混合卡片嵌入适配。`integration-addendum.json` 记录这两项，并检查原生渲染路径未变。它们不作为新留出组对模型规划或混合执行器的泛化证明。
- 两份最初不符合既有合同的语料草稿保留在 `corpus-invalid-draft*`；它们在修改生产实现前已弃用，没有混入正式样例。

这是同一结构生成器和有限词表的工程留出检验，**不是独立外部盲测，也不是跨题材创作质量或涨粉效果实验**。合成材料中的重复文本用于压力测试，不是成片文案建议。

## 测量结果

下表为“有失败的样例数 / 该类总数”，越低越好。

| 类别 | 开发组基线 | 开发组最终 | 新留出组最终 |
| --- | ---: | ---: | ---: |
| 比较文字完整适配 | 3 / 8 | 0 / 8 | 0 / 8 |
| 流程焦点可读、必要关系可见 | 9 / 20 | 6 / 20 | 7 / 20 |
| 素材区域未被裁切 | 0 / 8 | 0 / 8 | 0 / 8 |
| 密集提及未丢对象 | 1 / 8 | 0 / 8 | 0 / 8 |
| 重复强调位于正确对象介绍之后 | 8 / 8 | 0 / 8 | 0 / 8 |

基线时序结果最初另报了一个短场景全景，属于评估误报，已单列 `overview_only`，没有改实现去迎合错误判定。最终流程检查还增加了按原图邻接关系推导必要上下文，不能与较弱基线直接解释为同口径提升百分比。

新留出组流程 110 个讲解锚点中，102 个达到 30px，8 个未达到；13/20 个流程的全部锚点达标。必要上下文按当前讲述顺序定义为已讲入边来源，或首次展开的后续分支；不等价于每条边都已被旁白单独讲解。所有 7 个失败结构都保留了该定义下的节点和关系，失败原因是有效字号不足，范围约 19.2–25.1px。原留出组经过修正后仍有 9/20 个流程未全部达标，没有将它包装成一次通过。

完整的逐例结果在 [results](results)，冻结记录在 `freeze*.json`。材料区域通过只证明选中区域未被相机裁掉；没有图片内部文字大小元数据，不能据此声称截图小字都能读清。

## 结论和下一步边界

可以固化的能力是：给定文字的完整测量与适配、语音锚点的对象保留、重复短语的定位、关系子图重排与位置上下文。这些规则已经在不同结构中工作，不依赖当前几个产品视频。

尚未解决的是：**长标签的分支、汇聚及部分菱形图，现有单屏排版仍会不够大**，甚至 4 个节点也能失败。所以不能换成“五节点安全”或“长标签再加一个补丁”。本轮没有实现自动跨页分解，也没有证明这些图在物理上无法排好，只能证明当前排版器未达到要求。

下一轮若继续开发，应围绕同一组可验证约束改进文字换行宽度、布局候选与按讲述阶段分解，保留图的身份和关系，再用新结构检验。不得通过降低字号底线、删上下文或为这 7 个编号加特殊分支来“修绿”测试。本轮不扩展到任意视频类型、无布局的历史演示模板、模型分镜语义质量或爆款效果。
