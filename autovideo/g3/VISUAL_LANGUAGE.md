# 统一对象与动作 · 首版

目标是用一致的对象图标和少量有含义的动作，帮助观众跟上上游讲述。图标、动作和对应短语在现有分镜请求里一起选择，没有新增内容审查或人工选素材步骤。

## 已接入的画面

| 画面 | 对象表达 | 动作 |
| --- | --- | --- |
| 概念卡 | 每项对应一个 Lucide 图标，或沿用纯文字 | 发送、处理中、完成、中断 |
| 对比卡 | 两侧使用同一套对象图标 | 可在旁白短语处出现与强调 |
| 标准混合分镜中的流程图 | 2–5个节点，按讲述顺序排布，节点带图标 | 文件沿连线传递，节点处理与完成提示 |
| 原有独立流程图 | 共用对象词典与节点图标 | 延续原有旁白定位和关系强调 |

对象词典覆盖文件、文件夹、数据库、服务器、搜索、用户、团队、时间、费用、云端、代码、连接、图表、模型、计算、保护、世界、知识、自然、科学、建筑、设置和结果。没有适合对象时，可以继续使用纯文字。

## 自动接入

研映标准制作与矩阵的标准制作沿用 `visual_storytelling: true`，自动分镜可同时选择截图、图表、概念、对比和流程图。无需新增界面选项或逐段指定图标。快速卡片、聊天、图片轮播及文学专用呈现仍有各自入口，本版的对象组件覆盖范围见上表。

旧请求未提供视觉对象时继续有效；新编译的常规对象标签可按词典补齐图标，明确指定或明确留空的视觉选择优先。声音和倍速修订保留视觉数据，通过原有 beat 时间线同步。

概念、对比和流程 props 的运行时扩展为可选的 `visuals`：

```json
{"target":"line:0","icon":"file","action":"process","phrase":"处理文件时"}
```

`target` 对应卡片、对比侧或流程节点；`phrase` 定位到既有旁白。动作使用额外的普通 reveal beat，静态出现和动作起点可以分别安排。短语可跨配音分句，句内位置按字符比例估计，属于短语对齐。

## 渲染

- Lucide React 0.460.0，静态导入有限的对象图标，共用颜色和线宽。
- Remotion 与 `@remotion/lottie` 均为4.0.535，lottie-web为5.13.0，没有升级 Remotion。
- `ObjectMotions.ts`预制三个小型矢量片段：处理、完成、中断；由官方 Lottie 组件逐帧定位，播放一次后保持结束画面。发送位移、连线传递和 SVG 节点动作直接用 Remotion 当前帧计算。
- 图标与动画代码均来自仓库，模型只选择对象和动作标识。
- 原有冻结的组件 schema 和注册表保持不变；可选视觉字段由 `g1/visual_language.py`组合到运行时合同。

真实中文样片、关键帧及重放脚本见[本轮记录](acceptance/visual-language-20261026/README.md)。
