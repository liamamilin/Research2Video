# 快速制作、视频形式、视觉风格与音乐的统一接入设计

状态：2026-10-23 原始设计稿。统一制作计划与快速卡片阶段已按用户授权实施，当前合同和实际边界见 [实现说明](PRODUCTION_PLAN.md)；音乐与更多风格按后续阶段推进。下文保留设计时的全阶段目标和问题背景。

依据：[用户提供的创作资源与音乐讨论](https://chatgpt.com/s/cx_6adb19021aa08191932437a762133293)、[现有创作形式](CREATIVE_FORMS.md)、[快速样片及计时边界](acceptance/fast-card-prototype-20261023/README.md)。沿用 [多媒介架构](../17_CREATIVE_ARCHITECTURE_EVOLUTION.md) 与 [风格及声音系统](../18_VISUAL_LANGUAGE_AND_ASSET_SYSTEM.md) 的职责划分，不修改冻结的 Video IR v0.2。

## 1. 总体决定

AutoVideo 继续作为统一制作引擎。创作资源库统一浏览视频形式、音乐、包装和制作配方；快速版接入同一任务系统，成为执行能力之一。

| 维度 | 决定什么 | 所属模块与边界 |
| --- | --- | --- |
| 文稿配方 | 调研什么、讲什么、如何写稿和审校 | 研究系统管理；定稿出片时保留原文、来源及待核实状态 |
| 制作配方 | 某个题材推荐怎样组合形式、风格、声音和包装 | AutoVideo 管理组合与版本，引用下列资源，不复制其实现 |
| 视频形式 | 正文如何表达 | 形式库：信息卡片、动态排版、流程图、轮播、聊天体等 |
| 视觉风格 | 配色、字体、留白、图形、字幕和运动语言 | 创作资源库内的版本化风格定义；正文与包装共享基础设计参数 |
| 制作档位 | 本次允许的制作复杂度、资源需求和执行路线 | 快速、标准；具体 FFmpeg／Remotion 执行器由能力校验选择 |
| 声音 | 旁白、整段配乐、短提示音如何使用 | 旁白仍走现有 TTS；音乐模块产出资产；统一混音模块负责合成 |
| 包装 | 片头、片尾、角标、来源卡与提示音事件 | 继续使用现有包装库；提示音可引用音乐资产，不自行另做一套配乐 |

“快速”与“浅色”“聊天体”“轻音乐”属于不同维度。初期只有明确验收的组合可用，不能把快速档位宣传成所有形式都能快速制作。

风格可以推荐音乐情绪和包装方向，最终音乐选择与包装配置由制作计划确定。风格定义不能在执行时自行生成音乐、再添加片头或覆盖用户关闭的选项。

## 2. 一份制作计划，一条任务链路

```text
定稿及证据 + 制作配方引用 + 矩阵设置 + 本次选择
                         ↓
统一配置解析、能力与素材预检 → 冻结制作设置及来源
                         ↓
画面规划 / 旁白与对齐 / 图片与音乐资产准备
                         ↓
冻结实际选型、资产身份与完整时间线
                         ↓
正文执行器 + 包装组件 + 统一声音混合 → 最终导出
                         ↓
正文与成片 QA → 现有作品、下载与发布链路
```

配置解析是 AutoVideo 的共同入口。研究系统、网页、API 和 CLI 都提交同一份制作需求。研究系统继续负责定稿和矩阵调度，不再复制形式选型、主题与音乐解析规则。

创建任务时冻结配方、风格、包装定义及显式设置；需要读取正文、实测旁白后才能完成的 `auto` 选型，随后保存实际结果及原因。重试读取冻结结果，不因目录默认更新而换风格、换配乐。

这里统一的是责任与数据，不强制每一步启动独立进程。快速执行器可以把卡片、字幕、包装与最终音轨合在一次编码中，减少重复编码；仍须消费同一份包装定义和时间线，并分别提供正文及整片验收证据。

## 3. 配置继承与两种配方的衔接

建议按字段从低到高覆盖：

1. AutoVideo 通用默认。
2. AutoVideo 制作配方默认。
3. 研究系统文稿配方 `output` 中的显式制作覆盖。
4. 所属矩阵的显式覆盖。
5. 本次出片的显式选择。

素材、依赖、形式及预算限制是最后的校验条件，不是另一层会悄悄改值的默认。

文稿配方保留独立身份，例如 `research:topic_digest`；它引用 AutoVideo 制作配方的稳定 ID 和版本，并按需覆盖。不要根据显示名称相近自动匹配“专题速览”和“AI 快讯”。直接使用 AutoVideo 时跳过研究系统专有的层级。

研究系统已有共享 YAML 合并可以保留，但必须区分显式覆盖与程序补出的默认，不能把所有默认铺平成“本次手动选择”。最终记录每个有效值来自通用、制作配方、文稿配方、矩阵还是本次选择，页面能说明设置为何生效。

- 字段缺省才继承；显式 `false` 或关闭模式保持关闭。
- `auto` 表示允许在可执行候选中选择；显式指定形式不允许被偷偷替换。
- `null` 仅在字段合同明确定义时接受，不同时表示继承、关闭和自动。
- 嵌套对象逐字段合并；有序素材列表整体替换，避免重复配乐、重复图片。
- 旧 `package` 只经兼容适配转成统一包装计划；与新 `packaging` 同时提交继续拒绝。
- 旧任务不强行迁移或重新解析；新版本以父任务快照为起点，只更新指定项。

## 4. 当前应消除的重叠

| 当前事实 | 接入规则 |
| --- | --- |
| 研究系统 `web/services/video_render.create` 主要发送展开后的形式、声音与包装；尚未引用 AutoVideo `production_recipe` | 增加明确配方引用及覆盖来源，避免两边各维护一套题材制作默认 |
| API 的 `theme` 仅接受 `minimal_dark`，部分正文执行路径实际采用浅色，包装还有自己的 `accent` | 收拢到版本化风格参数；组件可有明确的局部覆盖，正文与包装从同一基础风格解析 |
| 快速样片写死了配色、片头、来源卡、片尾、提示音及时间偏移 | 去除样片中的业务默认；快速执行器只消费冻结计划，整条链路每个包装段落只出现一次 |
| 现有图片轮播仍通过 Remotion 渲染 | 不把“选择轮播”误认为自动启用了快速渲染；形式与执行器分别登记 |
| 音乐目录和推荐已存在，实际能力仍标记音乐生成、正文配乐不可用 | 分类、试听、可生成、可混音分别显示；不能把目录可见当作能力已完成 |
| 当前成片音轨直接与原旁白比较 | 加配乐时增加分轨与最终混音参考检查，保留原旁白质量检查与标准 |

上述为接入断点，不代表现有所有任务都会失败。尤其主题差异应通过新风格合同逐步整理，不能改变旧作品的渲染解释。

## 5. 时间线、布局与声音只有一个最终裁决者

完整时间线以帧为单位，包含片头、正文、来源卡、片尾及转场重叠规则。旁白、字幕、章节、配乐和提示音都引用该时间线。片头偏移只由时间线编译一次，各执行器不能自行再加偏移。

布局计划统一预留角标、字幕和来源提示的区域；风格控制外观，布局组件负责避让。全片字幕只生成和叠加一次。来源卡只使用提供的已登记来源，不能因包装要求自动编造来源；待核实标记随正文与作品记录保留。

声音分三种角色：旁白主轨、背景音乐、事件音效。包装模块登记“片头此处播放某提示音”，音乐模块提供带身份的声音资产，最终混音模块统一处理音量、循环接缝、淡入淡出和旁白期间压低音乐。同一资产可以复用，播放事件不得重复注册。

初期配乐建议优先导入或复用已生成音乐，供多条视频引用。ACE-Step 保留为独立音乐制作任务，产出完成后成为可引用资产；用户明确要求逐片生成新音乐时单独计入等待、推理和混音耗时。纯音乐任务不强制制造旁白、视频画面或视频包装。

对于未来外部视频素材自带的音轨，明确选择保留、静音或作为环境声使用，避免与主旁白重复。重型音乐模型与 TTS／图片模型按本机资源约束调度，不能默认同时占满内存。

音频验收分两层：保留未混音旁白与正文的对应检查；最终 MP4 与保存的参考混音比较，并检查削波、响度、接缝、静音和时长。不能为通过配乐视频而降低现有旁白相关性标准。技术指标和人工听审分别记录。

## 6. 快速执行器的初始能力边界

第一批只承诺已验收的信息卡片组合：文字、受控示意图或已有图片、逐句字幕、现有包装、旁白，以及音乐阶段完成后的已登记配乐。复杂逐元素动效、角色表演、分层动画不自动降级成卡片。

信息卡片需要稳定的形式身份；不能直接复用当前 `knowledge_cards` 并改变其历史含义。现有该模式还包含背景图与不同输入限制，命名与映射应在新合同中明确。

能力目录按“形式 × 风格版本 × 执行器版本 × 输出规格 × 所需素材”声明支持范围。显式选择的组合不兼容时，在提交前报告具体缺口；仅当请求允许自动选型或显式后备方案时，才选择兼容路线并记录原因。

样片的页面要点目前由人工编排。正式接入需要从定稿自动生成受控页面计划：每页引用原文段落、保留数字／单位／限定条件及来源状态，校验正文覆盖与可读性。不能把人工 `pages.json` 的存在当作自动文稿到卡片能力已完成。

样片的约 29 秒是页面内容及旧旁白准备好后的本机合成时间，约 35 秒包含 QA；不含页面编辑和新 TTS。正式性能记录分别报告排队、规划、配音、资产、渲染、包装／混音和验收，以及用户点击到可下载的总耗时。

## 7. 局部修改与批量性能

| 修改内容 | 应失效的产物 | 优先保留 |
| --- | --- | --- |
| 配乐或音乐音量 | 混音、最终封装及相关 QA | 定稿、旁白、对齐和画面；编码兼容时直接复制视频流 |
| 包装文案／开关／时长 | 包装、完整时间线、字幕／章节偏移和最终 QA | 定稿、旁白、正文画面计划；需要重编码的部分按后端能力决定 |
| 颜色、字体、字幕样式 | 受影响画面及包装、视觉 QA、最终导出 | 定稿、旁白及可复用音乐；不是所有图像素材都能跨风格复用 |
| 声音或语速 | 旁白、对齐、页面时长、混音及最终 QA | 未变的定稿、语义页面计划和兼容图片 |
| 正文事实或段落 | 受影响规划、旁白、时间线及其下游 | 经依赖校验未受影响的资产；不复用过期字幕或旧声音 |

缓存身份包括输入内容、计划、风格／组件／执行器版本、字体、素材哈希和输出规格；音乐还包括使用区间和混音参数。不能只用标题、配方 ID 或文件名作为缓存键。

复用现有任务 ID、幂等键、attempt、进度、取消、失败恢复、SHA 下载校验及原版保留。API 重试和下载失败都不能触发新音乐任务或再次生成整片。改变制作参数创建新版本，不复用原请求身份。

批量场景分别限制规划、TTS、重型素材生成和编码的并发。先测本机容量，再调整调度；全流程同时启动 20 个任务不等于吞吐更高。矩阵优先共享已审核的音乐与固定包装资产。

## 8. 实施顺序与验收

1. **先统一合同和解析。** 引入版本化制作设置、配置来源、能力目录和实际执行记录；现有执行器通过适配消费计划，旧请求默认行为保持。先做同一输入的解析一致性验证，再改变用户入口。
2. **再接快速卡片。** 完成自动页面计划及真实配音对齐，去除样片硬编码，接入现有 worker、包装、作品与下载；由用户或配方显式选择，先在一篇稿件和一个矩阵验证，再扩大使用。
3. **再接音乐使用与局部修订。** 按链接的第三阶段接入导入、资产引用、短音乐组件及统一混音；允许只换配乐生成新作品版本。ACE-Step 仍按链接的第四阶段单独试点，不成为快速档位的强制依赖。
4. **按能力扩展形式与风格。** 给轮播、聊天等形式逐项提供快速执行器；场景级混合执行器留到整片路线稳定后，避免提前增加大量组合。

每阶段都需要真实媒体与失败用例：

- 同一篇定稿分别走标准与快速路线；文字、数字、来源、待核实状态、字幕和章节不因档位改变而丢失。
- 至少两种风格验证正文、包装和字幕一致，包含长标题、长字幕与角标避让；只开放实际验收的组合。
- 无配乐、配乐加提示音、显式关闭音乐／包装、无来源、缺图片、缺音乐文件、版本不兼容和中断恢复均有预期结果。
- 验证实际 MP4 完整解码、音画时间、字幕可见性与旁白／混音质量；修订保留原版，换音乐不重做 TTS。
- 区分冷缓存全新生产、复用资产出片和只换音乐的耗时；最后用多题材的 20 条任务记录总批次耗时、吞吐、资源峰值、失败与恢复，未测之前不承诺批量分钟数。

上线保留旧执行路线作为回退入口；新能力默认不改变旧矩阵，先显式启用。关闭新路线不删除任何新旧作品、任务或失败证据。
