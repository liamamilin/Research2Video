# 09｜阶段实施路线

原则：先证明技术可行和质量潜力，再产品化；每阶段仅修改范围内的文件，附真实验收证据。

## G0｜技术与授权验证（不开发完整 App）

**目标：** 将关键假设变成能运行的最小技术样例。

工作项：安装/核实 Remotion + FFmpeg/ffprobe，创建 10–20 秒程序化解说样片；验证中文 TTS、音频时长获取、字幕与 Remotion 合成；测量 Mac 本地渲染情况；核实当前实际 Remotion 授权要求；记录三种路线初步成本/故障率。

产出：`G0_REPORT.md`、可播放样片、命令/日志/版本、技术抉择与风险。阶段门：有真正能解码的有声 MP4，不能只有截图或模拟日志。

## G1｜可确定性执行的 Video IR + Renderer

**目标：** 不依赖模型，使用 fixture IR 生成稳定的视频。

工作项：定义并测试 JSON Schema、运行时组件 props 校验、6 个视觉组件、主题 tokens、时间线 ms→frames 算法；用真实可授权 fixture 音频渲染；抽取关键帧测试布局。

产出：`G1_REPORT.md`、IR 样例/validator、6 组件、真实 fixture render、测试。阶段门：结构错误被拒绝，合法 IR 连续渲染一致，不执行不可信代码。

## G2｜真实模型自主出片

**目标：** 文本经过真实 LLM + 中文 TTS，无人工分镜，自动得到完整视频。

工作项：NarrationPlan、StoryBoardPlan 的结构化输出；TTS、aligner；音频驱动时间线；资源限制与局部重试；保持事实忠实性。

产出：`G2_REPORT.md`、Case A 真正自动全链路 MP4、调用记录/成本、失败测试。阶段门：没有人工填写脚本或 IR，且没有 Mock 冒充真实调用。

## G3｜服务化与 UI

**目标：** 用户经网页提交、跟踪、播放和下载。

工作项：FastAPI 任务 API、SQLite 原子 claim、单 worker、工作空间隔离、取消/重试、React 界面、配置预检。

产出：`G3_REPORT.md`、可启动应用、重启恢复与并发保护测试、操作录像或截图。阶段门：浏览器关闭重新打开仍能准确看到已持久化任务状态。

## G4｜品质闭环和发布验收

**目标：** 能对真实视频做基本机械检查、语义检查、失败报告和受控修复。

工作项：ffprobe/ffmpeg QC、抽帧、布局检查、可选视觉评估、重试预算；Golden Case A/B/C 实测；文档和依赖冻结。

产出：`G4_ACCEPTANCE.md`、三套真实证据、可运行发布包、问题清单。阶段门：通过 `08_QA_AND_ACCEPTANCE.md` 的完成定义。

## 阶段交付格式

每次提交必须包含：变更清单、测试命令/输出、可运行 artifact、失败/未验证事项、下一阶段前置项、Git commit。没真实测试时写“未运行”，不推测 PASS。

## 暂缓项

第二期考虑 AI 图片 + image-to-video、组件库扩展；第三期考虑任意主题与风格；更长期再研究 AI 视频模型、自由代码生成的安全沙箱及视觉自反思闭环。

## v0.2 文档修订后的 G1 细化门槛

- G0 **不受影响**：仅需真实有声程序化样片，不把 v0.2 Schema 当作 G0 阻断依赖。
- G1 应优先实现**一个可信动作链**而非平均铺开六个低质量组件：使用真实授权 fixture 音轨，完成 `reveal → activate_path → mark_disrupted`，保存 beat 前后帧；再实现剩余五个组件及验证器。
- 六组件均需可验证 props、动作注册、target 校验及至少一个具可观察状态变化的演示；组件不得仅能显示文字静态卡。
- G1 不能只有 JSON Schema 绿灯和静态截图，至少有一条 fixture IR 实际声画视频通过语义动作检查。
- 更新 IR 版本为 `0.2`，仅消费 `schemas/video-ir-v0.2.schema.json`。旧 IR v0.1 存档，不得默默兼容。

## 与 MVP 后规划衔接（2026-10-13 增补）

本文件 **G0–G4 保持原样**。G4 实测通过并被用户验收后，执行 `16_POST_MVP_ROADMAP.md` 的 **M0 基线冻结**；然后仅在用户明确授权的情况下考虑 H1、H2、H3、H4。

`15–24` 的远景描述不能反向扩大 G0–G4 的范围。设计文档包升级到 V0.3 不等于产品已经过 G0，更不等于完成 MVP。
