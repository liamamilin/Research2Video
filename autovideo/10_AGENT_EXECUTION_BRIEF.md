# 10｜给编码 Agent 的执行指令

> 适用：把本目录交给 Codex、OpenCode、Qoder 等编码 Agent。本套设计文档为 V0.3-DESIGN-FINAL，当前目标产品是 V0.1；若用户只要求设计评审，禁止自行开始实现。

## 总目标

构建 AutoVideo：用户输入中文知识文本，系统自动生成完整 1080p/30fps 的知识解释视频，包含真实 AI 中文旁白、对应字幕与程序化动画。按 `09_IMPLEMENTATION_PLAN.md` 分阶段完成。

## 执行次序

1. 全文阅读 README 及 00–12 号文档，列出冲突、未定项、外部依赖与风险。不要擅自扩大范围。
2. 扫描工作目录：如果有现有代码、文档、未提交修改，先盘点并保护；不覆盖或重建无关工程。
3. 先只执行 G0。G0 有真实有声 MP4、验证日志和报告后停止，等待用户确认继续 G1。
4. G1/G2/G3/G4 各自具有硬验收门槛，未通过不得跳阶段，也不得声称完成。
5. 影响其他项目或系统目录的操作，必须隔离到本项目 sandbox；禁止清理其他仓库资源或写入真实系统计划任务。

## 工程硬约束

- LLM 输出只作为结构化数据，不能直接作为本地可执行代码。
- 所有 provider keys 只在后端，不入 Git；提供 `.env.example`。
- 使用显式 JSON Schema + 组件 props validator；不得默默接受未知属性。
- TTS 必须在镜头时间线最终确定之前生成；依靠真实音频时长及对齐结果。
- Mock 不能用于真实验收，通过 mock 的测试只标记为单元/契约测试。
- 失败分阶段记录，保证此前输出与源文件不受损；不能无限重试。
- 不重复开发 Remotion 自有的基础渲染/字幕组件能力，优先调研其官方文档、skills 和模板。

## 首轮应做的工作（可直接执行）

- G0 环境检查与技术核验；写出确定使用的具体运行时和版本。
- 生成最小程序化动画，接真实中文 TTS，使用真实音频同步字卡，渲染一条 10–20 秒 MP4。
- 用 ffprobe 核验格式、音视频流、总时长并保存关键帧；人工可播放验证是最初一项必要证据。
- 输出 G0_REPORT.md：实测数据、模型/授权/费用/问题、下一步技术建议。
- **只执行 G0，不继续全面产品开发；提交报告后停止。**

## 汇报规范

`Status: PASS | PARTIAL | FAIL`；附实际运行命令、版本、关键测试数、文件位置、真实 MP4 路径、未验证项、Git commit。如果没有真实输出，不能写 PASS。

## 设计修订提示（v0.2）

- 现行新 IR 设计基线是 `03_VIDEO_IR_CONTRACT.md` 和 `schemas/video-ir-v0.2.schema.json`；旧 v0.1 Schema 仅归档。不要同时实现两个不兼容版本。
- G0 仍只验证真实 TTS + 程序化动效 + 字幕 + 音画导出，不需完整 IR 编译器。
- 将来执行 G1 时，使用 `schemas/component-registry-v0.2.json`、六个组件 props schemas 和 `13_G1_TEST_MATRIX.md` 实现 action target、时间锚点以及 Beat 前后状态测试；**当前不得自行跳过 G0 去实现 G1**。
