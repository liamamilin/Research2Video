# 22｜MVP 后用户体验与交互演进

## 1. 唯一默认主流程（跨版本不变）

```text
粘贴文本 →（可选少量偏好）→ 生成 → 查看进度 → 看视频 → 下载
```

即使内部越来越复杂，用户仍应能只靠这条路径完成成片。新能力不得把“每镜头选模型”“手调时间轴”“审核每个 API 请求”变成必填步骤。

## 2. 体验三层

- **Simple**：只输入文本，直接生成。默认自动决定镜头技术与声音。
- **Inspect**：查看内容提要、视频风格、章节/镜头、质量检查报告和实际费用。
- **Refine**：在用户主动需要时，更换风格、修改讲稿片段、重做某镜头或重生成整片。

默认展示 Simple；Inspect/Refine 可展开。**不等于要开发 Adobe Premiere 级时间轴编辑器。**

## 3. 主要能力随版本演进

| 功能 | H1/V0.2 | H2/V0.3 | H3/V0.4 | H4/V1.0 |
|---|---|---|---|---|
| 可选择的视觉风格 | 初步 | 扩展 | 自动诊断不协调 | 持久化风格库 |
| 场景预览/素材解释 | 可以 | 媒介标签与成本 | 质量问题定位 | 工作空间内复用 |
| 局部重生成 | 基础镜头 | 图像/视频镜头 | 自动或用户触发 | 成熟体验 |
| 成本可见性 | 资产/API 成本 | 模型镜头预算 | 修复成本增量 | 项目视角 |
| 多格式/语言/题材 | 暂缓 | 按证据扩展 | 按验收扩展 | 按真实需求提供 |

表格是设计方向，不要求 H1 一口气实现全表所有行。

## 4. 新项目页（愿景）

- 输入：文本框、目标时长/比例（H4 前仍可以固定）、风格、旁白。
- 可选：预算上限、是否允许云图片/视频生成、素材是否可发送第三方。
- 自检提示：素材过长、出处/数字有疑义、风格与目标不匹配时自动提示，但不让正常任务陷入长表单。

## 5. 任务页（愿景）

可折叠的三条信息层：

1. 用户看到：`内容策划 / 配音 / 分镜 / 素材制作 / 合成 / 质检`，以及当前实际状态。
2. 需要时展开每个 scene：片段预览、对应原文、生产媒介、花费和风险。
3. 研发模式展开：IR、provider 日志、hash、逐 Beat 截图、异常和复现指令。

错误信息示例：`镜头 03 的人物动作生成失败；已切换为图像动画重试。` 而不是只显示 `500`。

## 6. 非破坏性修改体验

用户主动修改旁白时清楚提示可能导致：重新 TTS → 更新时间锚点 → 影响相关镜头与全片合成。只更换镜头背景不应自动重写所有文案或重新购买所有素材。

- 使用版本/attempt 列表而非覆盖。
- 保留之前可播放成片和必要素材。
- 成本较高的改动明确预计额外开销；不能隐式循环付费生成。
- 修复后检查字幕和音轨与画面是否仍相符。

## 7. H4 发布前用户测试

至少用数份不同复杂度的输入，让没有参与开发的人完成：发起任务、理解失败、重试、定位单镜头问题、下载成片。记录完成情况和认知负担，而不是只展示界面截图。
