# 12｜首轮路线实验协议（A/B/C）

## 目标

不是证明“哪种工具更热门”，而是验证谁能以可接受的成本、可复现性和较少人工干预，生成质量较高的视频。所有技术路线采用同一段原文、相同 TTS 和同一输出配置。

## 实验方案

- **A 自由代码生成**：LLM 自主生成 Remotion 代码，仅在隔离、无密钥、限制网络/文件系统的实验沙箱运行。**只做评估，不进入 V0.1 生产执行链路**。
- **B 受约束组件**：LLM 输出 storyboard JSON → Video IR → 已注册 React 组件。
- **C AI 图片 + 程序化动画**：LLM 生成图像 Prompt，图像服务返回图片 → Remotion 做运镜/字幕/信息层；需要可用图像 API 时才执行，未接入则写 Not Tested。

## 统一测量项

- 端到端成功率、平均失败重试次数、输出有效率。
- 信息表达是否准确、是否出现不可读文本与低质量排版。
- 人声自然度、镜头与字幕是否同步。
- 生成和修复成本、耗时、是否容易单镜头重做。
- 每条路线至少保留真实视频、渲染日志、失败报告，不仅使用静态图评价。

## 决策原则

G0 不必完整实现 A/B/C 三条生产线；先验证其中一条可生成 10–20s 有声视频，再根据实际时间/预算补对照试验。V0.1 主线预设 B；如果 A/C 效果显著优于 B，应先出 RFC，再改变路线。

## 动态视觉表达补充指标（v0.2）

A/B/C 三路除总体画面质量外，必须报告：

- 观众能否不看字幕仅看镜头就辨认关键状态变化；
- 一段解释至少两个明确动作点（如信号传递→受到干扰）是否在合理时间发生；
- 关键动作在音频对齐边界之前/之后采帧，是否真正出现预期视觉差异；
- 该表达由自由代码、组件动作还是图像动画产生，局部重做需要改动什么。

这属于质量比较维度，不意味着每一秒都必须运动或任一方案必然优胜。
