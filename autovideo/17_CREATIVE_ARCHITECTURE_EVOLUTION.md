# 17｜创作架构演进：多媒介而不失控

**状态：未来接口研究草案。** 不修改当前 `03_VIDEO_IR_CONTRACT.md` 的 IR v0.2 规范，不视为任何既有字段已被批准。

## 1. 为什么保留 IR 又不能被其困住

受控组件可以保证可验证的运行行为；但如果所有媒介都强制映射为现有六组件，必然产生单一模板感。解决方式不是解除全部约束，而是**将“语义导演”与“各媒介执行器”分离**。

```text
输入文本 + 内容证据
        ↓
Content & Narration Plan（要说什么；哪些事实来自输入）
        ↓
Visual Intent + Narrative Beats（要让观众看见什么变化）
        ↓
Scene Media Router（此镜头用哪种生产手段；理由和预算）
        ├─ Procedural Adapter → 注册组件 / 动作
        ├─ Image Motion Adapter → 图片 + 裁切/景深/视差/图形叠层
        ├─ Video Generation Adapter → 短片段 + 规范化/裁切
        └─ 3D Adapter（研究分支，按价值批准）
        ↓
Scene Artifact + Timing + Rights/Cost Manifest
        ↓
Unified Timeline / Audio Mix / Subtitle Overlay
        ↓
Preview → QA → Repair / Fallback → Final MP4
```

## 2. 契约边界

- **语义层**回答 *why/what*：镜头目的、观众理解目标、内容证据、视觉状态/动作；与渲染技术无关。
- **生产计划层**回答 *how*：候选媒介、提示/资源需求、镜头预算、可接受后备方案、预计时间与权利限制。
- **执行层**只消费已经验证的媒体特定规范（Adapter Contract）；不得把自然语言指令伪装为任意代码执行。
- **合成层**统一输出：持续时长、宽高、帧率、透明与否、音轨策略、色彩空间等；具体标准待 H2 实测冻结。

建议分开设计 `StoryboardPlan`、`SceneProductionPlan`、`RenderedSceneArtifact`。**以上是概念名，不代表直接在现行 Video IR v0.2 中添加字段。**

## 3. 场景路由规则（先规则，后学习）

| 内容需求 | 首选尝试 | 后备方案 |
|---|---|---|
| 数学数值、图形解释 | 程序化图表/动画 | 受控静态图 + 逐层解释 |
| 概念定义、对象关系 | 语义组件与 Beats | 图片 + 标注与局部运动 |
| 抽象场景、氛围/隐喻 | AI 图片 + 动态镜头 | 程序化符号隐喻 |
| 自然动作、人物/空间镜头 | 视频模型（若有价值及权限） | 图片动态与叙事重构 |
| 连续可复用角色/场景 | 受控资产、参考图/一致性机制 | 改写分镜避开不稳定特写 |

路由器应记录每个选择的**意图、备选、质量风险和预算**。模型不能只因为“视频模型更酷”就优先使用。

## 4. 版本化与兼容性

1. 现行 `Video IR v0.2` 在 G1–G4 继续按既定合同执行。
2. H1 尽可能通过资产和已注册组件扩展，不做破坏 schema 的大改。
3. H2 如引入多种 scene payload，先写 `RFC: IR v0.3`，包含新 schema、完整 JSON fixture、兼容策略、迁移/拒绝规则、验证器与示例影片。
4. 旧作品应保存 `schema_version`、renderer/adapter/prompt/model 版本以及 asset hash；无法重放时给出具体缺失原因。
5. 用内容寻址缓存中间资产，局部修改只使依赖的场景及合成结果失效。

## 5. 可靠性和隔离

- **程序化生产**：仍使用受控执行路径。
- **自由代码实验**：单独实验进程/容器/虚拟机；禁外网、禁宿主密钥、只读输入、限制文件访问/CPU/RAM/超时/输出大小；校验这些限制**真实生效**以后才允许运行模型代码。
- **云模型生产**：输出作为不可信媒体文件处理，校验真实类型、长度、编码、内容哈希，转码规范化后交合成器。
- **外部来源**：标记素材许可、来源、内容是否允许交给第三方模型处理；不带出用户未授权的原始材料。
- **失败降级**：后备媒介必须满足最基本的语义意图；如果做不到就报告失败，而不是随便贴图片。

## 6. 反直觉但重要的决定

**不要把一个复杂 Agent 当成整个工作流。** 应把“选择/创意”交给模型，把“执行/检查/恢复”交给可测试服务。否则升级模型会同时改变内容决策、代码执行和视频质量，无法确定问题来自哪里。

## 7. H2 架构门槛

- 两种媒介产出可在同一条视频正确混合，且没有重复旁白或冲突的模型自带音频。
- 运行任何缺省媒介时，系统不会丢失已完成的其他镜头。
- 资产来源/生成参数/权利状态与成本可逐镜头查询。
- 渲染路径不存在“任意 LLM 代码默默在宿主执行”的快捷通道。
