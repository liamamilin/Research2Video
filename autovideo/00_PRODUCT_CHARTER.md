# 00｜产品章程

## 1. 用户希望什么不同

现在，要把一段已有知识变成精美视频，通常要分别写解说稿、设计分镜、画图、录音、做动画、剪辑并检查。用户不想操作这些步骤；希望只提交文本素材，就得到完整、准确、好看的成片。

## 2. 产品承诺

- **输入**：一份中文文本素材（文章、提纲、讲稿、概念说明）。
- **系统处理**：理解文本并选择表达重点 → 自动解说稿 → 分镜 → 配音 → 视觉与音效 → 合成 → QA。
- **输出**：完整 MP4、字幕文件、结构化分镜、渲染报告、资产清单；失败时返回可定位的原因。
- **交互**：填入素材、选择少量偏好、点击生成、查看进度/预览/下载；正常成功路径无人工介入。

## 3. 成功与不成功

**成功：** 系统收到一段复杂但适合解释的中文材料，能独立制作一条观众看得懂、字幕完整、语音清楚、动画合理、画面统一的视频。

**不成功：** 返回的只是 PPT 页面轮播；旁白与画面不对应；事实被编造；只能运行一个硬编码 demo；使用 Mock 声音冒充真实成果；渲染失败却显示成功。

## 4. 产品原则

1. **表达优先**：选画面的依据是内容如何被观众理解，而非效果炫酷。
2. **适合的技术优先**：解释图用程序化动画，未来写实镜头可交给视频模型。
3. **内容可追溯**：解说稿中的实质论断要能追溯输入文本；推断/补充内容必须标注，不凭空补事实。
4. **确定性执行**：LLM 可以提出设计，渲染器只执行受约束的结构数据。
5. **真实产出优先**：由真实 LLM 和真实 TTS 出片是 MVP 验收硬门槛。
6. **能回滚和重试**：任何失败不能损坏既有工程或先前成功成片。

## 5. 内容保真规则

- 允许压缩、排序、改写语气、换直观类比，但不得改变原文中心论点。
- 含数字、专有名词、引语和因果关系时，保持可核对的一致性。
- 原文存在矛盾、缺乏解释素材或容易误导的语句，优先保留限定语或在生成报告中记录风险。
- V0.1 不承诺联网事实核查，不得暗示外部证据已被验证。
- 用例不适合自动解释时，明确失败或返回“需要更明确素材”，不能制造不存在的事实。

## 6. 未来方向（不属 V0.1）

AI 图像、视频模型镜头、不同画幅、多语言、长视频、团队协作、视频编辑器、发布到平台、批量高并发、素材库复用、自动跨视频风格学习。
