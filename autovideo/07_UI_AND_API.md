# 07｜用户界面与 API 草案

## 1. UI 三个主要页面

### A. 新建视频 `/new`

- 大输入框：粘贴文本；标题、目标时长、主题、voice（默认值能工作）。
- 开始生成按钮；预检失败要清晰解释缺什么。
- 不显示内部复杂 prompt 或 provider 字段，进阶配置可折叠。

### B. 任务详情 `/jobs/:id`

- 当前状态：等待、生成脚本、合成旁白、分镜/渲染、检查、完成/失败。
- 展示阶段产物摘要与可读错误；可取消、可重试。
- 成功后播放器、下载按钮、字幕和 report 链接。
- 即便浏览器关闭，后台任务状态仍可持久化并在重开后查询。

### C. 任务列表 `/jobs`

- 标题、提交时间、状态、视频时长、失败/成功指示、详情入口。
- V0.1 不建多角色用户中心；限制服务只绑定本机访问或明确身份验证。

## 2. HTTP API（建议）

| Method | Endpoint | 目的 |
|---|---|---|
| `POST` | `/api/jobs` | 创建任务，返回 `job_id`，202 Accepted |
| `GET` | `/api/jobs` | 分页列出任务 |
| `GET` | `/api/jobs/{id}` | 获取状态、阶段进度、错误 |
| `POST` | `/api/jobs/{id}/cancel` | 申请取消 |
| `POST` | `/api/jobs/{id}/retry` | 新 attempt，不覆盖旧制品 |
| `GET` | `/api/jobs/{id}/artifacts` | 列出允许下载的制品 |
| `GET` | `/api/jobs/{id}/artifacts/{name}` | 下载 MP4 / SRT / JSON 报告 |
| `GET` | `/api/config/status` | 能力是否配置完成（不泄露密钥） |

## 3. 创建任务示例

```json
{
  "title": "为什么噪声会影响信息传输",
  "source_text": "……用户粘贴的中文素材……",
  "target_duration_sec": 60,
  "theme": "minimal_dark",
  "voice_id": "default_zh"
}
```

成功创建：`202 {"job_id":"<uuid>","status":"QUEUED"}`；参数问题返回 422；能力未配置返回明确的可恢复错误。

## 4. 请求与任务契约

- 创建任务时不等待视频生成完成，耗时工作由持久化 worker 执行。
- 下载接口用允许的 artifact name 映射到本地文件，禁止直接拼接用户指定路径。
- V0.1 轮询即可，例如 2–3 秒更新一次；不要求立即引入 WebSocket。
- 任务状态只反映服务端确切状态；下载链接必须先确认制品存在且 QA 验证通过。
- 对失败和中断呈现具体阶段、下一步、是否适合重试。

## 5. MVP 用户体验底线

正常场景只需“粘贴文本 → 生成 → 看视频”；不要求用户理解 Video IR、FFmpeg、模型参数。视觉设计简洁，内容结构与排版需达到基本产品级，而不是仅展示后端调试字段。
