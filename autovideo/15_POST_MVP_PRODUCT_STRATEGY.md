# 15｜MVP 后产品战略与边界

**状态：FUTURE / DESIGN ONLY。** 本文讨论的是 *产品 V0.1 经 G4 验收之后* 的方向；当前文档集合 V0.3 不表示产品 V0.3 已经实现。除非用户明确授权，不应执行本文的工程任务。

## 1. 用户真正要买到的结果

用户不是来“获得一组漂亮镜头”，而是希望：**把已有文字中值得表达的内容，转化成准确、清楚、审美一致、声音完整且可以发布的视听作品**，全流程默认无需人工参与。

完整价值链分成五层：

1. **内容忠实**：辨认原文主张、事实、限制条件、作者态度；不能偷偷改写成另一个意思。
2. **表达设计**：选择哪些内容适合语音、示意动画、图表、场景、隐喻或留白；取舍可追溯。
3. **媒介制作**：把表达计划落实为图形、图片、视频、旁白、音效、音乐，处理镜头衔接。
4. **体验检验**：检查观众是否能看懂、是否耐看、是否有明显错误；分清自动可证明和主观判断。
5. **可迭代的作品**：当内容、风格或某一镜头不理想，只重做必要范围，既有好成果不丢失。

## 2. 产品能力分层

| 层次 | V0.1 的基线 | MVP 后的目标 |
|---|---|---|
| 输入 | 中文知识素材 | 逐步支持故事、评论、研究、产品说明等文本 |
| 导演 | 注册组件 + Visual Intent + Beats | 可以在多个媒介之间作选择，依据质量反馈重规划 |
| 画面 | 程序化 2D 知识动画 | AI 图片、视差、3D、视频模型镜头的受控混合 |
| 声音 | 真实 TTS、字幕、授权音效/音乐 | 更自然的表达、自动原创配乐/音效、声音一致性 |
| 评价 | 技术硬门槛 + 研发主观评议 | 可校准的多模态评估、定位问题、有限循环改进 |
| 操作 | 文本输入、进度、下载 | 可选择查看分镜、局部重生成、项目及风格资产管理 |

## 3. 不同时期的产品定义

- **V0.1：可靠视频生成工具**。以知识解释视频证明完整闭环。
- **V0.2：高品质动效讲解器**。视觉表达能力与风格显著提升；不必须引入视频模型。
- **V0.3：混合媒介视频导演**。面对每个镜头，选择适当的生产方式，保持片段连续性。
- **V0.4：带审片能力的创作系统**。通过有界自动改进，减少肉眼可见的问题和无意义重复生成。
- **V1.0：可持续运转的个人 AI 视频工作室**。支持多个内容域、工作区、风格复用、局部操作与稳定交付。

**版本名是产品能力标签，而非日期承诺或功能全都必须实现的合同。** 允许根据试验结果合并阶段、删减低价值功能或者调整顺序，但必须出具 RFC。

## 4. 基本原则（跨版本）

1. **表达成效 > 模型炫技**。图表能解释清楚的，不必花钱生成真人电影镜头。
2. **自由度与可靠性共同设计**。受控组件是 MVP 的安全默认，不是永久的表达上限；新增生成能力通过独立适配器与隔离运行引入。
3. **自动化是正常路径**。可提供人类修改入口，但不能要求用户逐镜头批准才能成片。
4. **来源与变更可追溯**。包括内容来源、资产来源、模型/提示版本、成本、权利状态、生成链条。
5. **局部迭代优先**。QA 应以 scene/beat/audio segment 为最小可重制单元；避免重做整片。
6. **先有质量证据，再做大规模产品化**。成本、质量和失败率未验证之前不引入无关服务与商业模块。

## 5. 不自动纳入未来承诺的功能

- “任意题材都能像专业电影一样”的无限能力承诺。
- 批量灌水式自动发布、增长黑客和未经允许的外部账号操作。
- 平台级团队协作、付费订阅、市场、社区、编辑器全功能替代品。
- 给出分数就能替代专业审美与事实核查的绝对承诺。

这些方向需要单独需求、经济性或风险评估，不应由编码 Agent 从远景描述中自动开发。

## 6. 核心决策问题

每次新引入一种媒介时，先回答：**它为哪些内容模式带来了原方案无法取得、且观众可感知的改善？** 如果没有真实样片支持，应回到实验而不是建设大模块。
