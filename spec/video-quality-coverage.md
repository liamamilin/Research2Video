# 文稿与出片质量规则的覆盖范围

2026-10-24。公共规则按处理环节应用，不按矩阵、稿件标题或配方白名单应用。矩阵和配方可以配置受众、讲法与视频形式，不能关闭内部研究备注检查。

| 环节 | 公共实现与入口 |
|---|---|
| 一次写稿及改稿 | `core/video/writer.py`、`audit.py` 共享 `audience_copy.GUIDANCE`；内部备注和无原文核验依据的来源缺失断言进入修复和复审 |
| 五步改编及改稿 | `adapt/draft.py`、`adapt/review.py` 使用同一规则；本地发现的来源缺失断言同样进入改稿，真正的事实限定随主张保留 |
| 读取旧版审校结果 | `video_workflow.rule_checks` 在已保存审校上叠加当前本地备注检查，不修改历史结果，也不冒充新的事实审计 |
| 文稿列表与视频看板 | `credibility.label` 同样实时检查当前正文；发现内部备注时显示“口播有问题”，看板引导修改口播，避免仍推荐直接定稿/出片 |
| 手动定稿 | 页面、助手均进入 `video_executor.approve`；内部备注未解决时返回具体段落，保存的稿件不变 |
| 新出片与重跑 | 页面、步骤重跑、助手、自动流水线均通过 `video_render.create`，标准和快速档共用同一检查 |
| 自动矩阵 | `video_autopilot` 经 `video_executor` 调用同一写稿、审校与出片服务，配置不产生另一套质量逻辑 |
| AutoVideo 独立入口 | 原稿提交、原稿修订先检查再做形式选择/配音；素材模式检查生成的旁白并反馈给有限重试；画面、音色、速度和背景修订复用旧旁白时也先检查 |
| 快速卡片 | 所有选择 `information_cards` 的配方和入口共同使用 `g2/card_editorial.py` 提炼、原文摘录、归属/条件标签与短句字幕 |
| 普通信息动效与流程图 | 与快速卡片共用本机强制对齐的短句字幕计划；单独的渲染字幕轨道不改动旁白分段、动画触发或 Video IR 合约；字幕轨道和导出 SRT 必须一致。画面布局仍沿用原形式 |
| 其他创意形式 | 图片轮播、演绎对话等保留已有实现，本轮代表样本没有覆盖这些形式，不把当前验收结果外推到它们 |

两个项目可以独立运行，各自有公共检查模块；相邻工作区的合约回归会检查提示词和匹配规则一致。AutoVideo 不依赖 Research 的数据库或私有模块，单独调用也不能绕过这项检查。规则只识别明确的内部资料缺口，不禁止“材料”一词，不拦截材料性质、官方标称或真实的测试限制。

## 历史记录与事实核验

新规则不批量重写旧稿，不覆盖旧审校和旧片。旧稿重新定稿或新出片时执行当前本地检查；已生成视频下载失败后的断点续传继续原任务，不重复出片。真正的待核实原因不因这项检查被清除，自动流水线仍执行事实门槛，手动决定沿用原有规则。

《续航手机最抢眼，五件新品变化速览》中的原网页逐条核查、链接纠正和来源快照是该篇的具体证据工作。公共写稿规则不能替代未取得的原文，也不会将“摘要没收录”直接改成“原评测没有”。这轮没有增加自动抓取全部原网页的功能。

回归逐一解析当前全部配方及矩阵生产配置，覆盖旧审校缓存、手动定稿、标准/快速出片、重跑、自动出片、下载恢复和独立 AutoVideo 输入。离线覆盖表示各入口使用规则，不保证每次模型产出的文稿都精彩，实际成片仍需验收。

## 本批代表样本发现的修复

- 来源缺失断言需有记录的原网页复核及该段事实审计依据。摘要没写许可证、容量、研究方法或研究出处，不能直接断言原文没有。普通研究范围、作者归属、模拟条件和“可能”等真正限定不受这项匹配拦截。
- 快速卡片的来源标签识别媒体“最近转述”的情形；否定存在的对象与后续能力限定不能拆成两条相反主张，例如“没有冶炼厂，能生产军工专用高纯铝”。原始失败样片、修订版本与重跑输出均保留。
- 普通动画不再直接把整段配音当作一条字幕。新片及音色/速度/画面修订重新校验短句字幕轨道；历史片没有短句轨道时保留其原输出，不改写历史文件。

实际样本记录位于相邻 AutoVideo 项目的 `g3/acceptance/matrix-recipe-quality-20261023/`；每篇技术结果、人工画面抽查和未执行的完整听音分别记录。选择范围为 8 篇、6 个矩阵、4 类已有配方，不能视为全部矩阵和配方已实片验收。
