# 视频改编（Video adaptation）

状态：设计已确认（2026-10-17），实现中。本文件替换 `spec/video-scripts.md` 里「写稿」那一步：
研究报告不再一次改写成讲稿，而是经过五步改编，变成适合视频的讲稿。

## 为什么需要这一步

研究报告和视频讲稿的视角不同。报告写给**提出问题的人**：他知道为什么要问，会回头
查数字，需要每个判断的出处和口径。讲稿讲给**第一次听到这个问题的人**：他只听一遍、
不能回看，也没人告诉他为什么要在乎。

| | 研究报告 | 视频讲稿 |
|---|---|---|
| 对象 | 提出问题的人，会回看 | 第一次听到的人，只听一遍 |
| 组织方式 | 按证据状态：结论 → 事实表 → 争议 → 未定 | 按理解顺序：为什么在乎 → 概念 → 机制 → 证据 → 反方 → 怎么做 |
| 术语 | 默认读者懂 | 第一次出现就解释 |
| 数字 | 越精确越好，带口径 | 少，有参照；精确值和口径进简介 |
| 限定条件 | 每句都带 | 只讲影响结论的；其余进简介 |
| 不确定 | 写给审稿人：「未取得一手来源」 | 说给观众：「官方没公布，先当参考」 |

现在的写稿（`core/video/writer.py`）一次调用同时做两件事：从报告里挑事实，按口播
写出来。模型边翻报告边写，报告的结构和密度就原样搬进了讲稿。C4 v1 的这一段：

> 先把乘数说清楚。缓存写入，5 分钟有效期是输入价的 1.25 倍，1 小时有效期是 2 倍。
> 缓存读取命中，是 0.1 倍。但 Opus 5.5 和 Sonnet 5.5 单独降到 0.05 倍。所以
> Opus 5.5 输入 4 美元，对应缓存读取 0.20 美元，是 20 倍差距，不是大家常说的 10 倍。

事实都对，但五句话里有十个数（不算型号），其中两句各有四个；「缓存写入」「有效期」
「命中」都没解释过。观众听完，一个数也记不住。

改编的做法：**先把报告拆成事实，再按观众的理解顺序重新组织，按选定的风格写出来，
最后让一个「新观众」和一个「核对员」检查。**

## 一、标准：什么样的讲稿适合视频

每条标准有编号，审校结果按编号报告。「怎么查」一栏中，**规则**指代码检查，不花钱，
每次保存都跑；**评审**指模型检查（见第 ④ 步）。

不达标分两级：**必须改**会触发自动修改，改完仍未解决的在审稿页标红；**提醒**只显示。

### A 讲给谁

| 编号 | 要求 | 怎么查 |
|---|---|---|
| A1 | 讲述方案写明观众画像：已经知道什么、不知道什么、关心什么、看完能做什么 | 规则（方案必填） |

观众画像由选题的「目标受众」和风格的「深浅」档位（第三节）决定。后面所有要不要
解释、要不要举例的判断，都以它为准。

### B 讲什么

| 编号 | 要求 | 怎么查 |
|---|---|---|
| B1 | 全片一句话主旨，不超过 30 字；方案里每一节标明它对主旨的作用（铺垫、机制、证据、反方、行动……）。新观众听完能复述出来 | 规则 + 评审 |
| B2 | 开场 15 秒（约 65 个朗读单位）内抛出钩子：一个具体场景、反常识的结果，或观众关心的问题，并让观众知道看下去能得到什么。不先讲背景，不自我介绍 | 评审 |
| B3 | 取舍：事实底稿里的每条事实，要么进讲稿，要么写明为什么不用（不用的进简介） | 规则 |
| B4 | 结尾回到开场的钩子，再说一次主旨；栏目要求行动时，给出具体能做的动作 | 评审 |

### C 听得懂

| 编号 | 要求 | 怎么查 |
|---|---|---|
| C1 | 先铺垫再使用：方案术语表里的术语，第一次出现的那一段要用一句白话解释，或者前面已经解释过 | 规则（按段落的 `introduces` 标注检查顺序）+ 评审（抓术语表之外的生词） |
| C2 | 背景前置：理解一个判断需要的背景，放在这个判断前面讲 | 评审 |
| C3 | 类比要对得上：方案里写明类比物对应什么概念，以及类比在哪里不成立 | 评审（忠实核对） |
| C4 | 数字克制：一句最多 2 个数字；数字要有参照（倍数、对比、换算成熟悉的量）；精确值和口径进简介 | 规则（数阿拉伯数字，型号中的版本号不算）+ 评审（中文写的数量） |
| C5 | 一段一事：每段只讲一个点；长度按栏目设置（深度解读为 60–140 个朗读单位） | 规则（长度）+ 评审 |
| C6 | 句子短：一句不超过 40 个朗读单位 | 规则（超过 40 提醒，超过 60 必须改） |
| C7 | 路标：每节第一句交代这一节讲什么。5 分钟以上的视频，大约每 2 分钟（约 520 个朗读单位）回顾一次讲到哪了 | 规则（按段落的 `recap` 标注算间隔）+ 评审 |
| C8 | 并列的方案按内容称呼，不按顺序称呼：先说「有两种写法」，之后说「时间戳放开头的」「挪到后面的」，不说「第一遍」「第二遍」，免得听成先后跑了两次 | 评审 |

### D 讲得对

| 编号 | 要求 | 怎么查 |
|---|---|---|
| D1 | 不新增事实：每个事实性说法都能对应到这一段标注的事实编号。举例和假设场景必须让人听得出是假设 | 评审（忠实核对） |
| D2 | 不放大确定性，也不放大范围：按事实的置信度选用对应的说法（见下表）；不把「Opus 5.5 和 Sonnet 5.5」说成「5.5 这一代」 | 评审（忠实核对）+ 规则（钩子不能用未核实的事实） |
| D3 | 数字等价：取整误差不超过 5%，方向不变。换算出来的数（「便宜 20 倍」）必须来自事实底稿里的推导事实，写稿时不现算。推导事实记录公式、参数和单位：讲稿用的参数要和推导一致（讲稿讲的是 0.05 倍读取，回本次数就不能用按 0.1 倍算的）；由推导引申的说法（「只用一两次就不划算」）要能用公式验算 | 评审（忠实核对） |
| D4 | 出处自动继承：段落的引用就是它所用事实的来源，写稿模型不再写网址 | 规则 |
| D5 | 审稿用语不进口播：「得核实」「没拿到一手出处」写进段落备注；对观众说不确定，用观众听得懂的话 | 规则（禁用词）+ 评审 |

置信度与说法：

| 置信度 | 含义 | 讲稿里怎么说 |
|---|---|---|
| 已证实 | 一手来源，或两个独立来源 | 直接说 |
| 厂商自述 | 只有厂商自己的说法 | 「官方说」「按厂商的说法」 |
| 有迹象 | 单一案例、二手来源 | 「有案例显示」「目前看」 |
| 推导 | 由其他事实算出来的 | 「算一下」「按这个价格推算」 |
| 推测 | 报告标为推测 | 「可能」「我的判断是」，不能当结论讲 |
| 有冲突 | 来源之间说法不一 | 说清用的是哪个口径，或者两个都说 |
| 未核实 | 没有可信来源 | 默认不讲；要讲就明说「还没有一手来源」，而且不能用在钩子和主旨论证里 |

D5 的例子，C4 v1 第四节：

> 原文：……说实际命中率区间是 30% 到 98%……这个区间我没拿到一手出处，得核实。
>
> 改为：……有第三方文章说，命中率可能在三成到九成八之间浮动，官方文档里还没找到
> 原话，先当个提醒。
> 备注（不朗读）：30%–98% 只有二手转述，需找到 Batch 文档原文。

### E 好读

| 编号 | 要求 | 怎么查 |
|---|---|---|
| E1 | 没有读不出来的符号：× → ≥ ≤ ~ /、括号、短横线区间、Markdown 标记。区间写成「41% 到 80%」 | 规则 |
| E2 | 代码、命令、参数名只在观众要照着输入时才读，每段最多一个；其他时候讲它的作用（「把输出长度设成 0 的预热请求」） | 规则（计数）+ 评审 |
| E3 | 对观众说「你」；不说「根据报告」「本期报告」「上回」「上一期」 | 规则（沿用现有禁用词） |
| E4 | 总长度在预算的 ±25% 以内（沿用 `core/video/length.py`） | 规则 |

### F 简介

讲稿删掉的严谨内容不丢，放进简介。每个版本附一份简介：

- 一句话摘要；
- 精确数字和口径，即讲稿里取整或省略的那些；
- 讲稿没展开的限定条件，以及仍未确定的问题；
- 来源清单（代码从事实底稿生成，不由模型写）；
- 章节时间点（成片后按 AutoVideo 的章节时间生成）。

简介不交给 AutoVideo，存在本系统，发布时使用。

## 二、五步改编

```
研究报告 + 引用核对
 → ① 事实底稿  事实、置信度、来源、概念                   （每份报告做一次）
 → ② 讲述方案  观众画像、主旨、钩子、术语表、分节、取舍    （每种风格做一次）
 → ③ 写稿      按方案和风格写，每段标注用到的事实
 → ④ 审校      规则检查 + 新观众评审 + 忠实核对，最多改两轮
 → ⑤ 人工审稿  看方案、讲稿和检查结果；编辑、换风格、定稿
```

只有第 ① 步读完整报告，② 以后只用事实底稿。所以换风格只需重跑 ②③④，不用重新
调研，也不用重读报告。

### ① 事实底稿

- **输入**：研究报告全文、引用核对结果（`core/provenance.py`）、可信网址
  （`writer.trusted_urls`）。
- **做法**：一次模型调用，把报告拆成独立的事实。报告里算出来的结论（「20 倍差距」
  「贵 25%」）单独列为**推导事实**，写明由哪几条事实算出。事实要记精确的说法和
  范围：报告结论段写「5.5 家族降到 0.05 倍」，但它自己的价格数据显示 Haiku 5.5 仍是
  0.1 倍（缓存读取 0.01、输入 0.10），底稿要记成「Opus 5.5 和 Sonnet 5.5」。
  推导事实要写出公式、参数和单位。来源有多个版本时（论文修订、文档更新），记下用的是
  哪一版：同一篇论文 v1 写降本 45–80%，v2 改成 41–80%。
- **输出**：

```json
{
  "question": "报告回答的问题，一句话",
  "answer": "报告的直接回答，一句话",
  "facts": [
    {
      "id": "F3",
      "claim": "Opus 5.5 输入 4 美元每百万 token，缓存读取 0.20 美元每百万 token",
      "confidence": "已证实",
      "sources": ["https://platform.claude.com/docs/en/about-claude/pricing"],
      "caveat": "口径、适用范围，可空",
      "derived_from": []
    },
    {
      "id": "F9",
      "claim": "前缀每次都被打断时，比不开缓存贵 25%",
      "confidence": "推导",
      "sources": [],
      "caveat": "每次调用都按 5 分钟写入价，即输入价的 1.25 倍计费",
      "derived_from": ["F4", "F5"],
      "formula": "写入倍率 1.25 − 不开缓存 1 = 多付 0.25"
    },
    {
      "id": "F14",
      "claim": "1 小时有效期的缓存，要到第三次请求才回本",
      "confidence": "推导",
      "sources": [],
      "caveat": "单位是总请求次数，不是复用次数",
      "derived_from": ["F4", "F5"],
      "formula": "回本请求数 = (2 − 读取倍率) ÷ (1 − 读取倍率)；读取 0.05 倍时 2.05，0.1 倍时 2.11"
    }
  ],
  "concepts": [
    {"term": "提示词缓存", "meaning": "报告里的含义", "needs": ["token"]}
  ]
}
```

- **代码校验**：编号唯一；`sources` 只保留可信网址，去掉的记下来；没有来源的非推导
  事实降为「未核实」；推导事实必须有公式，引用的编号必须存在，它的来源取所依据事实的来源之和，
  依据里有「未核实」的，推导事实也算「未核实」。
- **存储**：新表 `fact_sheets`，按报告内容和拆分提示词的版本算 sha256，存一份，同一份
  报告的所有版本、所有风格共用。提示词改版后生成新的底稿，旧版本仍指向旧底稿，事实编号
  不会错位。
- **人工**：审稿页可以展开查看。第一版不支持编辑。

### ② 讲述方案

- **输入**：事实底稿、栏目（结构要求、目标时长）、选题（目标受众）、风格（深浅 +
  语气）、长度预算。
- **做法**：一次模型调用。视角转换主要发生在这一步：决定讲什么、不讲什么、先讲什么，
  哪些概念要铺垫、用什么类比。
- **输出**：

```json
{
  "audience": {
    "knows": ["用过大模型 API", "知道按 token 计费"],
    "lacks": ["提示词缓存怎么收费", "前缀匹配是什么意思"],
    "cares": "每月的 API 账单",
    "takeaway": "检查自己的系统提示里有没有每次都会变的内容"
  },
  "core_message": "缓存省不省钱，取决于前缀是不是每次都一字不差",
  "hook": {"kind": "反常识", "idea": "开了缓存，账单反而比不开还贵", "facts": ["F9"]},
  "glossary": [
    {
      "term": "提示词缓存",
      "plain": "把每次都一样的开头存起来，下次直接复用，不再按全价算",
      "analogy": "复印店存档",
      "mapping": {
        "存档费": "缓存写入，多付 25%",
        "照上次那份再来一份": "缓存读取",
        "原稿必须一模一样": "前缀逐字节一致"
      },
      "breaks": "复印店的存档不会过期；缓存 5 分钟或 1 小时后失效"
    }
  ],
  "beats": [
    {"title": "开了缓存反而更贵", "role": "钩子", "point": "一个时间戳让缓存变成罚款",
     "facts": ["F9", "F1"], "terms": [], "budget": 180},
    {"title": "缓存怎么收费", "role": "概念", "point": "存一次多付一点，之后复用只付零头",
     "facts": ["F3", "F4", "F5"], "terms": ["提示词缓存"], "budget": 300}
  ],
  "left_out": [
    {"fact": "F21", "reason": "OpenAI 侧的口径未定，和主旨无关", "to_description": true}

```

`role` 取值：钩子、背景、概念、机制、证据、反方、行动、收束。

- **代码校验**：事实编号都存在；每条事实要么在 `beats` 里，要么在 `left_out` 里
  （B3）；钩子不用「未核实」「有冲突」的事实（D2）；栏目要求的角色都有（深度解读
  要求钩子、反方、行动）；各节预算由代码按方案的比例重新分配，总和等于栏目预算。
- **人工**：审稿页显示方案。栏目可以设 `review_plan: true`，让流程在方案这一步停下，
  人确认后再写稿；默认不停，审稿时可以改方案、从方案重写。

### ③ 写稿

- **输入**：讲述方案、方案用到的事实（不是整份报告）、风格说明和示例、每节预算。
- **输出**：在现有结构上，每段增加三个字段，另附简介：

```json
{
  "title": "视频标题",
  "sections": [{
    "title": "小节标题",
    "paragraphs": [{
      "text": "口播段落",
      "facts": ["F3", "F4"],
      "introduces": ["提示词缓存"],
      "recap": false
    }]
  }],
  "description": {
    "summary": "一句话摘要",
    "details": ["精确数字和口径"],
    "open_questions": ["仍未确定的问题"]
  }
}
```

- **代码处理**：段落的 `citations` 由 `facts` 的来源算出（D4）。`evidence` 由事实
  置信度算出：用到「未核实」或「有冲突」的事实，标 `NEEDS_REVIEW`；用到有来源的
  事实，标 `CITED`；不用事实的过渡段，标 `UNCITED`。简介的来源清单由代码生成。
  长度照旧测量。

### ④ 审校

三项检查，结果都按标准编号报告，并指到具体段落。

**④a 规则检查**（代码）：A1、B1 字数、B3、C1 顺序、C4 数字、C5 长度、C6 句长、
C7 回顾间隔、D2 钩子、D4、D5 禁用词、E1 符号、E2 计数、E3 禁用词、E4 总长。

**④b 新观众评审**（一次模型调用）：模型扮演方案里的观众，**看不到报告和事实底稿**，
只按顺序读讲稿，模拟只听一遍。输出：

- 每段读完会冒出的问题（「X 是什么？」），跟不上或想划走的地方，以及可能听错的说法
  （C8）；
- 读完后用一句话复述主旨（交给 ④c 和方案的主旨比对，对应 B1）；
- 钩子（B2）、好懂（C）、节奏（C7）、风格贴合，各打 1–5 分。

**④c 忠实核对**（一次模型调用）：输入每段讲稿和这段标注的事实（含置信度、口径），
以及方案里的类比对应关系。逐段检查：有没有新增事实（D1），确定性或范围有没有被放大
（D2），数字是否等价（D3），类比对不对得上（C3）；再判断新观众复述的主旨和方案是否
一致（B1）。

**修改**：把「必须改」的规则问题、新观众的问题、核对出的问题汇总，发一次修改请求，
**只重写有问题的段落**，其他段落原样保留。改完重跑 ④a 和 ④b（新观众要听整篇才能判断
衔接），④c 只核对改过的段落。最多两轮。

**通过条件**：没有「必须改」的规则问题；忠实核对没有问题；新观众各项不低于 4 分，
没有留下「X 是什么」的问题。两轮后仍未通过的，保留问题最少的一版交给人工；剩下的
问题列在审稿页上，不隐藏，不截断。

### ⑤ 人工审稿

在现有审稿页上增加：

- 版本标题旁显示风格，如「进阶 · 讲解通俗」；
- **方案**面板：观众画像、主旨、术语表（含类比对应）、分节和每节要点；
- 每段显示事实标签，悬停可看事实原文、置信度和来源；
- **检查结果**：按标准编号列出，点击跳到对应段落；
- **简介**页签；
- **换个风格**：选深浅和语气，从第 ② 步重写成新版本，可以和其他版本对照；
- **改方案重写**：改了主旨、术语表或分节后，从第 ③ 步重写。

外部审阅意见（人工或其他模型）同样要回到来源核对再改：C4 的一条审阅意见引用的是论文
v1 的数字，而文稿用的是修订后的 v2。

编辑段落时保留它的事实标注。保存时自动重跑规则检查；新观众评审和忠实核对要花模型
调用，点「重新审校」才跑。定稿时如果还有「必须改」的问题，会提示并要求确认，但不硬拦。

## 三、风格

风格分两个维度，分别选择：**深浅**决定铺垫多少，**语气**决定怎么说。栏目给默认组合，
每篇可以换。

### 深浅

| 档位 | 假定的观众 | 铺垫 | 数字 | 每节新概念 |
|---|---|---|---|---|
| 入门 | 没用过这类工具 | 所有术语都铺垫，包括 token、API 这类基础词 | 全片 3–5 个关键数字，都换算成熟悉的量 | 最多 1 个 |
| 进阶 | 用过，知道基础名词 | 只铺垫本话题特有的概念 | 关键数字带参照 | 最多 2 个 |
| 专家 | 从业者 | 不铺垫行业通用词，只澄清容易误解的地方 | 可以保留精确数字和口径 | 不限 |

档位影响三处：② 方案里的 `audience.knows / lacks` 和术语表大小；④b 扮演的观众；
规则检查里的数字和概念上限。

### 语气

每种语气定义六项：定位、句式、修辞、节奏、结构偏好、禁忌。下面的示例都用 C4 的
同一组事实改写开头那段「乘数」：缓存写入（5 分钟有效期）多付 25%；缓存读取是输入价
的 0.1 倍，Opus 5.5 和 Sonnet 5.5 降到 0.05 倍；Opus 5.5 输入每百万 token 4 美元，
缓存读取 0.20 美元。

**简洁干货**（concise）
- 定位：给时间紧的从业者，结论先行。
- 句式：短句，以陈述句为主，少修饰。
- 修辞：不用类比就讲不清时才用。
- 节奏：一节一个要点，不回顾，不铺垫情绪。
- 结构偏好：结论 → 依据 → 做法。
- 禁忌：寒暄、反问堆叠、「我们来看看」这类空转句。

> 缓存的账就两个数。存进去，多付 25%。之后原样再用，只付一折。Opus 5.5 和
> Sonnet 5.5 又把再用的价格砍了一半。按 Opus 5.5 算，正常 4 美元的输入，走缓存
> 只要 2 毛。

**讲解通俗**（explainer）
- 定位：老师把学生讲明白，先提问题再给答案。
- 句式：口语，可以自问自答。
- 修辞：全片用一个贯穿的生活类比（最多再加一个），类比要能一一对应；其余概念用白话
  讲清楚。（v1 让每个新概念都配类比，C4 一篇用了 6 个，太散，v2 改成这样。）
- 节奏：每节结尾一句小结；长视频每 2 分钟回顾一次。
- 结构偏好：问题 → 类比 → 机制 → 证据 → 怎么做。
- 禁忌：类比对不上；居高临下（「这很简单」）。

> 打个比方，提示词缓存就像复印店。第一次把原稿交给店员存档，要多付一点存档费，
> 比正常价贵四分之一。之后你只要说「照上次那份再来一份」，价格只有原来的一成。
> 到了 Opus 5.5 和 Sonnet 5.5，「再来一份」又便宜了一半。按 Opus 5.5 的价格，
> 正常 4 美元的输入，走缓存只要 2 毛钱。

**风趣口语**（playful）
- 定位：朋友聊天，好笑但不糊弄。
- 句式：口语，可以用俗语和网络说法，适度吐槽。
- 修辞：夸张的比喻、反差。
- 节奏：每分钟最多一两个包袱，抖完马上回到正题。
- 结构偏好：反差开场 → 吐槽现象 → 讲清机制 → 给招。
- 禁忌：**笑点只能落在比喻和语气上，不能落在事实上**：不夸大数字，不编情节，
  不调侃具体公司或个人没有证实的行为。

> 缓存这事儿，说白了就是头一回贵，往后白菜价。头一回存进去，多掏 25% 的开户费；
> 往后只要原样再来，直接打一折。Opus 5.5 和 Sonnet 5.5 更狠，再对半砍。按 Opus 5.5
> 算，4 美元的活儿，2 毛钱拿下。前提是你得「原样」再来，差一个字节？不好意思，
> 重新开户。

**故事案例**（story）
- 定位：用一个场景串起全片，让观众代入。
- 句式：叙述，有起伏：遇到问题 → 找原因 → 解决。
- 修辞：场景细节只为事实服务，不添加新事实。
- 节奏：场景开场，中段跳出来讲机制，结尾回到场景。
- 结构偏好：场景 → 困惑 → 机制 → 解决 → 你也可以这样做。
- 禁忌：虚构的人和事必须让人听得出是假设（用「你」或「假设」），不编具体的人名、
  公司和数据。

> 假设你在做一个客服机器人，每次请求前面都带着同一大段说明。缓存开着，月底的账单
> 却比不开还高。翻了半天才发现，说明的第一行写着当前时间。时间一变，缓存就把它当成
> 一份新文件，重新存一遍。每次都多收四分之一的存档费，一次便宜也没占到。

**新闻播报**（news，留给今日快讯一类的栏目）
- 定位：客观转述。
- 句式：第三人称，倒金字塔，时间、主体、来源明确。
- 修辞：不用类比和玩笑。
- 节奏：一条一事，不展开机制。
- 结构偏好：发生了什么 → 影响谁 → 下一步看什么。
- 禁忌：观点和判断必须说明是谁的。

> Anthropic 九月发布的 Opus 5.5 和 Sonnet 5.5，把缓存读取价降到输入价的二十分之一，
> 比之前又降了一半。写入缓存的加价没变，五分钟缓存仍要多付 25%。这意味着，提示词
> 前缀一旦不稳定，开缓存可能比不开还贵。

示例里的每个说法都能对回事实，这正是 ④c 要核对的：「存档费」「开户费」对应缓存写入
的 25% 加价，「再来一份」对应缓存读取，「原样」对应前缀逐字节一致；故事里「比不开还
高」对应推导事实 F9。范围也要对：如果写成「5.5 这一代又砍了一半」，就把 Haiku 5.5
也算了进去，④c 应当把它标为放大（D2）。

用第一节的规则数一下：v1 那段有 10 个数，两句超过上限（C4）；五个改写版每句最多
2 个数，全段 0–3 个。

### 配置

风格存在 `config/video_styles.yaml`，每个预设带版本号。修改预设就升版本，旧版本保留；
每个讲稿版本的元数据记录所用的预设版本，如 `explainer@1`。栏目增加以下几项：

```yaml
deep_dive:
  # ……现有字段……
  writer: legacy            # legacy：一次写稿；adapt：五步改编
  default_style: {depth: intermediate, tone: explainer}
  allowed_tones: [concise, explainer, playful, story]
  structure:
    required_roles: [钩子, 反方, 行动]
    sections: [4, 6]
    paragraph_units: [60, 140]
```

`script_style` 保留，写栏目特有的要求（如「按证据强弱展开」）；结构上的硬性要求移到
`structure`，由代码检查。

## 五、验收

用 C4 的研究报告，不重新调研：

1. 生成两版：「进阶 · 讲解通俗」和「进阶 · 风趣口语」，和现在的 v1 放在一起。
2. 三版跑同一套检查（规则、新观众、忠实核对），对比以下几项：「必须改」的问题数、
   没解释的术语数、每句的数字个数、新观众的提问数、忠实问题数、时长。
3. 你读三版，选出最像你想要的那版；选中的用「按原稿配音」出片，听一遍。

满足以下条件后，改编流程替换现在的写稿，成为「深度解读」的默认流程：

- 没有「必须改」的规则问题，忠实核对没有问题；
- 新观众每节的提问不超过 1 个；
- 你认为它比 v1 好。

### C4 v1 审阅发现的问题

这些问题都在 v1 里实际出现过，前五条在 v2、最后一条在 v3 里人工改掉了。用 C4 报告
重新生成时，它们是回归用例：改编流程要么不犯，要么在 ④ 拦下。

| 问题 | v1 原文 | 应当拦下它的标准 |
|---|---|---|
| 并列方案听成先后 | 「跑两遍。第一遍……第二遍……」 | C8 |
| 范围放大 | 「5.5 家族把读取倍率降到 0.05 倍」（Haiku 5.5 仍是 0.1 倍） | ① 记精确范围；D2 |
| 推导参数不一致 | 讲稿讲 0.05 倍读取，回本次数 2.11 却按 0.1 倍算 | D3 |
| 单位错 | 「要复用 2.11 次」，实际是总请求次数 | D3（推导事实记单位） |
| 引申错误 | 「只有一两次复用就不划算」，实际复用两次已回本（2.1 对 3） | D3（引申要能验算） |
| 审稿用语进口播 | 「这个区间我没拿到一手出处，得核实」 | D5 |

## 六、已确认的决定（2026-10-17）

1. 「深度解读」的默认风格是「进阶 · 讲解通俗」。
2. 讲述方案不停下来等人确认，直接写稿；审稿页能看到方案。改方案重写放在第二步实现，
   届时再加栏目开关 `review_plan`。
3. 风趣：可以调侃现象，不调侃具体的公司和个人。
4. 故事：只用「你」或明说「假设」，不编人名。
5. 命令和参数：第一版保留原文，每段最多一个。AutoVideo 加「只上画面、不朗读」的字段，
   以后再议。
6. 新观众评审第一版用同一个模型。
7. 验收通过前，栏目新建的文稿仍走现在的一次写稿（栏目配置 `writer: legacy`）；改编通过
   「换个风格」给已有文稿生成新版本。验收通过后把栏目改成 `writer: adapt`。
