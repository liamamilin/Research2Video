状态：一期已实现，2026-10-24。下文的接口验证数字保留调研时点；正式页面读取当前账号缓存。用户已授权开启定时采集。

建议在「平台管理」增加「视频数据」tab，采用账号概览、视频表现列表、单条视频详情三个层次。先回答“最近整体表现怎样、哪条视频值得复盘”，再逐步补齐观看分析。账号统计与单视频统计分别保留来源和截止时间。

重要的观看口径：样本 `rate=2093`、时长558、`avg_duration=116`；另外两个样本也呈类似比例关系。由这些样本可推测 `rate` 接近按万分位表示的平均观看比例，但不足以认定为“看完人数÷观看人数”。设计中不把它标成严格完播率，也不计算开头流失或秒级留存。

## 页面布局

平台子导航调整为「视频投稿｜视频数据｜评论收件箱｜账号与策略」。维持现有侧栏，不新增顶层导航。

### 账号概览

标题明确写「账号整体表现」，包含这个账号全部相关稿件的统计。右侧选择近7日/近30日，卡片展示该时间范围内的新增播放、新增点赞、新增收藏和账号粉丝净增，下面显示每日播放趋势。

这一块不受下面的视频搜索、栏目及来源筛选影响。日期来自平台返回的 `date_key/log_date`，旁边同时显示“统计截至10月23日”和“最近同步时间”。不能把同步成功时间当成数据已经结算到今天。本次7日播放每日数据之和与汇总均为683，截止日期为2026-10-23。

### 视频表现

列表默认展示账号全部稿件，可切换「本工作流视频」，并搜索标题或BV号。工作流来源由已确认的 BV 与文稿发布记录关联，不能仅凭相似标题认领。可按发布时间、累计播放、收藏率排序；新增播放排序需要相应历史采集覆盖。

默认列：标题及发布时间、累计播放、点赞、投币、收藏、评论。弹幕、分享、分区、文稿版本及同步状态放详情或可选列，避免首屏横向拥挤。已公开、审核中、不可访问状态应明确；尚未公开的视频统计显示“—”，不将抓取失败或不可访问的视频写成零播放。

按账号+BV去重，文稿同版多次出片不能重复计算视频。站内旧视频显示「站内历史视频」，没有本地文稿时不伪造关联；允许后续人工关联。导入统计不会自动把历史视频加入评论回复或补发首评流程。

列表默认展示“截至最近同步的累计数据”。如果将来提供“近7日净变化”，列名、基准时间和覆盖区间必须一起变化，不能把累计数当作所选期间增量。

### 单条视频详情

点击视频标题，在列表下方就地展开详情，保留筛选与排序；移动端同样纵向展开。详情包含7项累计指标、发布时间、视频时长、文稿版本、视频链接，以及回到文稿和评论收件箱的入口。

趋势按采集覆盖显示：只有一个点时显示“已建立基线，等待下一次采集”；有两个以上点后显示累计变化及采集区间净变化。观看分析不在返回范围时，显示“平台暂未返回该视频的观看分析”，不能把未返回的数据画成0%。

待处理评论使用本地收件箱口径，标为「已采集待处理观众评论」。平台总评论可能包含作者预设首评与作者回复，不能等同于观众反馈，也不能简单减1推算真实观众评论量。

## 指标计算与比较

- 点赞率、收藏率、投币率分别为对应累计次数÷累计播放次数，分母为0时显示“—”。它们不是去重用户转化率，不合成一个不透明的“视频质量分”。
- 工作流集合的比率用合计分子÷合计分母，不能直接平均每条视频的百分比。小播放量样本展示原始分子和分母，避免把1次播放1次点赞当成稳定优势。
- 账号粉丝净增仅描述账号变化；未获得单条视频的归因数据时，不显示“这条视频带来6个粉丝”。
- 对比新视频时优先比较相同发布时长的结果，例如发布后24小时或7天。错过相应采集时点的旧视频不补造历史，不以当前累计数参加同窗口排名。
- 两次采集之差是“这段区间的净变化”，可能因撤赞、删评或平台校正为负；不强制归零。跨越缺失日期的差值不拆成虚构的每日新增。
- 标题、封面、时长及分区变更保留时间标记，方便复盘，不能直接据此断言某次改动导致播放上涨。

## 采集与存储建议

一期采用按需手动同步加可选后台采集。先分页同步账号目录及目录中已返回的统计，避免为全部视频立即逐条打详情接口。新公开视频按30分钟采样，发布1至7天按2小时采样，较旧视频每日采样；实际时间受调度间隔、采集队列与接口退避影响。

账号日统计单独缓存；当返回日期未前进时，不把同一天的数据重复记成新一天。界面每次刷新只读本地缓存，不随现有6秒页面轮询向B站发起全账号请求。用户手动同步有冷却时间，同账号只有一个同步任务；权限/登录错误与限流时停止重试或退避，保留最后一次成功结果并展示数据时间。

建议新增独立的分析数据表，避免改变投稿和评论状态机：

| 数据 | 唯一标识和用途 |
| --- | --- |
| 视频目录 | `uid+bvid`；元数据、平台状态、已验证的文稿关联 |
| 视频统计快照 | `uid+bvid+采集时间`；7项累计指标、来源、成功状态 |
| 账号每日统计 | `uid+平台日期+指标`；平台给出的每日值，保留来源和更新信息 |
| 观看分析快照 | `uid+bvid+平台统计窗口`；只有单位与定义已确认的字段可用于展示 |
| 同步任务 | 目录分页进度、成功/失败数量、错误类别、最近成功时间 |

登录失效不会清空历史。账号切换时按UID隔离。没有快照、字段不支持、平台未结算、接口失败和真实零值分开表示。数据库不保存凭证或原始接口响应，不依赖无定义的 `vt/vv` 等字段猜测观看时长。

## 实施顺序

第一阶段：全账号目录及工作流关联、7项基础累计统计、账号7/30日趋势、单视频详情、缓存和快照。首次使用即能看累计和账号历史趋势；单视频趋势从采集后形成。

第二阶段：发布后24小时/7天同龄比较，按已积累样本复盘栏目、题材、长度及发布时间。再核验并接入平均观看时长、平均观看比例、设备与粉丝分布。曝光、点击率、严格完播率及留存曲线只有拿到可验证来源后才进入范围。

一期通过已有的独立托管调度器运行固定内置任务 `__bilibili_video_data`，计划ID `bilibili-video-data`，每5分钟检查到期项。目录每小时分页刷新，账号概览每6小时刷新；每轮最多补读5条到期单视频，优先近期视频。新发布任务通过当前UID和已确认BV发现，不自动加入评论管理或补发首评。

`platform_analytics.db` 保存按UID隔离的目录、7项累计统计快照、账号7/30日缓存及采集游标。首次只有一个基线时不显示增量；相邻真实测量可出现负差值。未公开或不可访问的条目不显示为0，失败保留旧快照与错误。单视频历史从启用后积累，观看分析和同龄比较留待二期。

`GET /api/platforms/bilibili/analytics` 和 `/analytics/videos/{bvid}` 仅读缓存。编辑者可通过 `POST /analytics/sync` 排队手动同步（60秒冷却）；管理员通过 `PUT /analytics/settings` 开关定时采集。Web每15秒处理手动队列，自动采集由独立调度进程执行，因此控制台空闲退出不会停止定时计划。断开账号后停止请求，切换账号不会读取上一UID的数据；重新连接同一账号释放登录退避。

一期验收：首次完整采集359条稿件，其中352条公开视频建立快照，7条未公开稿件保留状态。19:15的独立调度已实际执行成功；控制台已加载新接口。完整检查通过（Python 2113通过、3跳过；前端442通过），最终相关后端119项及前端32项复查通过。页面实测搜索、准确的文稿版本关联、单视频详情与基线提示；记录见 [验收数据](acceptance/video-data-phase1/verification.json)、[账号概览](acceptance/video-data-phase1/overview.png)、[单视频详情](acceptance/video-data-phase1/detail.png)。

## 维度扩展（2026-10-24）

已增加矩阵筛选、视频列表/详情中的矩阵信息，以及可展开的「按矩阵看表现」。BV号关联发布记录，再复用视频看板的文稿来源归属（来源选题/报告 → Job → 矩阵），包含父文稿与归档矩阵；不按视频标题、配方标签推测。当前归属按现行配置计算，并在页面明确说明。站内未关联文稿的视频、独立视频、归属暂不可用分别保留，避免把历史视频当作某个矩阵的已知样本。

矩阵汇总覆盖当前账号全部缓存视频，不受列表搜索、分页或矩阵筛选影响。每个BV只计一次。展示视频数/公开数、有效播放样本数、累计播放、单条播放中位数、收藏率及分子分母。收藏率只在播放和收藏均有效的同一批样本上合计；分母为0显示“—”。未公开、不可访问、缺失指标不计为0，保留旧快照的异常样本注明。该汇总描述累计现状，不作为发布同龄效果排名。

推荐继续扩展的维度：

| 维度 | 能回答的问题 | 数据基础与优先级 |
| --- | --- | --- |
| 栏目/生产配置 | 快讯、专题、行动清单等，哪些形式值得继续做？ | 工作流已有关联，优先 |
| 目标受众 | 面向开发者还是大众的内容表现如何？ | 创作时设定的受众，不能冒充B站真实观众画像，优先 |
| 时长区间 | 1分钟内、1–3分钟、3–10分钟及更长视频如何表现？ | B站实际时长可直接分段，优先 |
| 发布时间 | 星期、时段与表现有什么关系？ | 平台发布时间可读，需控制发布年龄，优先 |
| 发布年龄 | 发布后24小时/7天，同等曝光时间下表现如何？ | 从快照积累；未覆盖这些窗口的旧视频不补造，优先积累 |
| B站分区 | 知识、科技等平台分类下的数据怎样？ | 平台分区已有，作为辅助维度 |
| 画面形式/制作风格 | 不同成片形式是否值得继续尝试？ | 使用匹配已发布版本的实际出片配置，后续 |
| 制作效率 | 耗时、重试次数、失败率与最终产出有什么关系？ | 本地出片记录可用，费用需单独核算，后续 |
| 主题/关键词 | 哪些具体题材长期有需求？ | 需要规范标签，不能把松散标题关键词直接当稳定分类，后续 |

除矩阵之外的维度尚未增加筛选入口。配置型维度实施时应保存发布版本的快照，防止日后调整受众、栏目或风格时把历史归属一并改写。多维组合比较须显示样本数、统计覆盖和发布时间窗口；账号粉丝不能按矩阵或单视频归因。

矩阵扩展验收：当前20条视频归属9个矩阵，340条历史视频未关联。验证期间定时采集自动发现了1条新投稿并纳入其矩阵。矩阵筛选不改变账号概览；聚合覆盖全部分页数据，比例按配对样本合计。完整检查通过（Python 2119通过、3跳过；前端444通过），正式页面已核对。见 [验收记录](acceptance/video-data-matrices/verification.json)、[矩阵汇总截图](acceptance/video-data-matrices/matrices.png)。
