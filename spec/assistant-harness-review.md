### F01：手动运行的 ID、摘要与产物不一致

- **触发：** 同一个 Job 先后执行 A、B，再查询 `source=manual, run_id=A`。
- **实际：** `events` 来自 A，但 `run` 固定取最新的 B。隔离样本中 A 失败、B 成功，查询 A 得到的是“旧日志＋新成功摘要”。即使最新成功事件包含 `output_path`，摘要也不保留它，因此助手的 `report` 仍为 `null`。
- **影响：** 助手可能解释错失败原因、判断错一次运行的状态；手动运行后的“打开这次报告”缺少直接产物。该问题来自已有日志接口，新工具直接沿用了其返回值。
- **依据：** [日志摘要与目标事件](../web/runner/log_store.py#L97)、[固定选择 runs[0]](../web/routes/jobs.py#L671)、[助手据摘要提取报告与当前任务](../web/services/assistant_tools/work.py#L89)、[运行引用采用 current](../web/services/assistant_runtime.py#L59)。
- **建议：** 按请求 ID 选中摘要，保留该次运行的产物路径；“当前正在执行”单独展示，不能替代被查询对象。不存在的 ID 返回明确未找到。
- **补验：** A 失败/B 成功、反向状态、未知 ID、服务重启后读取，以及每次运行各自产物；取消后续指代仍绑定所选 ID。

### F02：配置保存与回退准备顺序不可靠

- **触发：** 新配置写入成功后，创建回退记录或保存专用快照失败。
- **实际：** `apply()` 先调用原配置保存，再创建回退卡片和快照。注入快照写失败后，临时预算已由 12 改为 18，调用方收到异常，专用快照不存在。
- **影响：** 配置已经改变，聊天却可能只显示失败；若改坏模型，承诺的直接回退入口可能拿不到或无法使用。原接口可能另有普通备份，本问题不等于所有备份都丢失，但直接恢复链路确实断开。
- **依据：** [先保存、后准备回退](../web/services/assistant_configuration.py#L110)、[原配置接口的普通备份与写入](../web/routes/config.py#L344)。
- **建议：** 发布新配置前先可靠保存旧值和恢复信息，再绑定保存后的版本；若写入已成功而收尾失败，返回“已保存、恢复准备失败”的真实部分结果。
- **补验：** 回执库失败、快照失败、权限设置失败、保存前后进程中断；验证旧配置、新配置和按钮状态能一致解释。

### F03：回退错误地继承了秘密输入卡片的一小时有效期

- **触发：** 配置保存超过一小时后点击“恢复变更前配置”，即使期间没人再次修改配置。
- **实际：** 回退记录以 `config_rollback` 存进 `protected_inputs`，读取时统一受 `pending + 3600 秒` 规则限制，直接报“输入卡片已过期”。前端按钮未显示到期时间，使用说明也未披露该限制。
- **影响：** 用户稍后发现模型或预算配置有问题时，直接恢复能力失效；“重新发起操作”还可能依赖已经不可用的 LLM。
- **依据：** [创建回退记录](../web/services/assistant_configuration.py#L113)、[统一过期检查](../web/services/assistant_store.py#L172)、[回退读取卡片](../web/services/assistant_configuration.py#L123)、[前端回退按钮](../ui/src/components/AssistantAction.tsx#L9)。
- **建议：** 回退与秘密输入分别定义有效性；优先使用配置版本冲突检查约束旧回退。若确实需要到期规则，应有可见状态和不依赖 LLM 的替代恢复入口，不凭空再设新时限。
- **补验：** 超过输入卡片有效期、重新登录、模型不可用，以及后续配置编辑发生版本冲突时的行为。

### F04：结构化配置仍能保存不存在或类型错误的字段

- **触发：** 在已知分区中提交未知字段，或把数值写成普通字符串。
- **实际：** `validate_patch()` 校验顶层分区和秘密/URL等规则，但不校验业务字段；原保存接口只保证 YAML 可解析。隔离检查保存了 `budget.monthly_usd_limit: not-a-number` 及拼错的 `monthly_usd_limt`，返回 `saved=true`；随后预算消费端抛出 `ValueError`。
- **影响：** 用户看到“配置保存成功”，实际预算查询会失败；手动启动入口对预算异常的处理是跳过预算检查。其他字段的影响需逐项核对，不能把“YAML 有效”视为“配置可用”。
- **依据：** [patch 校验](../web/services/assistant_safety.py#L45)、[保存只做 YAML 验证](../web/routes/config.py#L335)、[预算字段转数值](../core/budget.py#L47)、[手动运行预算异常后继续](../web/routes/jobs.py#L602)。
- **建议：** 复用实际配置模型或按开放给助手的字段补业务校验，明确拒绝未知字段和错误类型；模型相关可用性测试与字段校验分别完成。
- **补验：** 拼写错误、无效数字/枚举/范围、删除必需字段、合法扩展字段；拒绝后文件及当前有效配置保持一致。

### F05：关停后的状态查询会触发网关自动启动

- **触发：** 从经网关访问的助手页面关停 Web 应用，页面保留维护进度卡片。
- **实际机制：** 卡片对未完成维护每四秒请求一次应用的回执接口；网关对这个 API 请求也执行 `Supervisor.ensure()`。启动抑制仅覆盖 `restart`，没有覆盖 `shutdown`。应用退出后，查询本次关停结果的请求就能触发再次启动。隔离检查中，`shutdown/completed` 标记下的一次 `ensure()` 确实调用了模拟 `_spawn()`。
- **影响：** “关停”可能只短暂退出，用户自己的结果卡片将应用重新唤醒。这里的缺口是被动状态轮询与关停互相冲突；既有“用户再次主动访问可以唤醒”语义可以保留。
- **依据：** [维护卡片轮询](../ui/src/components/AssistantAction.tsx#L74)、[网关所有普通请求触发 ensure](../scripts/gateway.py#L382)、[仅抑制 restart](../scripts/gateway.py#L196)、[helper 的关停完成语义](../scripts/service_maintenance.py#L43)。
- **建议：** 让关停结果核验不唤醒业务进程，例如通过网关提供受权限约束的维护状态，或在关停流程中停止会唤醒应用的被动请求；需要一并检查其他页面的轮询。
- **补验：** 浏览器→网关→应用完整关停，保持页面打开后观察进程，再主动重新打开应用。现有真实维护测试直连应用端口，未覆盖这条组合链路；本轮也没有关停在线服务做验证。

### F06：维护准入检查与任务注册没有共同的原子边界

- **触发：** 请求 A 已通过“允许新运行”检查但尚未注册任务；请求 B 开始维护、观察到没有任务；随后 A 才启动。
- **实际：** 维护只在自己的入口使用准入锁。启动 Job 的标记检查、配置/预算读取和 `start_job()` 之间存在窗口。隔离检查在读取 Job 时插入 `restart/applying` 标记，后续仍调用了模拟 `start_job()` 并返回成功。
- **影响：** 并发操作下，维护可能漏掉刚启动的运行，未按用户选择的等待/拒绝策略处理。未在本轮实际终止运行或模拟整个服务退出。
- **依据：** [Job 准入检查](../web/routes/jobs.py#L575)、[随后才注册任务](../web/routes/jobs.py#L619)、[维护准入锁及活动任务等待](../web/services/assistant_maintenance.py#L91)。
- **建议：** 维护标记建立与任务注册使用同一个短临界区，覆盖 Job 和轮次入口；不要把长时间执行放进锁内。
- **补验：** 在检查、注册、维护最终无活动判断之间设置屏障，覆盖等待、拒绝、取消三种策略，并确认没有遗失仍未退出的 worker。

### F07：会话恢复没有绑定当前标签页的会话 ID

- **触发：** 同一账号先在标签页 A 使用对话 A，再在 B 新建或使用对话 B，随后刷新 A；已完成请求后离开助手再返回也可能触发。
- **实际：** 会话 ID 只在组件 ref/进行中的内存请求中；`sessionStorage` 仅保存消息。重新挂载时无 ID，服务端选择该账号最近更新的对话。隔离检查中 A 有任务上下文，创建空 B 后，无 ID 恢复返回了空 B。
- **影响：** 当前工作上下文意外切换，“它/刚才的任务”等指代不再接续原对话；旧对话数据仍存在，不能称为数据库丢失。完整历史会话管理原本就未纳入本次范围，本问题不要求先开发历史列表。
- **依据：** [只缓存消息](../ui/src/pages/Ask.tsx#L23)、[组件内会话 ID](../ui/src/pages/Ask.tsx#L83)、[无 ID 时选最新](../web/services/assistant_store.py#L59)。
- **建议：** 按当前账号及标签页保留活动会话 ID，恢复时显式传入；新对话同步更新 ID，账号切换隔离；无有效 ID 时才使用最近会话。
- **补验：** 双标签页、刷新、离开再返回、新建后刷新、重新登录；显示的消息、发送携带的 ID 和后端对象引用必须属于同一段对话。

### F08：受保护输入处理中断后没有结果待核验状态

- **触发：** 卡片已从 `pending` 变为 `processing`，服务在记录结果前重启，或响应丢失后首次查询仍是 processing。
- **实际：** 该表没有执行者/更新时间或恢复检查。重新构造存储并模拟更换进程标识后，卡片仍是 `processing`，也不能再次 claim。前端只在挂载和提交失败时读取，没有进行中轮询或直接核验按钮。
- **影响：** 页面长期停留“正在处理”，用户无法分辨仍在执行、已经成功、还是结果未知。新 Token 若已创建但响应丢失，不能再次取出原值；解决办法也不能是自动重放创建。
- **依据：** [卡片表字段](../web/services/assistant_store.py#L38)、[claim 与读取](../web/services/assistant_store.py#L172)、[受保护输入提交/结果记录](../web/routes/assistant.py#L110)、[卡片前端状态读取](../ui/src/components/AssistantAction.tsx#L23)。
- **建议：** 记录执行归属及可核验业务引用；失去执行者时显示结果未知，提供相应账号/凭据状态的直接核验入口。新 Token 需要核验元数据并按用户选择撤销/重建，保持不自动重放。
- **补验：** 分别在执行前、业务已成功、回执保存后丢响应；重启后能够解释真实状态，秘密不进入聊天，未知操作不重复执行。

### F09：验证的输出目录与真实文件写入目录不同（已有引擎问题）

- **触发 A：** 工作区与进程 CWD 不同，Job 使用相对输出路径。
- **触发 B：** 两者相同，但设置显式 `runtime.output_root` 并使用相对文件名。
- **实际：** `_resolve_output_path()` 校验绝对解析结果后又返回相对路径，`_save_output()` 则按进程 CWD 写入。本轮两组实际写入分别落在 `process-cwd/output`、`process-cwd`，而不是通过校验的目录；声明的目录中没有对应报告。
- **影响：** 报告可能写错目录、无法被索引和打开；显式输出根也无法约束真正的写入位置。这是已有校验/写入接口不一致，当前 realpath 修改没有消除该问题；默认工作区与 CWD 一致、未使用自定义根时不一定触发。
- **依据：** [解析与返回相对路径](../core/engine.py#L544)、[保存按收到路径直接写入](../core/engine.py#L580)、[Web executor 的工作区来源](../web/runner/executor.py#L54)。
- **建议：** 实际文件操作始终使用校验后的绝对目标；另生成用于索引/展示的相对引用。旧文件暂存、恢复及元数据记录也需采用一致的目录语义。
- **补验：** 非默认 CWD、自定义输出根、macOS 路径别名、目录符号链接，以及旧报告替换失败后的恢复；所有实际写入都应落在已核验目录。

## 优化点

1. **结果卡片补足用户真正需要的运行信息。** [运行时已传 last_run](../web/services/assistant_runtime.py#L171)，[界面未展示](../ui/src/components/AssistantAction.tsx#L114)。优先显示最近一次结果及报告入口，时间可读；暂停状态下的未来时间应标成预览，避免“已暂停＋接下来会运行”的歧义。无需新建监控页面。
2. **断线后给出直接核验入口。** [流式请求失败](../ui/src/pages/Ask.tsx#L61) 现在主要是一句“核验回执/业务状态”；可保留会话与请求引用，直接重新读取同一段已记录结果，让 LLM 故障时也能查清已经做了什么，不重新执行命令。
3. **收紧报告查询的扫描范围。** [每次分页前读取全部匹配报告并逐文件检查](../web/services/assistant_tools/reports.py#L70)，[限定搜索还会读取全库匹配候选再筛选](../web/indexer/vectors.py#L448)。先把目录/paths/轮次范围下推到查询层，避免报告增加后每页都扫描整个集合；本轮未测规模耗时，不编造性能阈值。任何排序改动仍按 AGENTS.md 做真实检索评测。
4. **把大任务的部分完成状态讲清楚。** [当前工具循环有 16 轮/32 次上限](../web/services/assistant_runtime.py#L103)，跨月比较、多报告原文展开可能碰到边界。先用真实长任务观察是否发生，再让结果明确覆盖了哪些材料、剩余哪些工作，并保留可继续的对象引用；不要只提高上限或先引入新的 Agent 框架。
